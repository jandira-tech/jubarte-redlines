# Dependency trim (2 PRs) and per-library READMEs in the release

Status: PLANNED (2026-10-02). It comes from a `Cargo.lock` audit: 345
packages, 15 of them present in two or more versions.

PRs A and B trim dependencies. PR C changes the release. Optional PR D swaps
the comparer hash, and only lands if its measurements say so. Each PR
branches from `main`, runs the AGENTS.md gates, and lands alone.

## PR A: tiny-skia 0.12 everywhere (drops png 0.17 and bitflags 1)

**Why.** tiny-skia 0.11 is the only crate still on png 0.17, which in turn is
the only crate still on bitflags 1. With 0.12 both leave the graph. 0.12 also
fixes a panic when drawing small anti-aliased rectangles (tiny-skia #119),
which our PNG raster and metafile paths can hit. Its one breaking change,
`RadialGradient::new` taking a start radius, does not touch us: `src/` has
no `RadialGradient`.

**Scope.** This one PR replaces the five dependabot PRs #324–#328. Each of
those edits the root `Cargo.toml` and differs only in which lock file it
moves.

1. `Cargo.toml`: `tiny-skia = "0.12"`.
2. Run `cargo update -p tiny-skia` in each workspace, one after another: root,
   `jubarte-wasm`, `jubarte-python`, `jubarte-rust-inproc`,
   `jubarte-app/src-tauri`.
3. Ride-alongs in the same PR, since every workspace gets rebuilt anyway:
   - ooxmlsdk 0.13.1 (#323). It is a dev-dependency, the schema oracle in 12
     test files. Its 0.13 prefix handling ("Pandoc's ns0" now accepted) can
     move oracle results, so run `m24_strict_namespaces` and
     `m22_alternate_content_resolve` and read any change. Check whether it
     moves to quick-xml 0.42, which would remove 0.41.
   - The #322 cargo-minor-patch group (lock-only: tauri 2.11.6, swift-rs
     1.0.8, tauri-plugin-dialog 2.7.3).

**Tests.**
- Root: `cargo test --workspace --no-fail-fast`. The PNG raster tests
  (`convert_docx_to_png*`, `diff_render`) are the ones that can move.
- Each sub-workspace: `cargo check` (tauri: `cargo check` in `src-tauri`).
- Holdout gate (`hold.sh` + `holdcmp.py`): the PDFs must be unchanged.
  tiny-skia only rasterizes, so any PDF diff is a bug.
- Count the lock's packages before and after. Expect png 0.17 and bitflags
  1.3 to be gone, plus quick-xml 0.41 if ooxmlsdk 0.13 dropped it.

**Close.** #322–#328 are closed as superseded, each with a comment linking
PR A.

## PR B: vendor the part of rdocx-opc we use (drops rdocx-opc and quick-xml 0.37)

**Why.**
- rdocx-opc 0.1 is the only crate on quick-xml 0.37, a third copy next to
  our 0.42 and ooxmlsdk's 0.41.
- `jubarte-wasm` keeps a patched vendored copy
  (`jubarte-wasm/patches/rdocx-opc`, 835 lines) only to avoid its zstd-sys
  default. That copy has to be kept in step with upstream by hand.
- We call 12 of its methods, all from `src/opc/mod.rs`: `from_reader`,
  `resolve_rel_target`, `part_name_to_rels_path`, `content_types`,
  `get_or_create_part_rels`, `get_part`, `get_part_rels`,
  `main_document_part`, `package_rels`, `part_rels`, `parts`, `set_part`;
  and the types `OpcError`, `Relationship`, `Relationships`.

**Licence.** rdocx-opc is MIT OR Apache-2.0. Copy only the code we use, keep
its copyright notice, add an SPDX header with both licences, and record it in
`REUSE.toml` and `LICENSES/`. Run `reuse lint`.

**Steps.**
1. Red first: add `tests/opc_roundtrip.rs`. Open each `tests/corpus` docx,
   save it unchanged, and require every part's bytes, every relationship and
   every `[Content_Types].xml` entry to be equal (the current behaviour).
   Add a part-name normalisation case and a `resolve_rel_target` case with
   `../` and absolute targets.
2. Move the OPC model into `src/opc/package.rs`, `src/opc/rels.rs` and
   `src/opc/content_types.rs`. It reads and writes with our quick-xml 0.42
   and `zip` 8, which we already depend on (deflate only, so no zstd).
3. Remove `rdocx-opc` from `Cargo.toml`, delete
   `jubarte-wasm/patches/rdocx-opc` and its `[patch]` entry, and update the
   comment on the `zip` line in `Cargo.toml`.
4. Word validity: run the validator (`tools/validate-docx`) over the redline
   outputs of a 30-pair sample, before and after; the outputs must be
   byte-identical. Run `word_pdf.py` on 5 outputs as a smoke test (they must
   open with no repair prompt).
5. Gates: full suite, `m_validity_ring1`, the WASM build (`build-npm.sh`)
   and its npm smoke test, and native/WASM `script_redlines` agreement for
   the same commit.

**Risk.** This is the package layer. Any change in the bytes written is a
regression unless the round-trip test explains it.

## PR C: one README per published library, generated by the release

**Today.** Five READMEs are maintained by hand and drift apart:
- root `README.md` (crates.io, 867 lines);
- `jubarte-python/README.md` (PyPI, 175);
- `jubarte-wasm/npm/README.md` (npm `jubarte-wasm`, 160);
- `jubarte-wasm/cli/README.md` (npm `jubarte-redlines` CLI, 37);
- `jubarte-wasm/README.md` (developer notes, not published).

The root README uses relative links (`./Cargo.toml`, `./LICENSE`,
`docs/…`), and those links are broken on crates.io, PyPI and npm.

**Design.** `scripts/library_readmes.py` (uv script, stdlib only) takes the
root README as the original and writes one README per library:

- **Spec.** `scripts/library_readmes.toml` holds one table per library:
  - `out` (target path);
  - `title`;
  - `lead` (the intro paragraph);
  - `install` (fenced block);
  - `keep` (root headings to carry over, in order) or `drop`;
  - `extra` (a library-only fragment file, appended or placed after a
    named heading).
- **Fragments.** The hand-written library content moves into fragments:
  - `jubarte-python/README.extra.md` (Python API, abi3 wheels);
  - `jubarte-wasm/npm/README.extra.md` (Node and browser usage, full and
    slim builds);
  - `jubarte-wasm/cli/README.extra.md`.

  The script never invents prose.
- **Rewrites, applied to every output:**
  - Relative links and images become absolute URLs pinned at the release
    tag (`https://github.com/jandira-tech/jubarte-redlines/blob/vX.Y.Z/…`;
    images through `raw.githubusercontent.com`).
  - The Socket and version badges move to the library's own registry.
  - Root-only sections (Contributing, Project structure, Benchmarks
    internals) are dropped by the spec.
- **Stamp.** Every output starts with this line under the SPDX header:

  ```
  <!-- generated by scripts/library_readmes.py from README.md
       sha256=<root README hash> version=X.Y.Z; edit README.md or the fragment -->
  ```

- **Modes.**
  - `--version X.Y.Z` writes the files.
  - `--check` exits 1 if any output differs from what it would write.
- **crates.io.** `Cargo.toml` `readme` points at the generated
  `README.crates.md`, which is listed in `include`. The root `README.md`
  stays the GitHub page.

**Release enforcement** (`scripts/release.sh`):
- Step 1, version sync, runs `library_readmes.py --version $VER` after
  `bump-version.mjs`.
- Step 4 adds `library_readmes.py --check` to the gates. A stale or
  hand-edited library README stops the release with: "run
  scripts/library_readmes.py --version X.Y.Z; edit README.md or the
  fragment, never the generated file".
- Step 6 proves each artifact carries its README: `cargo package --list`
  holds `README.crates.md`, the maturin sdist's `PKG-INFO` body equals the
  generated Python README, and `npm pack --dry-run` lists README.md for both
  npm packages. The stamp's version must equal `$VER`.
- Step 7 commits the generated files with the release commit.
- The `--how-readme-and-other-docs-were-updated` statement now also lists
  the regenerated library READMEs.

**Tests.** `scripts/test_library_readmes.py`, beside the other release-script
tests:
- Rewrites relative links and images to the tag.
- Keeps and drops sections by heading, including a heading inside a code
  fence (it must not be split).
- Places fragments.
- `--check` passes after a write and fails after a hand edit or a root
  change.
- The stamp holds the version and hash.
- `test_release_sh.py` gains a case where a stale library README fails the
  gate.

## Optional PR D: sha1 → SHA-256 for the comparer's content hashes (measure first)

**Facts.**
- The comparer keys its block and atom hashes with SHA-1. This is a port of
  Open-Xml-PowerTools' `SHA1HashStringForUTF8String`.
- The values stay inside the process (`pt:` scratch attributes). Only their
  equality matters, so any other digest gives the same redlines as long as
  no ordering depends on them. The byte-identical redline fixtures would
  catch one that does.
- Dropping `sha1` removes only that crate. `digest` 0.11, `block-buffer` and
  `cpufeatures` stay for sha2 0.11 (the `inspect`/`edit` snapshot guard).

**The real argument is not crate count.**
- SHA-1 chosen-prefix collisions are practical: SHAttered 2017, "SHA-1 is a
  Shambles" 2020.
- In a redline engine, a collision makes two different paragraphs compare
  equal, so a change goes unmarked.
- To exploit it, the colliding bytes have to survive as serialized XML text.
  That is hard, but not shown impossible.
- SHA-256 closes the hole.

**Alternatives considered.**
- xxh3-128: fastest, but not collision-resistant against a crafted
  document, and it adds a crate.
- BLAKE3: fast and cryptographic, but it adds a crate with SIMD code paths.
- SHA-256 through sha2: already a dependency.

**Cost.**
- Native on Apple Silicon and x86 with SHA extensions: about the same.
- WASM: no SHA instructions, so SHA-256 in software runs roughly 1.5–2× the
  time of SHA-1, and hashing is on the compare profile (LCS_PERF_PLAN
  HASH-01…HASH-STREAM-03).

**Gate.**
- Speed: run the speed-campaign matrix (native and WASM, ABBA). Land only if
  the WASM compare wall stays within noise, or Arthur accepts the cost for
  the collision fix.
- Output: redline outputs byte-identical on the 1164-pair pool.
- Tests: `tests/sha1_key_invariant.rs`, `tests/m1_foundation.rs` and
  `tests/perf_hash02_stream.rs` pin SHA-1 values. They become SHA-256 golden
  values, with the equivalence oracles kept.
