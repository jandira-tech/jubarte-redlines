# Goal: release 0.10.0

> **Outcome:** goal met — v0.10.0 shipped (CHANGELOG dated 2026-09-28, tag
> `v0.10.0` created 2026-09-29) and was superseded by v0.10.1 (tagged
> 2026-09-30); both tags are in `main`.

Set 2026-09-28 on branch `release/0.10`. The release ships when every item
below is done and the versioning gates in `VERSIONING.md` pass.

1. **Agent adoption.** Land the features started on `feat/agent-adoption`
   (PR #213): `inspect`, `text`, `edit`, `convert --png/--report`,
   `capabilities`, the Python `Document` facade and edit plans, and the
   `jubarte-documents` skill, plus anything related that is still missing.
2. **Self-update.** Add an update command that contacts GitHub only when
   the user asks for it. Nothing checks for updates in the background. Use
   an existing crate for the release lookup and binary swap rather than
   writing one.
3. **Known issues.** Fix every open item in `KNOWN_ISSUES.md` and un-ignore
   the tests parked on them.
4. **Word differences.** List where the default redline differs from
   Word's own redline, say which side is better, and document the modes
   (`--revisions word`, `--powertools-faithful`, …). The Word-faithful
   mode stays byte-for-byte Word where the default improves on Word.
5. **Tests.** Every test passes, or the code is fixed, before the release.
   No test is ignored without a recorded reason.
6. **Quality guard.** A fixed random sample of 40 pairs from
   `neurotic_docx_bench` is scored before any change
   (`tools/redline40/`), and re-scored after any change that can move
   redline output. A drop is fixed before moving on.
7. **Method.** `/conejo-code` stages (spec, plan, interface, failing test,
   implementation, test hardening, review), done inline without agents and
   without waiting on CI or CodeRabbit. CodeRabbit reviews the PR when it
   opens and four times a day after that.
8. **Release.** Run the full versioning sanity check and release 0.10.0.
