## Deprecated ids still in use

The retired colon long-id family (`body:p:12`, `header1:rev:3`) and 0.12's retired spellings (`#12`, `#c5`, `t0.r1.c2`) that the CLI still prints or accepts. Every run of this script warns while this table has rows; `--strict` fails. The 17 October 2026 contract (docs/superpowers/specs/2026-10-17-short-and-long-id-contract.md) retires the whole family: after the schema-2 cutover the only long ids are the four-field `PART.ELEMENT.ATTRIBUTE.VALUE` family, always paired with a `short_id` — colon ids stay neither in JSON nor in machine hints and error payloads, so these rows go only when the cutover removes the last one.
