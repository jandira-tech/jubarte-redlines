## Method

- Comments and string literals are blanked first, so doc examples such as ``/// use jubarte::markdown::...`` are not counted as dependencies.
- A dependency is a path that resolves to another `src/` file: every `use` tree (braces expanded), every inline `crate::`, `super::`, `self::` and `jubarte::` path, and relative paths whose first segment is a child module (`use write::X`). `super` inside an inline `mod tests {}` correctly points at the enclosing file.
- A path is resolved to the file of its longest matching module prefix. When the remainder names an item that a facade (`lib.rs`, a `mod.rs`) re-exports with `pub use`, the edge goes to the file that defines it, not the facade.
- `mod x;` declarations are listed as *Declares submodules*, not as dependencies. A child that does `use super::...` does depend on its parent file.
- *(test)* marks edges whose every occurrence is inside `#[cfg(test)]` code. Files reachable only through a `#[cfg(test)] mod x;` are *test-only*.
- *Depended on by (outside src)* scans `tests/`, `benches/`, `examples/`, `fuzz/` and the three binding crates for `jubarte::` / `jubarte_redlines::` paths and resolves them the same way.
- External crates are matched against the `[dependencies]` names in `Cargo.toml` (`std` is omitted).

Known limits: file-level, not item-level (a `use` of one function counts as a dependency on the whole file); macro-generated paths and trait-method calls that need no import are invisible; a glob import (`use super::*`) is credited to the glob's module file only, so the real targets behind a glob that the module itself re-imports are not traced; paths hidden behind `type` aliases or renamed imports of modules are resolved by name only.
