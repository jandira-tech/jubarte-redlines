## 2024-05-18 - [Eliminate dom.elements in atomize.rs hot paths]
**Learning:** Checking for empty DOM children via `dom.elements(id, None).is_empty()` allocates a whole `Vec<NodeId>` on the heap before the `.is_empty()` call drops it. This allocation is unnecessary when we only need to check if any child is an element. In tight loops (like `annotate_element_with_props` and `revision_tracking_element_from_ancestors` which is run for every created atom), these intermediate allocations add up to substantial overhead.
**Action:** Replace `dom.elements(id, filter)` with manual loops over `0..dom.child_count(id)` and `dom.child_at(id, i)`, then manually filter and iterate. For `.is_empty()` checks on elements, use `(0..dom.child_count(id)).all(|i| !dom.is_element(dom.child_at(id, i)))` or `.any()`.
