## 2024-05-18 - [CRITICAL] Duplicate ID vulnerabilities via `saturating_add` overflow
**Vulnerability:** Document ID generation logic (such as for `max_abstract_num_id`, `max_num_id`, `max_pic_id`, etc.) relied on `saturating_add(1)`. If an attacker supplies an input document with IDs artificially inflated near or at `i32::MAX` / `u32::MAX`, subsequent allocations stay at the maximum limit due to saturation, producing duplicate IDs that cause parsing failures, document repair dialogs, and severe Word fidelity issues upon opening.
**Learning:** Using `saturating_add` for unique resource ID generation provides no uniqueness guarantee at integer boundaries. It will silently cap and create collisions.
**Prevention:** Always implement ID generation using a loop with `wrapping_add(1)` combined with a `taken` identifier `HashSet` check to guarantee ID uniqueness and avoid duplicate IDs near boundary limits. Use a pattern similar to `rename_repeated_doc_pr_ids` (`while next == 0 || taken.contains(&next) { next = next.wrapping_add(1); }`).
