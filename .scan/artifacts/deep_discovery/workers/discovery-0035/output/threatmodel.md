# Threat Model

Jubarte is an in-process Rust DOCX comparison, tracked-change editing, inspection and PDF/PNG/Markdown conversion engine, distributed as a native CLI, PyO3 Python package and WASM Node/browser package. Inputs flow from caller-provided package bytes, Markdown and edit-plan JSON through OPC/ZIP and XML processing into returned bytes or host-selected outputs (README.md:12-40; src/lib.rs:5-24). Python also exposes a stdio MCP server with a held filesystem directory capability; this is a distinct authorization surface from ambient-authority CLIs (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381; src/publication.rs:146-165,203-225). Conditional privileged workflows include CLI self-update, installation, GitHub release publication and externally implemented Jules review/remediation actions.

## Assets

- Confidential document content, comments, revisions, embedded media and derived reports/views. Render report JSON explicitly includes per-page text, so reports are document-bearing exports (src/convert/mod.rs:489-530).
- Integrity of source documents, clean copies, tracked-change outputs and exact edit requests. Legacy edit plans optionally pin source SHA-256; mismatch refuses with STALE_SOURCE, and edits reject signed or macro-bearing packages (src/edit.rs:2073-2105).
- Host filesystem files accessible to native/Python/Node processes; MCP grants access only through its selected root capability, whereas native CLI publish_paths intentionally uses ambient local authority (src/publication.rs:146-165,203-225).
- Availability of the embedding process. Default admission permits 64 MiB compressed/per-part and 256 MiB total inflated; comparison permits 512 MiB compressed/per-part and 2 GiB total, both with 10,000 entries and XML depth 256 (src/admission.rs:63-99).
- Installed CLI executable and trust in published archives. Current updater trusts GitHub release SHA256SUMS.txt with no compiled signing keys or first signed release (src/update.rs:25-48,198-210,245-257).
- Release-signing secret ZIPSIGN_PRIVATE_KEY, temporarily decoded to runner-local $RUNNER_TEMP/zipsign.XXXXXX/keyN; GitHub publication token scoped by the release job's contents:write permission (.github/workflows/release.yml:230-239,261-309,356-369).
- Jules service API credential and review/publication authority of external actions. Standard review receives JULES_API_KEY and GITHUB_TOKEN; remediation receives JULES_API_KEY and requests an automatically created companion PR (.github/workflows/jules-review.yml:28-50; .github/workflows/jules-el-conejo-review.yml:259-324).

## Trust Boundaries

- Untrusted document producer -> Rust byte APIs -> admission/OPC/XML/image/font/layout components. admit checks archive structure, names, duplicates, supported compression/encryption, bounded inflated reads and XML policy before returning success (src/admission.rs:439-575). WmlDocument::from_bytes specifically consumes InputLimits::compare, not the smaller default budget (src/wml_document.rs:35-58).
- Unchecked XML caller -> public permissive DOM parser is a caller-obligation boundary distinct from checked APIs. Source documents that parse_xdocument does not enforce input policy and callers must gate through checked XML or package admission; defaults include 1,024 attributes, 1,024-byte attribute names, 64 MiB attribute values and 128 MiB start tags (src/xmllinq/parse.rs:19-36,48-57).
- Untrusted OPC relationship -> package lookup. resolve_relationship and related lookups exclude TargetMode=External rather than fetching it; emitted hyperlink relationships can remain external references (src/opc/mod.rs:770-821,880-892). Opening an output in another application is outside the engine's no-fetch boundary.
- CLI operator -> selected local input/output paths. Native CLI routes ordinary output publication through publication::publish_paths, whose explicit policy grants ambient access; staged writes use held parent handles, private Unix staging directories, readback verification and rename/no-clobber linking (src/bin/jubarte.rs:261-273; src/publication.rs:203-225,421-570). This is not MCP-root confinement.
- Python/Node CLI operator -> host filesystem wrappers -> engine bytes. Python Document.read uses Path.read_bytes; Node read uses fs.readFileSync and write uses fs.writeFileSync (jubarte-python/python/jubarte_redlines/document.py:142-145; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-73,106-111). Their publication controls must be evaluated separately from native cap-std publication; shared clap parsing does not establish shared I/O enforcement.
- MCP stdio client -> root-brokered document tools. Startup expands/resolves --root or current directory and creates _native._OutputRoot once. load reads relative to this held capability; publish sends relative names and overwrite policy into it. Path.resolve checks are diagnostics, not final authorization (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381; jubarte-python/src/lib.rs:1246-1278). Native OutputRoot reads through cap-std and validates portable output paths, refuses confined-output symlinks and uses atomic no-clobber installation unless overwrite is granted (src/publication.rs:146-199,228-250,431-469,558-569). All connected MCP callers receive the tools; read_only/destructive annotations are hints, not separate caller authorization (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,126-143,300-327).
- Untrusted Markdown image reference -> native CLI resource broker -> local image bytes. Effective root is --resource-path, else Markdown parent, else '.', then canonicalized and held as OutputRoot. Percent-decoded URLs and targets outside that root are refused; actual reads are capability-relative (src/bin/jubarte.rs:2811-2876,2936-2943). Python/npm CLIs reject resource_path options rather than inheriting this native broker (jubarte-python/python/jubarte_redlines/__main__.py:1057-1064; jubarte-wasm/cli/bin/jubarte-redlines.mjs:724-727).
- Document font family -> native font discovery -> host fonts and parsed font bytes. JUBARTE_FONT_DIR overrides the per-user directory; otherwise locations are macOS $HOME/Library/Application Support/jubarte/fonts, Linux $XDG_DATA_HOME/jubarte/fonts or $HOME/.local/share/jubarte/fonts, and Windows $APPDATA/jubarte/fonts (src/convert/font.rs:2633-2652). System and Office font discovery are independent sources, including fixed macOS directories, Windows WINDIR/SystemRoot/default C:\Windows\Fonts and LOCALAPPDATA\Microsoft\Windows\Fonts, and $HOME/Library/Group Containers/UBF8T346G9.Office/FontCache/4/CloudFonts/<family>; cloud family path construction requires one normal component (src/convert/font.rs:2181-2207,2225-2236,2281-2309,2855-2862).
- Local benchmark harness -> long-lived jubarte-inproc stdin protocol -> ambient file reads/writes. This unpublished adapter reads both requested paths and directly writes the requested result path, without the MCP root broker; it is a developer/harness capability, not an authenticated remote service (jubarte-rust-inproc/Cargo.toml:5-18; jubarte-rust-inproc/src/main.rs:29-68,91-99).
- CLI operator -> self-update -> GitHub release assets -> installed executable. Repo owner/name are fixed, platform maps to five desktop targets, archive binary path is jubarte-<version>-<target>/jubarte[.exe], SHA256SUMS.txt is required, and extracted binary must be a regular file. Noninteractive operation requires --check or --yes; requested versions can downgrade (src/update.rs:25-48,91-108,120-125,144-151,198-257,307-320). Current RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None make signature verification inactive despite compiled support.
- Authorized tag publisher -> release workflow build artifacts -> published GitHub release. v* tags must match Cargo.toml; builds read repository content and release job alone has contents:write. Signing secret is provided only to signing step, decoded under RUNNER_TEMP and cleaned by trap; checksums are generated after signing and gh release create publishes dist/* to github.repository (.github/workflows/release.yml:15-49,51-89,230-239,261-321,356-369). GitHub-side tag permissions and secret protections are external prerequisites.
- Repository PR content -> externally implemented review/remediation services. Standard Jules review runs only same-repository non-Dependabot PRs, uses no checkout, receives a read-content/write-review/check token, and disables approval. Companion remediation independently resolves same-repository PR head SHA for checkout, gates service invocation on trusted login arthrod and selected events, but supplies starting_branch as the mutable head ref and requests AUTO_CREATE_PR with require_plan_approval=false (.github/workflows/jules-review.yml:19-50; .github/workflows/jules-el-conejo-review.yml:46-52,64-102,259-324). External pinned action/service implementations and their enforcement are absent from the inspected repository.

## Attacker Capabilities

- A document supplier may choose DOCX ZIP records, XML, relationships, image/font payloads, legacy DOC bytes, Markdown text and embedded references submitted to library/CLI processing. They do not thereby choose trusted CLI flags, environment variables or arbitrary host output paths.
- An edit-plan supplier may choose operation JSON and anchors subject to schema, snapshot and operation validation. Author/date strings are document metadata, not authenticated identities; successful editing does not establish human approval (src/edit.rs:5-24,2073-2105).
- A connected stdio MCP client may invoke both advertised read and write tools and choose root-relative input/output names and overwrite arguments. Without another host-level policy it is authorized for the entire selected root; it must not gain filesystem authority outside the held root (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,300-327).
- A same-repository PR contributor may control source, PR metadata and relevant changes consumed by CI and external review actions. This does not imply they control repository secrets, authorized release tags, trusted login gates or remote Jules service permissions (.github/workflows/jules-review.yml:19-50; .github/workflows/jules-el-conejo-review.yml:64-102,259-324).
- A release-asset attacker is a distinct, conditional actor. Because current binaries have no signing keys, an attacker who can replace both an archive and its adjacent sums file is not stopped by a separately anchored archive signature. Ordinary document authors do not have that capability (src/update.rs:44-48,198-210,245-257; docs/SELF_UPDATE.md:59-80).
- Local actors already controlling the process account, trusted environment, selected root directory, release signing secret or tag-publishing account are not assumed attackers who gain those same privileges merely through authorized operations.

## Security Objectives

- Reject unsafe or ambiguous package structure and enforce the active compressed, entry, part, total inflation, XML depth and tag budgets before expensive document processing; retain caller-selected stricter limits (src/admission.rs:39-99,439-575). Input bounds are not a substitute for host CPU/memory containment (SECURITY.md:70-74).
- Preserve checked-versus-unchecked XML API distinctions, refuse policy-breaking XML before DOM construction on checked paths, and do not interpret untrusted external relationship targets as file/network authority (src/xmllinq/parse.rs:19-36; src/opc/mod.rs:770-821).
- Keep MCP reads/writes within its held root despite symlink changes, preserve existing outputs unless overwrite is explicitly requested, and reject unsafe confined export paths (jubarte-python/python/jubarte_redlines/mcp_server.py:75-108; src/publication.rs:146-199,228-250,431-469,558-569).
- Keep the native Markdown image reader inside its explicit/default resource root and never fetch URL references through that broker (src/bin/jubarte.rs:2811-2876,2936-2943).
- Apply edit operations against the intended immutable source snapshot, reject a mismatched supplied SHA-256, and distinguish document-edit transaction success from filesystem multi-file atomicity (src/edit.rs:5-24,2081-2105; src/publication.rs:168-173).
- Treat rendered/exported page text, edit reports and tool responses as confidential document outputs; their exposure follows the caller's chosen publication/transport recipients (src/convert/mod.rs:489-530; jubarte-python/python/jubarte_redlines/mcp_server.py:132-144).
- Install updates only through an explicit command with applicable confirmation/check policy, expected repository/platform/archive path, checksum verification and regular-file verification; accurately expose the current checksum-only signing posture (src/update.rs:25-48,91-125,198-257,307-320).
- Keep signing and publication authority distinct from read-only builds and review automation; preserve service invocation gates without treating model review as human approval (.github/workflows/release.yml:54-55,230-239,261-309; .github/workflows/jules-review.yml:28-50; .github/workflows/jules-el-conejo-review.yml:259-324).

## Assumptions

- No deployment/user context was supplied. Do not infer a public HTTP service, multi-tenant hosting, authentication boundary or observed remote deployment. MCP startup here uses stdio (jubarte-python/python/jubarte_redlines/mcp_server.py:373-381).
- SECURITY.md says the engine provides no user authentication, encryption or key agreement and requires process CPU/memory limits for untrusted work. Actual hosting quotas and process isolation are outside inspected source (SECURITY.md:70-85).
- Documentation/configuration discrepancy: SECURITY.md:89-94 describes rdocx-opc 0.2 and quick-xml 0.41, whereas the current manifest consumes oxml-opc 0.14.2, quick-xml 0.42 and an explicit quick-xml-041 alias. The policy's dependency description is stale; this alone does not establish a vulnerable dependency (Cargo.toml:104-117).
- Documented library wording says every function takes complete bytes and uses no temporary files, while a separately exposed native publication module intentionally stages host files, and native rendering independently reads installed/user fonts. Interpret the byte-processing guarantee by API rather than asserting a universal filesystem-free library (src/lib.rs:5-11; src/publication.rs:146-225,472-505; src/convert/font.rs:2247-2249,2633-2652).
- Documentation accurately stages signed updates as conditional: current source has no trusted keys and no signing threshold, so current binaries verify sums only; release workflow can sign if its external secret is configured, but that does not make current updater builds require signatures (docs/SELF_UPDATE.md:59-80,119-121; src/update.rs:44-48,245-249; .github/workflows/release.yml:261-309).
- docs/SELF_UPDATE.md:22-24 claims GH_TOKEN/GITHUB_TOKEN increase API budget. The inspected builder does not explicitly configure an authentication token; whether the self_update dependency consumes those variables remains unresolved because its implementation is not repository source (src/update.rs:198-218). Do not infer a credential recipient from this documentation alone.
- MCP read_only_hint/destructive_hint annotations are metadata; no per-caller tool permission partition or confirmation gate is present in the inspected build_server. Root-wide client authorization is delegated to the stdio host (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108).
- Native output publication is atomic per file, not across a set; cleanup warnings and partial commit/durability outcomes are part of its contract (src/publication.rs:168-173). Do not extend the edit-plan all-or-nothing logical guarantee to all filesystem exports.
- External Jules action internals, service-side repository permissions, credential storage, branch/revision binding and automatic PR behavior cannot be verified offline from these workflow callers. The pinned action references are evidence of the contract, not proof of enforcement (.github/workflows/jules-review.yml:35-50; .github/workflows/jules-el-conejo-review.yml:259-324).
- The benchmark inproc worker is unpublished and assumes a trusted local harness; attaching its stdin to an untrusted client would grant ambient path reads/writes and is an additional deployment prerequisite (jubarte-rust-inproc/Cargo.toml:5-18; jubarte-rust-inproc/src/main.rs:91-99).
- No application code was executed and no external services or symlinked build cache were contacted. This independent pass maps material architecture boundaries; remaining parsers, generated WASM implementations and individual controls still require audit-specific review.
