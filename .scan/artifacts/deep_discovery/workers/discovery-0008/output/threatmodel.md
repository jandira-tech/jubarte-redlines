# Threat Model

Jubarte is a local Rust document-processing engine for DOCX comparison, tracked edits, revision settlement, inspection, validation, scrubbing, Markdown conversion and PDF/PNG rendering. Rust CLI, Python/PyO3 and WASM interfaces share engine code; Python and Node add their own local filesystem adapters. The optional Python MCP server exposes document tools over stdio and grants a persistent directory capability rooted at --root, defaulting to the server working directory. Native rendering additionally accesses host font resources and a persistent font index. Explicit self-update and maintainer release/review automation have separate network, credential and publication authority. This is a source-backed architecture map, not completed security-audit coverage. Evidence: Cargo.toml:57-58, Cargo.toml:102-128, src/lib.rs:96-165, jubarte-python/pyproject.toml:43-49, jubarte-python/Cargo.toml:35-37, jubarte-wasm/Cargo.toml:18-19, jubarte-python/python/jubarte_redlines/mcp_server.py:373-381.

## Assets

- Confidential input documents, document text, comments, authorship and revision history; derived clean/redline DOCX files, Markdown patches, JSON reports and rendered PDF/PNG artifacts. MCP edit writes <root>/<out_dir>/clean.docx, redline.docx, patch.diff and report.json, with optional redline.pdf and redline-page-NN.png. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:152-205.
- Integrity of caller-selected local files and the MCP server's granted document directory. The directory capability is held open, while ambient CLI publication intentionally accepts local paths outside any common root. Evidence: src/publication.rs:146-217.
- Host memory and CPU used by archive decompression, XML parsing, document comparison, legacy DOC parsing, fonts, image decoding and rendering. Default admission limits are 64 MiB compressed, 10,000 entries, 64 MiB per part, 256 MiB inflated and XML depth 256; comparison limits raise compressed/per-part bounds to 512 MiB and aggregate inflated bytes to 2 GiB. Evidence: src/admission.rs:39-100.
- Native renderer font files and persistent index metadata. The index defaults to ~/Library/Application Support/jubarte/font-index.tsv on macOS, $XDG_DATA_HOME/jubarte/font-index.tsv or ~/.local/share/jubarte/font-index.tsv on Linux, and %APPDATA%\jubarte\font-index.tsv on Windows; JUBARTE_FONT_DIR changes its default parent and JUBARTE_FONT_INDEX overrides or disables it. Evidence: src/convert/font.rs:2633-2652, src/convert/font.rs:3098-3107, src/convert/font.rs:3182-3229.
- Installed CLI executable, release archives/checksums, package-registry identities and publication credentials. Current updater trusted signing keys are empty and the first signed release is unset. Evidence: src/update.rs:25-48, src/update.rs:198-258, scripts/release.sh:374-380, scripts/release.sh:919-959, scripts/release.sh:1063-1069.
- GitHub release-write authority, optional release signing private key, Jules API credentials and delegated review/remediation capabilities. These are privileged development workflows, separate from document processing. Evidence: .github/workflows/release.yml:230-307, .github/workflows/release.yml:356-369, .github/workflows/jules-review.yml:17-41, .github/workflows/jules-el-conejo-review.yml:259-324.

## Trust Boundaries

- Document producer -> Rust package/XML consumers: caller-controlled ZIP records, part names, compressed data and XML cross into trusted process memory. Admission checks central/local ZIP consistency, special-entry defects, case-folded duplicate names, encryption/compression policy, streamed inflated-byte budgets and XML checks. InputLimitOverrides rejects unknown configuration fields. Evidence: src/admission.rs:103-138, src/admission.rs:439-553, src/opc/archive.rs:34-51. The library forbids unsafe Rust in its own code: src/lib.rs:86.
- Library caller -> raw XML parser: parse_xdocument is intentionally permissive and allocates a character vector without applying input policy; try_parse_xdocument_with_limits validates before constructing its DOM. Callers choosing the raw API own prior admission and process limits. Evidence: src/xmllinq/parse.rs:88-135. Default tag limits are 1,024 attributes, 1,024-byte qualified attribute names, 64 MiB attribute values and 128 MiB start tags: src/xmllinq/parse.rs:48-57.
- Legacy DOC producer -> legacy parser: supported conversion follows the separate compound-file/WordDocument/FIB/table pipeline rather than DOCX ZIP admission. Stream structure and encryption checks belong to legacy_doc, and process resource limits remain a host obligation. Evidence: src/legacy_doc.rs:174-216, src/legacy_doc.rs:765-795.
- Edit-plan producer -> document transaction: version-1 source SHA-256 is checked when supplied; version-2 source SHA-256 is mandatory and checked after plan validation. Version-1 editing refuses packages containing XML signatures or vbaProject.bin. These integrity checks bind source bytes, not authenticated identity or human approval. Evidence: src/edit.rs:2072-2104, src/edit/v2_apply.rs:75-100.
- MCP client -> document filesystem: all connected clients receive the tools installed by build_server, with document reads/publication mediated by _native._OutputRoot and cap_std::fs::Dir. --root defaults to Path.cwd(); expanded/resolved root is opened once. Python resolution checks provide diagnostics, while actual reads and writes use the persistent capability. No per-user authentication or tenant partition is implemented by this stdio adapter. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:54-108, jubarte-python/python/jubarte_redlines/mcp_server.py:373-381, jubarte-python/src/lib.rs:1244-1276, src/publication.rs:146-199.
- MCP mutation -> output publication: output paths must pass portable-relative-name validation; target symlinks/directories are refused, and overwrite=false uses atomic hard-link installation. All bytes are staged and verified before any commit; atomicity is per file, and errors can report an already committed subset. Unix staging directories use mode 0700; Windows inherits platform access controls. Evidence: src/publication.rs:83-143, src/publication.rs:168-199, src/publication.rs:228-245, src/publication.rs:431-512, src/publication.rs:535-570.
- Local CLI caller -> ambient filesystem: native publish_paths holds destination-parent handles and stages outputs, but deliberately grants ambient local-path authority. Python CLI _write uses Path.write_bytes; Node CLI write uses fs.writeFileSync. Their preflight existence checks are distinct from native publication enforcement and must be reviewed independently. Evidence: src/bin/jubarte.rs:261-273, src/publication.rs:203-225, jubarte-python/python/jubarte_redlines/__main__.py:101-103, jubarte-python/python/jubarte_redlines/__main__.py:126-133, jubarte-wasm/cli/bin/jubarte-redlines.mjs:76-79, jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111.
- Markdown image names -> native CLI resource loader: the trusted root is explicit --resource-path or the Markdown file's parent, falling back to '.'. URL schemes are refused, percent escapes are decoded before policy checks, canonicalized targets must remain under the root, and actual reads use OutputRoot. The general Markdown library instead accepts a caller-provided image callback, absent by default. Evidence: src/bin/jubarte.rs:2811-2878, src/bin/jubarte.rs:2936-2943, src/markdown/mod.rs:196-198, src/markdown/mod.rs:216-226.
- Document font requests -> ambient native font discovery/index: document family names select parsed host fonts, including system, Word and cloud-cache locations and configured user fonts. Cloud-family names must be one normal path component. The persistent index records source paths and timestamps, reloads matching files and saves through a process-specific temporary filename followed by rename. These operations do not use the MCP OutputRoot. Evidence: src/convert/font.rs:2225-2236, src/convert/font.rs:2263-2315, src/convert/font.rs:2633-2652, src/convert/font.rs:3154-3172, src/convert/font.rs:3182-3229.
- Operator -> updater -> installed executable: explicit self-update resolves releases from jandira-tech/jubarte-redlines, selects one platform archive and inner jubarte binary, requires checksum verification and registers an extracted-regular-file verification hook. Noninteractive installation needs --yes; --check only resolves availability; explicitly requested versions can downgrade. Signature verification is implemented but inactive with the current empty key list. Extraction, HTTP behavior and executable replacement are delegated to self_update and were not independently inspected here. Evidence: src/update.rs:25-48, src/update.rs:88-124, src/update.rs:144-161, src/update.rs:186-258, src/update.rs:307-321.
- Maintainer/CI -> release consumers: tag-driven GitHub builds have contents:read, while the release job alone has contents:write. Optional ZIPSIGN_PRIVATE_KEY reaches the signing step and temporary $RUNNER_TEMP/zipsign.XXXXXX/keyN files; checksums are generated after signing. A separate local release script can publish crates.io, two npm packages, PyPI and a GitHub fallback release using operator credentials. Its typed version confirmation can be bypassed with the explicit --yes option, and security-check.sh runs even with --skip-gates. Evidence: .github/workflows/release.yml:15-25, .github/workflows/release.yml:51-89, .github/workflows/release.yml:230-321, scripts/release.sh:374-380, scripts/release.sh:655-660, scripts/release.sh:875-899, scripts/release.sh:919-959, scripts/release.sh:976-1012, scripts/release.sh:1039-1069.
- PR content -> privileged review/remediation automation: one pinned reviewer receives JULES_API_KEY and a GitHub token with contents:read, pull-requests:write and checks:write, gated to same-repository non-Dependabot PRs, without local checkout. A different pinned companion-remediation action receives JULES_API_KEY and starts only for trusted arthrod author/dispatcher conditions; its requested mode is AUTO_CREATE_PR with require_plan_approval:false. Companion workflow document gates and prompts do not establish what the external action or Jules service enforces. ## Attacker Capabilities

- A document supplier can control DOCX ZIP/XML, embedded media/fonts, Markdown text/image references or supported legacy DOC bytes that a caller elects to process. They do not thereby control trusted process environment, CLI arguments, MCP root selection, host filesystem permissions or release credentials.
- An MCP client can invoke the registered read/write tools and select paths within the operator-granted root, including overwrite=true. All clients sharing this server share that capability; a meaningful boundary failure would add access outside that grant, rather than merely exercise permitted edits. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108, jubarte-python/python/jubarte_redlines/mcp_server.py:152-168.
- A library caller may supply permissive XML, increased limits or an image callback; those choices are caller authority, not proof that an untrusted document can alter policy. Resource-exhaustion impact on a shared service requires a host deployment and workload access not supplied here. Evidence: src/admission.rs:103-164, src/xmllinq/parse.rs:88-135, src/markdown/mod.rs:196-198.
- A release-asset attacker would need write access to release artifacts or a separate transport/provider compromise. The current checksum-only updater cannot distinguish coordinated archive/checksum replacement using an independent signing identity, as the documentation explicitly explains. Evidence: docs/SELF_UPDATE.md:59-80, src/update.rs:44-48.
- PR authors control reviewed source and PR metadata within their GitHub permissions. Fork authors are excluded from the privileged Jules paths inspected here; same-repository authors and the trusted companion-remediation trigger have different authority. No claim is made that PR text alone can acquire repository write authority. Evidence: .github/workflows/jules-review.yml:19-31, .github/workflows/jules-el-conejo-review.yml:65-82, .github/workflows/jules-el-conejo-review.yml:259-324.

## Security Objectives

- Bound untrusted package/XML resource use and reject unsafe or ambiguous package representations before protected processing; preserve explicit caller-configured limits. Raw permissive parsing and maintainer debug inspection must remain distinguishable from checked admission. Evidence: src/admission.rs:39-164, src/admission.rs:439-553, src/opc/archive.rs:15-19, src/xmllinq/parse.rs:88-135.
- Keep MCP document reads and publication within the persistent root capability despite symlink/path replacement, preserve overwrite opt-in and report partial publication accurately. Evidence: src/publication.rs:83-199, src/publication.rs:431-570.
- Bind prepared edits to the intended source and expose refusal outcomes; do not treat a content digest, selected author string or model-visible tool annotation as authenticated authority. Evidence: src/edit.rs:2081-2092, src/edit/v2_apply.rs:84-100, jubarte-python/python/jubarte_redlines/mcp_server.py:54-55.
- Prevent Markdown image references from gaining arbitrary host-file or network read authority in the native CLI loader; caller-provided library callbacks own their additional authority. Evidence: src/bin/jubarte.rs:2811-2878, src/markdown/mod.rs:196-198.
- Install only the explicitly selected release's intended regular executable, with the configured checksum/signature policy and operator confirmation semantics. Preserve the distinction between implemented signing support and active trusted signing keys. Evidence: src/update.rs:104-124, src/update.rs:198-258, src/update.rs:307-321.
- Keep release signing, registry publication, review comments and companion PR creation as separately authorized capabilities. Bind published versions/artifacts and constrain credentials to their intended consumers. Evidence: .github/workflows/release.yml:31-49, .github/workflows/release.yml:230-307, scripts/release.sh:875-899, .github/workflows/jules-review.yml:28-39, .github/workflows/jules-el-conejo-review.yml:259-324.

## Assumptions

- Authorized scope is the current repository at '.', with no supplied deployment context, threat model or knowledge base. Source inspection was offline and read-only; application code and tests were not executed. Ignored dependency/build directories and the target symlink were not followed. Only root SECURITY.md was found in the nonignored source inventory.
- No public web service, tenant deployment or external authentication layer was established. MCP is stdio-only in the inspected entrypoint; client authentication, subprocess sandboxing, memory/CPU quotas and filesystem ACLs remain host responsibilities. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:373-381; SECURITY.md documents process limits as a caller obligation.
- Documentation/control qualification: build_server describes tools as only touching files under root, and explicit document I/O does use OutputRoot. Native render font discovery and font-index persistence instead use ambient host paths, potentially outside that root. Thus the root is a document-I/O capability boundary, not an established process-wide filesystem sandbox. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108, src/convert/font.rs:2633-2652, src/convert/font.rs:3098-3107, src/convert/font.rs:3154-3229.
- Signing is staged rather than currently mandatory: docs describe signature protection after activation and explicitly disclose checksum-only operation before that point; actual RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None. No deployed secret or release state was queried. Evidence: docs/SELF_UPDATE.md:59-87, src/update.rs:44-48.
- The local release fallback assembles downloaded CI artifacts and directly creates a release after checksumming, without the release workflow's signing block. Current empty trusted keys make this compatible with current updater policy; behavior after future signing activation needs separate review. Evidence: scripts/release.sh:976-1012, .github/workflows/release.yml:252-307, src/update.rs:44-48.
- Dependency documentation has drifted: SECURITY.md discusses rdocx-opc 0.2 and quick-xml 0.41; the inspected manifest actually names oxml-opc 0.14.2, direct quick-xml 0.42 and a separate 0.41 alias for OPC error compatibility. Treat the manifest/lockfile dependency graph as current implementation evidence rather than assuming the older package name describes it. Evidence: Cargo.toml:131-149.
- self_update implementation, external pinned GitHub actions, Jules service authorization and the external app release-engine.sh are not present in the inspected source surfaces. Their endpoint credential forwarding, extraction/replacement mechanics, actual branch-write grants and publication approval controls remain unresolved. Evidence: src/update.rs:198-258, .github/workflows/jules-review.yml:35-41, .github/workflows/jules-el-conejo-review.yml:272-324, scripts/release.sh:382-389.
- The general Python Document facade stores bytes without parsing on construction; native operations perform validation. Loading a Document is therefore not itself proof of admission. Evidence: jubarte-python/python/jubarte_redlines/document.py:116-145.
- Native, Python and Node CLIs share engine semantics but not a single filesystem writer. Do not infer native staged publication guarantees for Python Path.write_bytes or Node fs.writeFileSync. Evidence: src/bin/jubarte.rs:261-273, jubarte-python/python/jubarte_redlines/__main__.py:126-133, jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111.
- Final source validation found admission/consumer gaps and downstream numeric/decoded-resource amplification despite the documented input limits. Confirmed scenarios are retained as findings; the architecture's description of configured limits is not a claim that all consumers enforce them. All 122 model source references and 52 current finding code excerpts were checked against current files; no application code was executed.
