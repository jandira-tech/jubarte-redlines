# Threat Model

Jubarte is a Rust DOCX toolkit for comparison, tracked edits, revision resolution, inspection, validation/repair, scrubbing, merging, Markdown conversion and PDF/PNG rendering, exposed through a native CLI, PyO3 library/Python CLI, optional Python stdio MCP server, and browser/Node WASM bindings (src/lib.rs:7-35; Cargo.toml:58-60; jubarte-python/pyproject.toml:43-49,57-59; jubarte-wasm/npm/package.json:34-75). Representative flow is caller-controlled package bytes -> admission -> in-memory OPC parts/XML DOM -> processing -> returned bytes or host-specific filesystem publication (src/wml_document.rs:50-57,85-96; src/admission.rs:439-470; src/publication.rs:175-225). Native rendering additionally reads installed/user/cloud fonts and maintains an on-disk font index (src/convert/mod.rs:857-878; src/convert/font.rs:2258-2276,3090-3107,3183-3229). Explicit self-update and maintainer release workflows have separate network and publication authority (src/update.rs:186-257; .github/workflows/release.yml:15-21,230-235,356-369). This is architecture mapping, not completed security-audit coverage. The explicitly authorized live checkout reported HEAD 41019ae16a6123f0273af0ca997901c85437be12; these citations must not be represented as immutable coverage of the different hash embedded in the scan artifact directory.

## Assets

- Confidential document text, revisions, comments, authors, images, embedded fonts and derived Markdown/PDF/PNG/reports; MCP returns text, inspection data, reports and rendered page text to its connected caller (jubarte-python/python/jubarte_redlines/mcp_server.py:132-150,194-218,246-255).
- Integrity and recoverability of caller-selected documents and output files. Native ambient publication stages and verifies bytes before per-file installation; capability-rooted publication additionally confines relative paths (src/publication.rs:161-225,535-570).
- Host availability: package inflation, XML parsing, comparison, image decoding and font parsing consume caller process resources. Default admission is 64 MiB compressed/per-part, 256 MiB aggregate inflated, 10,000 entries and depth 256; comparison/rendering uses 512 MiB compressed/per-part and 2 GiB aggregate with the same entry/depth caps (src/admission.rs:63-99; src/convert/mod.rs:773-778).
- Native font source integrity and persistent font index. Its configured location may be outside the document root and contains font source paths and filesystem stamps (src/convert/font.rs:2637-2652,3090-3107,3154-3170,3183-3229).
- Installed native executable integrity and release distribution authority. Updater selects jandira-tech/jubarte-redlines and SHA256SUMS.txt; signing trust keys are currently empty and the signed-release floor is None (src/update.rs:25-48,198-257).
- Release credentials: GitHub Actions GITHUB_TOKEN, optional ZIPSIGN_PRIVATE_KEY, and operator registry credentials/OTP. Their authority is publication/signing, independent of ordinary document processing (.github/workflows/release.yml:230-235,261-307,356-369; scripts/release.sh:934-958).
- Shared self-hosted CI filesystem/process authority and private build-cache connectivity, distinct from GitHub token permission (.github/actions/mbx/action.yml:8-32; .github/workflows/ci.yml:26-48).

## Trust Boundaries

- Untrusted document producer -> engine process: complete DOCX bytes and package metadata cross into ZIP/XML/image/font parsers. Admission performs preindex budgeting and ZIP defect refusal before later processing; the production OPC opener repeats structural consistency checks. Debug triage deliberately opens unchecked and reports defects instead of applying the normal opener's refusal (src/admission.rs:439-470; src/opc/archive.rs:15-51; src/debug.rs:213-215).
- Untrusted raw XML -> public XML APIs: try_parse_xdocument defaults to InputLimits::default and its explicit-limit variant validates before DOM allocation. Infallible parse_xdocument deliberately provides no input-policy enforcement; callers must validate first (src/xmllinq/parse.rs:90-135). This is an explicit API contract, not an established bypass.
- MCP client -> root-granted filesystem operations: stdio server accepts --root, default cwd, resolves it once, constructs native _OutputRoot, reads through the held capability and publishes capability-relative names. Path.resolve supplies early diagnostics rather than final authorization. Tool annotations are descriptive hints; the filesystem capability owns confinement (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,373-381; src/publication.rs:146-199).
- MCP client -> modification authority inside the granted root: edit writes out_dir/clean.docx, redline.docx, patch.diff, report.json and optional rendered files; render writes page-NN.png and optional render.pdf. Existing targets require overwrite=true. No distinct per-user or per-tool access policy is shown within that root (jubarte-python/python/jubarte_redlines/mcp_server.py:153-218,220-255; src/publication.rs:448-467,558-570).
- Local CLI operator -> ambient filesystem: native CLI reads user-specified paths and grants ambient publication authority. Python and Node adapters separately use host read/write APIs; they must not inherit the stronger native publisher's atomicity/confinement claims merely because they expose the same command names (src/bin/jubarte.rs:2740-2769; src/publication.rs:203-225; jubarte-python/python/jubarte_redlines/__main__.py:61-89,101-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-79,106-112).
- Markdown contents -> native CLI resource reads: --resource-path overrides the Markdown file's parent directory, falling back to cwd for a bare filename. Targets are percent-decoded, URL schemes refused, canonicalized beneath the root, then read through a held directory capability (src/bin/jubarte.rs:2811-2879,2936-2943). This is a separate, bounded local-read capability, not external relationship fetching.
- Document font names -> native rendering environment: renderer consults installed/user/cloud fonts and a persistent index using process environment and ambient filesystem access. Cloud font family path construction requires one normal component; index validity uses header/version and source stamps. This host-font activity is separate from MCP document path confinement (src/convert/mod.rs:857-878; src/convert/font.rs:2225-2236,2258-2276,2637-2652,3100-3107,3154-3170,3314-3358).
- Browser/Node host -> WASM module load and byte APIs: package exports select browser or Node loaders; browser default initialization fetches a sibling jubarte_wasm_bg.wasm, while Node reads its installed module file. These are executable-module acquisition paths, distinct from document relationship processing (jubarte-wasm/npm/package.json:34-75; jubarte-wasm/npm/web/jubarte_wasm.js:2571-2592; jubarte-wasm/npm/node/jubarte_wasm.js:2553-2555).
- Operator -> updater -> GitHub release executable: explicit self-update performs preflight, release selection, optional confirmation and checksum verification. The archive binary path is jubarte-{version}-{platform}/jubarte plus platform executable suffix; extracted binary must be a regular file before installation (src/update.rs:102-125,198-257,307-321).
- Maintainer/tag authority -> distribution channels: v* tag push triggers read-only build jobs and a contents:write release job. Signing secret is supplied only to the signing step, decoded under RUNNER_TEMP/zipsign.XXXXXX and removed by trap; publish step receives GITHUB_TOKEN. Local release script has a typed version confirmation before pushing and registry publication, and verifies the tag's engine artifact stamp (.github/workflows/release.yml:15-21,230-235,261-307,356-369; scripts/release.sh:870-919,934-958).
- Lower-trust PR contributor -> shared self-hosted CI: ci/adoption/docs/md-roundtrip subscribe to pull_request and execute the checkout on self-hosted, which can reach a shared tokenless private mbx cache and reused checkout/disk (.github/workflows/ci.yml:13-17,34-48; .github/workflows/adoption.yml:61-100; .github/workflows/docs.yml:79-99; .github/workflows/md-roundtrip.yml:28-39; .github/actions/mbx/action.yml:8-32). External PR-run approval and disposable runner provisioning remain unknown.

## Attacker Capabilities

- A document supplier can control package bytes, ZIP names/metadata, XML nesting/attributes, relationships, embedded images/fonts, document font names and text before a user or embedding application processes them. This does not imply control of host environment, executable installation, release credentials or process privileges (SECURITY.md:38-74; src/admission.rs:13-28).
- An authorized MCP caller can name readable documents and request supported edits/renders anywhere inside the operator-granted root, including overwrite when explicitly set. The caller does not thereby receive ambient arbitrary-path authority; native capability-relative I/O owns that boundary (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,153-218; src/publication.rs:146-199).
- An embedding Rust/Python/JavaScript application controls the bytes and options it passes. Trust in library callers is separate from trust in document producers; deployments that accept remote uploads or multi-tenant requests must add their own access controls and resource containment (src/lib.rs:7-35; SECURITY.md:71-85).
- A local CLI user intentionally selects ambient input/output paths under their own OS authority. Such selection is ordinary authorized behavior, not a privilege escalation (src/bin/jubarte.rs:2740-2769; src/publication.rs:203-225).
- A remote document supplier is not presumed able to change JUBARTE_FONT_DIR, JUBARTE_FONT_INDEX, the font index, installed fonts, release assets, tags or registry credentials. Any story requiring such control must establish a separate prerequisite (src/convert/font.rs:2637-2652,3100-3107; src/update.rs:25-48).
- A lower-trust contributor can submit PR-controlled code; execution depends on external GitHub run admission. Source PR workflows select self-hosted and execute checkout code, while actual disposable provisioning/cache-server policy is unavailable (.github/workflows/ci.yml:13-17,34-48; .github/actions/mbx/action.yml:8-32).

## Security Objectives

- Reject packages violating active size, count, inflation, XML or ZIP-structure policy before ordinary document processing; preserve explicit distinctions between standard and comparison budgets and caller overrides (src/admission.rs:63-109,439-470; src/opc/archive.rs:34-51).
- Use checked XML parsing for untrusted direct XML, retaining the intentionally permissive parser contract and inclusive configurable tag limits (src/xmllinq/parse.rs:49-57,90-135; SECURITY.md:43-65).
- Keep MCP document reads and publications within the held root capability despite pathname/symlink changes; refuse unsafe portable output names and output symlinks, preserve default no-clobber behavior, and report partial commits/durability uncertainty (src/publication.rs:146-199,228-255,448-467,535-570).
- Native publication must verify staged content and install each output without deleting the old destination as fallback; multi-file publication is only atomic per file (src/publication.rs:168-174,535-570).
- Avoid fetching document external relationships. Native Markdown image resource reads remain confined to the explicitly selected resource root (SECURITY.md:71-74; src/bin/jubarte.rs:2811-2879).
- Keep caller process CPU/memory containment as an explicit deployment obligation; admission bounds are not a universal denial-of-service guarantee (SECURITY.md:71-74).
- Keep self-update conditional on explicit command invocation, platform/version selection, confirmation or --yes, integrity verification and regular-file extraction. Do not represent current checksum-only releases as signature-authenticated (src/update.rs:25-48,120-125,198-257,307-321).
- Protect release signing and publication authority separately from ordinary runtime input; do not disclose credential contents in model artifacts (.github/workflows/release.yml:261-307,356-369).
- Keep lower-trust PR execution isolated from trusted runner/shared-cache authority; token read-only settings alone do not enforce that boundary (.github/workflows/ci.yml:26-48; .github/actions/mbx/action.yml:8-32).

## Assumptions

- Origin: supplied task context and resolved root SECURITY.md. Policy covers engine, CLI and Python/WASM bindings, treats DOCX/DOC/XML/images/fonts as untrusted, and places CPU/memory containment on callers. No user deployment context or authoritative external knowledge base was supplied.
- The architecture review initially observed HEAD 41019ae16a6123f0273af0ca997901c85437be12 in the authorized repository; later current-state observation is recorded below. A different hash in the inherited scan artifact directory is not evidence that these live files match that scan baseline.
- MCP transport is stdio; no HTTP listener, remote exposure, authentication service or tenant model is established by the inspected entrypoint (jubarte-python/python/jubarte_redlines/mcp_server.py:373-381).
- Documentation qualification: src/lib.rs:10-11 describes complete-byte functions with no temp files, but native rendering has host font reads plus a persistent font index saved through a sibling temporary file (src/convert/mod.rs:857-878; src/convert/font.rs:3183-3229). The broad wording must not be used as a guarantee of zero native filesystem activity.
- Documentation qualification: build_server says its tools only touch files under root, while its docx_render delegates native rendering, which can consult host fonts and save the configured font index outside that root (jubarte-python/python/jubarte_redlines/mcp_server.py:67-72,234-236; jubarte-python/src/lib.rs:389-414; src/convert/mod.rs:857-878; src/convert/font.rs:2637-2652,3100-3107,3213-3229). Root confinement is established for document path arguments and publications; whole-process confinement is not established.
- Cross-surface claims need bounded interpretation: Python/Node CLI headers advertise common names/flags/output behavior, but those adapters write with Path.write_bytes/fs.writeFileSync, unlike native staged publication (jubarte-python/python/jubarte_redlines/__main__.py:5-7,126-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:6-8,106-112; src/publication.rs:535-570). No exploitability assessment was performed.
- Current updater keys are empty and signed-release floor is None. Release workflow permits unsigned archives when no signing secret or committed public keys exist; this is consistent checksum-only behavior, not an established policy contradiction (src/update.rs:44-48,245-250; .github/workflows/release.yml:267-275).
- Host OS permissions, filesystem ACLs, environment values, actual granted MCP root, index ownership and public-service process limits are deployment facts not supplied here. Their effective concrete paths must be obtained from the deployment before claiming isolation from other local actors.
- Tests, benchmarks, fuzz harnesses, examples and developer utilities were not treated as production services. Privileged publication paths were mapped conditionally; no workflow, application code or attack input was executed.
- Source-state observation: during this audit, the authorized checkout HEAD changed from the architecture review's 41019ae16a6123f0273af0ca997901c85437be12 to the directly read current ref 4e10eca69c42211651ca907f38b74b6d19e6928c. Parent re-read all 30 retained finding evidence ranges after that change and found exact matches; no Git history or other revision was reviewed. These results concern inspected live source, not an immutable snapshot.
