# Threat Model

Jubarte is a local Rust Word-document engine providing DOCX comparison, tracked changes, inspection, editing, validation, repair, scrubbing, Markdown conversion, PDF and PNG rendering. Rust byte APIs are exposed through PyO3 and wasm-bindgen; native, Python and Node CLIs add host filesystem access. A separately installed Python MCP server exposes document tools over stdio with a caller-selected directory capability. Normal document processing loads package contents into memory, checks archive/XML policy on checked paths, and returns document/report/render bytes. Legacy DOC conversion has a separate OLE parser. Self-update and release automation are conditional privileged workflows, separate from document processing. Evidence: src/lib.rs:96-165; src/wml_document.rs:35-58; jubarte-python/pyproject.toml:42-49; jubarte-python/Cargo.toml:35-40; jubarte-wasm/Cargo.toml:18-32; jubarte-python/python/jubarte_redlines/mcp_server.py:67-112,373-381; src/legacy_doc.rs:13-50; src/update.rs:186-257.

## Assets

- Confidential source document bytes and their extracted text, comments, revisions, embedded media/fonts and derived artifacts; MCP text and render tools return document-derived content to their stdio caller. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:131-144,185-217,234-255.
- Integrity of originals, chosen output destinations, edit plans, clean/redline outputs, receipts and source/request/output digest bindings. Evidence: src/edit/prepared.rs:5-13,163-171,228-230; src/bin/jubarte.rs:1631-1656,1764-1813.
- Availability and memory/CPU resources of the embedding process: default admission allows 64 MiB compressed/per part, 256 MiB total inflated, 10,000 entries and XML depth 256; comparison admission instead permits 512 MiB compressed/per part and 2 GiB total inflated with the same entry/depth caps. Both retain 1,024 attributes/name bytes, 64 MiB attribute values and 128 MiB complete start tags. Evidence: src/admission.rs:63-99; src/xmllinq/parse.rs:48-65.
- MCP-granted root and documents/artifacts below it. The explicit file capability is an open cap-std directory, not an authentication or tenant identity. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/publication.rs:146-199.
- Native font files and persistent font metadata outside document roots: JUBARTE_FONT_DIR or platform data directories, Office/system fonts, and JUBARTE_FONT_INDEX or sibling font-index.tsv. Evidence: src/convert/font.rs:2281-2315,2633-2652,2855-2862,3090-3107,3182-3229.
- Installed executable integrity and release/package publication authority. The shipped updater's trusted signature-key list is empty, so its effective policy currently uses release checksums rather than mandatory signatures. Evidence: src/update.rs:25-48,198-210,245-257; .github/workflows/release.yml:230-235,261-309,356-369.
- CI runner filesystem, shared build-cache integrity, repository automation tokens and external Jules session authority. Evidence: .github/workflows/ci.yml:13-48,72-106; .github/actions/mbx/action.yml:8-22,33-52; .github/workflows/jules-review.yml:18-50; .github/workflows/jules-el-conejo-review.yml:254-324.

## Trust Boundaries

- Document producer to checked package consumers: attacker-controlled DOCX bytes cross archive indexing, decompression, XML scanning and DOM construction. admit applies preindex budgets, archive-defect checks, canonical part-name/duplicate checks, compression/encryption policy, bounded inflation and XML checks before returning package facts. Package data remains in memory; package entry names are not filesystem extraction destinations. Evidence: src/admission.rs:17-28,439-505,525-575; src/opc/archive.rs:34-51.
- Different byte APIs have distinct admission contracts. Inspection and validation consume InputLimits::default; WmlDocument and PDF/PNG layout use comparison budgets; comparer bindings permit typed key-by-key overrides. Markdown uses a bounded package constructor and its own XML policy while intentionally tolerating some malformed auxiliary XML. Evidence: src/inspect.rs:604-622; src/validate.rs:440-446; src/wml_document.rs:35-55; src/convert/mod.rs:768-798; src/document_comparer.rs:4926-4927; jubarte-python/src/lib.rs:65-100; jubarte-wasm/src/lib.rs:63-94; src/markdown/mod.rs:647-675.
- Raw XML caller to arena DOM: parse_xdocument is deliberately permissive and does not enforce input policy. try_parse_xdocument_with_limits validates first. An embedding caller must select the checked API or previously admit the XML/package; the raw API itself is not a safe-input guarantee. Evidence: SECURITY.md:54-65; src/xmllinq/parse.rs:84-135.
- Package relationship targets to content lookup: representative renderer paths resolve targets to PartFs bytes instead of fetching URLs or reading arbitrary host paths; story enumeration excludes External relationships. Embedded fonts resolve to in-memory package parts and are parsed as fonts. This is distinct from native installed-font lookup. Evidence: src/convert/mod.rs:789-793,21285-21304; src/convert/font_table.rs:205-228; src/opc/mod.rs:555-563.
- Native Markdown to local image resources: the CLI selects --resource-path or the Markdown input's parent directory, canonicalizes it and opens an OutputRoot capability. Percent-decoded schemes and paths escaping that root are refused; actual reads use the held capability. Evidence: src/bin/jubarte.rs:2835-2876,2936-2943.
- Local CLI user to ambient filesystem: native publish_paths intentionally grants access to explicitly selected host paths. Native edit publication stages exact output bytes, checks aliases/output collisions, rechecks source SHA-256 and commits each file, reporting partial commitment on failure. It is not an all-files atomic transaction. Python and Node CLI wrappers instead have their own direct host write implementations; shared argument grammar does not establish publication-control parity. Evidence: src/publication.rs:168-173,203-225; src/bin/jubarte.rs:1642-1656,1764-1813; jubarte-python/python/jubarte_redlines/__main__.py:101-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:76-110.
- MCP stdio caller to brokered document I/O: operator --root defaults to startup cwd and is expanded/resolved before serving. The Python server performs early containment checks, but _OutputRoot/read/publish ultimately uses the Rust directory capability and portable relative-name validation. Every connected caller gets the registered tools within this same root; read/write ToolAnnotations are hints, not a separate caller-authorization system. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:54-108,373-381; src/publication.rs:146-199,228-255.
- MCP rendering to native renderer resources: docx_render and optional edit rendering invoke native font resolution. Explicit document reads/writes remain capability-relative, but renderer font reads and font-index persistence use ambient process paths outside --root. The MCP module's broad 'tools only touch files under root' wording is therefore broader than the actual whole-process resource boundary. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:67-72,185-188,234-236; src/convert/mod.rs:806-857; src/convert/font.rs:2637-2652,3100-3106,3182-3227.
- Native renderer to local font state: document-selected family names drive search of configured/system/Office/user directories. The font index records source paths and modification stamps, reads cached face paths and persists through a PID-named temporary sibling followed by rename. Host permissions and trusted startup configuration govern these resources; OutputRoot does not. Evidence: src/convert/font.rs:2258-2276,2281-2315,2637-2652,3154-3171,3182-3229.
- WASM engine to host: the Rust publication module is absent on wasm32; browser byte APIs return bytes/strings, while the Node CLI independently reads/writes local files. Python and WASM bindings disable root default features and do not enable self-update. Evidence: src/lib.rs:163-165; jubarte-wasm/Cargo.toml:18-32; jubarte-python/Cargo.toml:35-39; jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21,52-73,106-110.
- Legacy DOC producer to OLE parser: .doc conversion reads the WordDocument and table streams and produces escaped Markdown/DOCX; encrypted/obfuscated and unsupported old formats are refused. It is a separate parser contract, not DOCX ZIP admission. Evidence: src/legacy_doc.rs:13-50.
- Maintainer debug input to diagnostic ZIP reader: debug deliberately opens archives unchecked and inspects defects rather than inheriting production refusal behavior. Evidence: src/opc/archive.rs:15-20; src/debug.rs:213-215.
- Release service to executable replacement: explicit self-update uses fixed jandira-tech/jubarte-redlines release lookup, platform-specific archive/binary paths, SHA256SUMS.txt and a regular-file verification hook. Nonterminal mutation requires --yes; --check does not install. RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None make mandatory signature verification inactive in this source. The extraction/swap implementation belongs to self_update, not document admission. Evidence: src/update.rs:25-48,91-108,120-125,186-257,299-318; docs/SELF_UPDATE.md:59-87.
- Maintainer/tag authority to publication: tag-driven release validates tag/version, builds platform binaries/wheels with read-only repository permissions, and gives only the final release job contents:write. ZIPSIGN_PRIVATE_KEY reaches the signing step and temporary key files; GITHUB_TOKEN reaches gh release publication. The local release script additionally publishes crates.io/npm/PyPI and has an unsigned artifact-recovery route. Evidence: .github/workflows/release.yml:15-21,40-49,51-89,230-309,356-369; scripts/release.sh:374-380,919-959,976-1012,1066-1069.
- PR authors to CI runner execution and shared cache: pull_request workflows check out and execute repository build/test code on self-hosted runners with contents:read and no persisted checkout credentials. The mbx action configures http://mbx-cache:7543 and namespace jandira-tech/jubarte-redlines, exports a cargo shim and a 20 GiB local GC setting. Its comments assert private-network reachability and protected-push-only cache publication; deployment isolation and external action enforcement are not established by this repository. Evidence: .github/workflows/ci.yml:13-48,72-99; .github/workflows/adoption.yml:48-59; .github/workflows/docs.yml:79-99; .github/actions/mbx/action.yml:8-22,33-52.
- Repository automation to external review/remediation service: Jules review runs only for same-repository, non-Dependabot PRs, receives JULES_API_KEY/GITHUB_TOKEN, has review/check write permissions and explicitly disables approvals. The separate companion-remediation action gates session creation to the configured trusted author/dispatcher and selected events, sets AUTO_CREATE_PR and require_plan_approval:false, and sends JULES_API_KEY. These are distinct workflows and authorities. Evidence: .github/workflows/jules-review.yml:18-50; .github/workflows/jules-el-conejo-review.yml:34-52,74-92,254-324.

## Attacker Capabilities

- A document producer can supply DOCX/DOC/XML, embedded fonts/images, package relationships and document text to an embedding caller. This does not initially grant host filesystem paths, trusted environment variables, executable-replacement authority or release credentials. Input limits and parser gates protect the caller's process boundary. Evidence: SECURITY.md:38-74; src/admission.rs:439-575.
- An MCP-connected agent can invoke the server's registered read and mutation tools, select paths below the operator-granted root, receive extracted content and request overwrite=true. This is already the tool capability granted by the operator; it is not evidence of tenant separation or per-tool authentication. The meaningful boundary is escape beyond granted document resources or unintended extra host authority. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:54-112,126-144,220-255,373-381.
- A local CLI/API caller chooses input/output paths, edit operations and explicitly supported settings. Such a caller already exercises the process user's ambient filesystem authority; attacker-controlled document contents alone must not acquire the same path authority. Evidence: src/publication.rs:203-225; src/bin/jubarte.rs:2835-2876; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-110.
- A PR author can supply code that relevant pull_request jobs compile/test on configured runners. No runner-host compromise, access to the private cache network from outside CI, protected-branch status or registry credentials is assumed. These prerequisites require deployment evidence. Evidence: .github/workflows/ci.yml:13-48,72-99; .github/actions/mbx/action.yml:8-22.
- An actor controlling release assets is distinct from an ordinary document producer and from a trusted release-signing-key holder. Current checksum-only updates rely on release-hosting authority; the repository documents that an actor replacing both archive and checksums is not stopped by SHA-256 alone. Evidence: docs/SELF_UPDATE.md:59-80; src/update.rs:44-48,245-257.

## Security Objectives

- Bound archive indexing/inflation and checked XML construction under the active consumer's limits; preserve typed refusal behavior and caller-selected budgets. Do not silently treat permissive raw parsing as checked admission. Evidence: src/admission.rs:63-99,439-575; src/xmllinq/parse.rs:84-135.
- Keep document relationships as package/data references without arbitrary network or ambient-file retrieval; confine native Markdown image reads to the explicitly selected resource root. Evidence: SECURITY.md:70-74; src/convert/mod.rs:789-793,21285-21304; src/bin/jubarte.rs:2835-2876.
- Preserve explicit file capability boundaries for MCP document I/O, reject unsafe export names and escaping/output symlinks, and require overwrite authority for replacement. Treat native font/cache I/O as a separate host-owned resource policy. Evidence: src/publication.rs:146-199,228-255,420-445; jubarte-python/python/jubarte_redlines/mcp_server.py:75-108; src/convert/font.rs:2637-2652,3100-3106.
- Bind applied edits and receipts to the source, request and exact selected output bytes; refuse source changes and unauthorized path aliases before native edit publication. Preserve accurate partial-commit and durability outcomes. Evidence: src/edit/prepared.rs:5-13,163-171,228-230; src/bin/jubarte.rs:1631-1656,1764-1813; src/publication.rs:168-173.
- Perform executable replacement only in the explicitly invoked updater workflow, with platform matching, version/confirmation policy, checksum verification and a regular extracted binary; require signatures only when compiled policy actually activates them. Evidence: src/update.rs:91-125,186-257,299-318.
- Keep release-signing and registry credentials out of documents, artifacts, reports and ordinary runtime components; restrict release/write and external-remediation authority to their separately configured workflows. Evidence: .github/workflows/release.yml:230-309,356-369; .github/workflows/jules-review.yml:18-50; .github/workflows/jules-el-conejo-review.yml:254-324.
- Require host memory/CPU limits for untrusted workloads; admission budgets alone do not establish comprehensive denial-of-service isolation. Evidence: SECURITY.md:71-74.

Cache server configuration, runner cleanup, fork approval policy, network isolation and actual host privileges are not present in the inspected deployment declarations. Evidence: .github/actions/mbx/action.yml:8-22; .github/workflows/ci.yml:13-48.
- Third-party self_update extraction/swap and external Jules/mbx action implementations were not inspected in this architecture pass; their exact implementation-owned controls remain explicit follow-up gaps, not confirmed missing protections.
- The in-process benchmark adapter is developer tooling with direct stdin-selected ambient file reads/writes, not a production server or a constrained MCP replacement. Evidence: jubarte-rust-inproc/src/main.rs:7-20,29-48,91-99.
- The root policy names rdocx-opc 0.2 in its dependency narrative, while the current manifest declares oxml-opc 0.14.2. The actual manifest/dependency graph must govern implementation review; the narrative name is stale. Evidence: SECURITY.md:89-94; Cargo.toml dependency declaration inspected.
- This is source-backed architecture mapping only. No vulnerability audit coverage, exploit validation, runtime isolation verification or live secret/provider configuration is claimed.
- Audit reconciliation: auxiliary XML admission bypass, altChunk expansion and WMF record-count failures are validated findings; native/MCP publication and document font path controls received source-backed dispositions. Python/Node final-output links and recorder staging violate the published publication contract and are retained as separate locally constrained findings. Broader source coverage remains partial.
