# Threat Model

Jubarte is a Rust document-processing library and CLI with Python/PyO3 and WASM bindings. It compares, reads, edits, validates, repairs, scrubs and renders Word documents using in-memory package/XML processing. Native CLI and Python/Node host adapters supply local filesystem authority; the optional Python MCP adapter exposes document tools over stdio with a persistent directory capability. Rendering additionally uses native host font files and a persistent font index independently of MCP document-root confinement. Optional native self-update downloads GitHub release assets and replaces the executable; maintainer scripts and tag-triggered CI separately publish packages and releases. Representative entry points and gates: src/bin/jubarte.rs:3560-3578, jubarte-python/pyproject.toml:42-49, jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381, jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21, src/inspect.rs:604-622, src/convert/mod.rs:769-798, src/update.rs:186-257.

## Assets

- Confidential document text, revision history, comments, embedded media and derived PDF/PNG/Markdown/diff/report outputs; MCP tools return document text, findings and reports as well as output paths to their connected client (jubarte-python/python/jubarte_redlines/mcp_server.py:131-150,185-217,234-255,354-368).
- Host filesystem integrity and intended output destinations. Native publication stages bytes beneath each selected output parent; MCP publication instead retains the operator-granted OutputRoot directory handle and accepts only portable relative output names (src/publication.rs:146-225,228-270,420-505).
- Source-to-edit binding and the integrity of checked primary output. V1 source SHA-256 checking is conditional on the optional plan field; V2 requires source.sha256 equality. Prepared edits retain source, normalized request and actual chosen-primary digests (src/edit.rs:2081-2089, src/edit/v2_apply.rs:84-99, src/edit/prepared.rs:157-181).
- Process availability and memory during ZIP/XML, legacy document, font, image and rendering work. Agent admission defaults are 64 MiB compressed/per-part, 256 MiB total inflated, 10,000 entries and XML depth 256; comparison defaults are 512 MiB compressed/per-part and 2 GiB total inflated with the same entry/depth caps. Overrides replace individual values (src/admission.rs:63-99,103-165).
- Native font sources and font-index integrity: JUBARTE_FONT_DIR or platform data folders supply fonts; JUBARTE_FONT_INDEX or the parent of the font folder supplies font-index.tsv. Cached face paths are read by the renderer and the index is persisted through a sibling temporary file and rename (src/convert/font.rs:2633-2652,3098-3107,3154-3172,3213-3229).
- Installed executable authenticity and release publication authority. Current self-update trusts GitHub release delivery plus SHA256SUMS.txt; RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None. CI signing secrets, GitHub contents-write credentials and local package-registry credentials are separate authorities (src/update.rs:25-48,198-210,245-257; .github/workflows/release.yml:230-264,278-308,356-369; scripts/release.sh:904-919,929-958,1063-1069).

## Trust Boundaries

- Untrusted DOCX/ZIP/XML bytes cross into package admission and then DOM/document operations. Opened::open admits using default limits, normalizes Strict packages and opens/parses within those limits. General rendering calls admit_package before package/DOM construction. The common archive opener rejects reported structural defects, while the deliberately unchecked opener supports triage and admission's own typed checks (src/inspect.rs:604-622; src/convert/mod.rs:769-798; src/opc/archive.rs:15-51).
- Raw XML library callers choose between checked and permissive APIs. try_parse_xdocument_with_limits validates before constructing the DOM; parse_xdocument explicitly requires a prior gate and does not enforce input policy itself. Shared defaults include 1,024 element attributes, 1,024 attribute-name bytes, 64 MiB attribute values and 128 MiB start tags (src/xmllinq/parse.rs:25-36,48-57,91-98,119-135).
- Edit requests cross from caller-authored plans to document mutations. V1 checks a supplied source hash, refuses blank authors and signed/macro-bearing inputs; V2 requires the exact source hash and resolves scope/context before operations. These are document-consistency controls, not user authentication or authorization (src/edit.rs:2072-2105; src/edit/v2_apply.rs:84-110). Dry run and application share in-memory preparation; filesystem publication remains a separate host operation (src/edit/prepared.rs:5-13,157-186).
- Native CLI users grant ambient authority through selected input/output paths. publish_paths opens and retains each actual parent rather than enforcing a global document root; staging uses an exclusive UUID directory and file, with Unix staging directory mode 0700. Publication is atomic per file and records partial commits/durability uncertainty rather than promising set-wide rollback (src/publication.rs:5-7,83-143,203-225,420-505).
- The MCP connected client can invoke registered read and write tools within the root chosen by the server operator. Startup defaults --root to cwd, resolves it once and serves stdio. Python containment checks are preliminary diagnostics; actual document reads and output publication pass through native _OutputRoot and cap-std directory-relative operations. No per-tool user identity or tenant separation is established; tool annotations are hints, while OutputRoot owns filesystem confinement (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,373-381; jubarte-python/src/lib.rs:1244-1276; src/publication.rs:146-199).
- Native font discovery/cache is a separate authority from document-root publication. Font-family lookup can inspect system, Word, cloud and configured user-font directories; cloud family names must be one normal path component. The index may read cached face paths and write its configured file outside the MCP root. Its enforcing boundary is host environment/filesystem authority, not OutputRoot (src/convert/font.rs:2225-2236,2263-2315,2633-2652,2855-2862,3098-3107,3154-3172,3213-3229).
- WASM byte APIs do not receive native publication::OutputRoot because that module is compiled only outside wasm32. Python and WASM bindings disable engine default features and request only cli grammar, so optional self-update is not part of those engine dependencies. Node's separately shipped CLI grants ambient filesystem access through node:fs around the WASM engine; its read/write helpers are distinct from native staged publication (src/lib.rs:147-149,163-165; jubarte-python/Cargo.toml:35-39; jubarte-wasm/Cargo.toml:18-23; jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21,52-79,106-111).
- Self-update is an explicit native CLI capability. It selects fixed jandira-tech/jubarte-redlines repository, platform archive and inner binary path; requests checksum verification and regular-file verification; prompts unless --yes, and --check does not install. Current keys leave signature verification disabled. Dependency-owned download, archive extraction and executable-swap behavior is not established merely by this wrapper (src/bin/jubarte.rs:3892-3896,4062-4073; src/update.rs:25-48,186-257,274-285,299-321).
- Release publication is privileged operator/CI work, separate from document processing. CI triggers on v* tags, checks tag/package version, grants build jobs contents:read and release job contents:write, optionally signs assets with step-scoped ZIPSIGN_PRIVATE_KEY, then publishes dist/* using step-scoped GH_TOKEN. Local release script has packaging dry runs and version confirmation unless YES, then separately publishes crates.io, two npm packages and PyPI with configured credentials (.github/workflows/release.yml:15-21,31-49,230-264,278-308,317-322,356-369; scripts/release.sh:729-747,874-888,904-919,929-958,1039-1069).

## Attacker Capabilities

- A document supplier controls package names, relationships, XML, revision/comment content, embedded fonts/images and document complexity submitted to a consumer. This does not imply host configuration, MCP root directory, registry accounts or release asset access (src/admission.rs:13-28; SECURITY.md:36-78).
- A connected MCP client can request supported reads/mutations under operator-selected root and overwrite=true. Tools expose that shared root capability, not a separate tenant identity. Escape would add host access not granted (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,152-168,258-277,373-381).
- An edit-plan author controls operations and V1 source-hash inclusion. Author strings and revision metadata are document data rather than authenticated identities. Consistency guards are not authorization (src/edit.rs:2081-2105; src/edit/v2_apply.rs:84-110).
- A malicious local peer may possess filesystem access to writable output/cache directories depending on deployment; this is conditional, not assumed. Native held handles, exclusive staging and MCP path validation are relevant to races when such a peer exists (src/publication.rs:146-148,228-270,420-505).
- Control of GitHub release assets, signing material or registry accounts is a conditional supply-chain starting capability, not ordinary document input. Current checksum-only update authenticity depends on release authority and transport/dependency controls; distinct signing-key compromise is not required because trusted keys are empty (src/update.rs:25-48,198-210,245-257; docs/SELF_UPDATE.md:59-82).

## Security Objectives

- Refuse packages/XML violating active policy before unbounded downstream parsing; caller owns process memory/CPU limits and permissive raw XML API obligations (src/admission.rs:13-28,63-99; src/xmllinq/parse.rs:25-36,119-135; SECURITY.md:72-78).
- Keep relationships within package semantics and preserve external targets as data rather than retrieval authority. Representative comparison treats External targets as strings and reads internal part bytes (src/document_comparer.rs:94-108). Broader no-network guarantee requires checking all consumers.
- Keep MCP document reads and explicit artifact writes beneath retained root, refusing escape symlinks, unsafe names and unrequested overwrite; distinguish ambient renderer font/cache I/O (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/publication.rs:146-199,228-270,448-464; src/convert/font.rs:3098-3107,3213-3229).
- Bind verification/receipt digests to chosen primary bytes and report refused plans without publication. V1 snapshot binding is optional when source_sha256 absent (src/edit/prepared.rs:5-13,157-186; src/edit.rs:2081-2089).
- Preserve existing native outputs on staging failure, commit complete bytes per file and report prior commits on later failure; no all-files atomic transaction is promised (src/publication.rs:83-143,168-174,420-505).
- Executable replacement requires explicit update and configured release/checksum/regular-file controls; implemented signature support differs from current checksum-only configuration (src/update.rs:44-48,186-257,299-321).
- Keep document clients separate from maintainer credentials/signing keys; bind CI releases to v* tag and matching package version with scoped permissions/checksums (.github/workflows/release.yml:15-21,31-49,230-264,317-322,356-369).

- No deployment context supplied (userContext=null). No production HTTP/public exposure, tenants, container mounts or concrete operator root established. MCP uses stdio (jubarte-python/python/jubarte_redlines/mcp_server.py:373-381).
- MCP docs say every path is under --root and tools only touch files there (mcp_server.py:7-9,67-68). Actual document I/O is confined but native rendering reads host fonts and writes environment/platform-derived index (src/convert/font.rs:2633-2652,3098-3107,3154-3172,3213-3229). This qualification alone is not a vulnerability without untrusted influence/unauthorized destination.
- Font-index defaults: $HOME/Library/Application Support/jubarte/font-index.tsv (macOS); $XDG_DATA_HOME/jubarte/font-index.tsv or $HOME/.local/share/jubarte/font-index.tsv (other non-Windows); %APPDATA%\jubarte\font-index.tsv (Windows). Nonempty JUBARTE_FONT_DIR changes default to its parent/font-index.tsv; JUBARTE_FONT_INDEX overrides; empty/off disables. Temporary file is font-index.tsv.<pid>.tmp. Values are parameterized source facts, not live environment reads (src/convert/font.rs:2637-2652,3098-3107,3213-3229).
- Root policy native memory-safety/no-fetch claims are inputs, not proof of every dependency/consumer; representative sources inspected, all parsers/consumers still require audit coverage (SECURITY.md:36-93; src/opc/archive.rs:15-51; src/document_comparer.rs:94-108).
- Self-update staged signing docs agree with RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None; updates are currently checksum-only (docs/SELF_UPDATE.md:59-82; src/update.rs:44-48,245-249,274-285).
- docs/SELF_UPDATE.md:22-24 claims GH_TOKEN/GITHUB_TOKEN authenticated API support; wrapper builder does not explicitly pass either (src/update.rs:198-211). Dependency token consumption unresolved; do not infer recipients from docs.
- Native publication is stronger than Node fs.writeFileSync/existence helpers; matching CLI syntax does not establish filesystem parity (src/publication.rs:83-143,420-505; jubarte-wasm/cli/bin/jubarte-redlines.mjs:6-8,76-79,106-111). Python CLI separately uses path.write_bytes (jubarte-python/python/jubarte_redlines/__main__.py:101-133).
- Actual branch/tag protection, secret availability, registry configuration, runner isolation/key custody are external controls not verified from YAML/scripts (.github/workflows/release.yml:15-21,230-264,356-369; scripts/release.sh:904-919,929-958,1063-1069).
- MCP effective read resource is <operator root>/<requested relative document>; edit writes <root>/<out_dir>/{clean.docx,redline.docx,patch.diff,report.json}, optionally redline.pdf and redline-page-NN.png. Render writes page-NN.png and optional render.pdf; compare/accept/reject write caller-selected relative out, all through retained native authority (mcp_server.py:67-108,170-217,220-255,258-327; src/publication.rs:146-199). Connected client receives text/paths/report; host ACLs determine other readers.
- Native output resource is selected ambient parent/.jubarte-<UUID>.partial/bytes, installed to selected name with exclusive staging and mode0700 directory (src/publication.rs:420-505). Node/Python resources are ambient caller-selected pathnames and PID plan partials, independently enforced by OS rather than OutputRoot.
- Native macOS font resources include /Library/Fonts, /Applications/Microsoft Word.app/Contents/Resources/DFonts and $HOME/Library/Group Containers/UBF8T346G9.Office/FontCache/4/CloudFonts/<family>, with family one normal component. User fonts resolve nonempty JUBARTE_FONT_DIR else $HOME/Library/Application Support/jubarte/fonts; other non-Windows use HOME prerequisite then XDG_DATA_HOME or HOME/.local/share; Windows uses APPDATA/jubarte/fonts, WINDIR else SystemRoot else C:\Windows/Fonts, and LOCALAPPDATA/Microsoft/Windows/Fonts (src/convert/font.rs:2225-2236,2281-2315,2637-2652,2855-2862). Recipient is renderer; host environment/ACLs own authority.
- Updater resource chain fixed GitHub repo -> requested/latest version -> platform archive/inner binary -> SHA256SUMS.txt -> optional keys (currently none) -> self_update installer/executable replacement. Preflight/prompt unless --yes, --check noninstallation, regular-file hook. Dependency extraction/swap/transport still need inspection (src/update.rs:25-48,186-257,299-321).
- CI signer consumes secret reference ZIPSIGN_PRIVATE_KEY via step environment, decodes 64-byte private-key files under RUNNER_TEMP/zipsign.<random>/keyN, signs dist/jubarte-*.tar.gz and *.zip and verifies committed public keys; EXIT trap removes staging. Release publisher uses step GH_TOKEN from secrets.GITHUB_TOKEN and contents:write to create release GITHUB_REF_NAME in github.repository from dist/* after checksums (.github/workflows/release.yml:230-264,278-308,317-322,356-369).
- Local Cargo publisher packages root jubarte-redlines $VER and cargo publish --locked via configured credential provider; npm separately publishes jubarte-wasm from jubarte-wasm/npm and jubarte-redlines from jubarte-wasm/cli with optional NPM_OTP; PyPI uses dist/pypi/* and UV_PUBLISH_TOKEN reference after wheel checker or explicit --no-wait partial-set consent. Registries/credential stores remain externally configured (scripts/release.sh:729-747,874-888,904-919,929-958,1039-1069).
