# Threat Model

Jubarte is an in-process Rust document engine exposing comparison, review, inspection, editing, validation, cleaning, Markdown conversion and PDF/PNG rendering through a native CLI, PyO3 Python bindings, wasm-bindgen Node/browser bindings, and an optional Python MCP server over stdio. Document bytes cross into ZIP/OPC, XML, legacy DOC, image and font parsers; operations produce document, text, report and render artifacts. Native CLI publication uses ambient filesystem authority with staged publication, while MCP document reads and writes use a persistent cap-std directory capability. Native rendering additionally reads installed fonts and maintains an ambient font index. Self-update and release publication are conditional privileged workflows. Sources: README.md:12-16; src/lib.rs:96-165; src/publication.rs:146-225; jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; jubarte-python/python/jubarte_redlines/mcp_server.py:373-381; src/convert/font.rs:3090-3107. This is architecture mapping, not completed security-audit coverage.

## Assets

- Confidential source document bytes, document text, authors, comments, revision history, images and fonts, together with generated clean/redline DOCX, PDFs, PNGs and JSON/text reports. MCP exposes document contents through read tools and produces named artifacts through write tools: jubarte-python/python/jubarte_redlines/mcp_server.py:131-150; jubarte-python/python/jubarte_redlines/mcp_server.py:185-217; jubarte-python/python/jubarte_redlines/mcp_server.py:234-255.
- Filesystem integrity of authorized outputs and pre-existing files. Native publication holds destination-parent handles, stages bytes in parent/.jubarte-<UUID>.partial/bytes, verifies staged bytes, and installs by rename when overwrite is allowed or hard link for no-clobber installation: src/publication.rs:419-505; src/publication.rs:535-570.
- MCP root directory authority and all documents intentionally made accessible beneath that root. The root defaults to the launch working directory, is resolved once, and backs native capability-relative reads and publication: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; jubarte-python/python/jubarte_redlines/mcp_server.py:373-381; jubarte-python/src/lib.rs:1244-1277.
- Host CPU, memory and availability during document processing. Agent-facing defaults admit 64 MiB compressed, 10,000 entries, 64 MiB per inflated part, 256 MiB total inflated and XML depth 256; comparison defaults allow 512 MiB compressed/per part and 2 GiB total inflated: src/admission.rs:63-100. PNG rasterization additionally limits an individual raster to 2^28 pixels: src/convert/raster.rs:24-42.
- Native font files, cached font source paths and render fidelity. Font locations come from trusted process environment and platform folders; default index paths are platform data-directory/jubarte/font-index.tsv, rather than inside the fonts subdirectory: src/convert/font.rs:2633-2652; src/convert/font.rs:2855-2862; src/convert/font.rs:3090-3107.
- Installed native executable and release artifact integrity. Self-update selects jandira-tech/jubarte-redlines release assets, SHA256SUMS.txt and a platform-specific archive member. This checkout compiles an empty release key list and no first signed version: src/update.rs:25-48; src/update.rs:91-108; src/update.rs:198-210.
- Conditional maintainer publication authority: GitHub release write permission, ZIPSIGN_PRIVATE_KEY secret reference and temporary decoded signing-key files, local crates.io/npm/PyPI publishing credentials, and integrity of artifacts sent to those registries. No credential values are reproduced: .github/workflows/release.yml:230-285; .github/workflows/release.yml:356-369; scripts/release.sh:919-959; scripts/release.sh:1063-1069.

## Trust Boundaries

- Untrusted document producers provide complete ZIP/OPC packages to a caller-owned process. Admission checks container budgets, canonical part identities, encryption/compression policy, ZIP structure and bounded inflation before document processing. XML-selected parts pass depth/tag policy; package contents remain in memory rather than being extracted: src/admission.rs:13-28; src/admission.rs:439-575; src/admission.rs:788-821. The shared archive opener independently refuses structural/header/type defects: src/opc/archive.rs:34-51. Parent validation establishes that extension-based XML selection misses nonstandard auxiliary XML names; this discrepancy is retained as a finding.
- Admission policy differs by consumer. Inspection opens with InputLimits::default(), admits bytes, normalizes Strict OOXML and opens with the same limits; comparison uses settings.input_limits, whose comparison baseline is larger and can be overridden through Python/WASM binding options: src/inspect.rs:604-622; src/admission.rs:80-100; src/document_comparer.rs:6530-6567; jubarte-python/src/lib.rs:65-79; jubarte-wasm/src/lib.rs:63-74. Limits belong to the engine; process-wide CPU/memory containment belongs to the embedding host.
- Raw XML callers choose between unchecked permissive parse_xdocument and checked try_parse_xdocument[_with_limits]. Checked parsing validates before allocating DOM nodes; the permissive public API explicitly does not enforce input policy: src/xmllinq/parse.rs:84-135. A low-level caller must not assume all public XML/OPC helpers constitute full document admission.
- Document relationships resolve to package parts, not ambient host files. Representative rendering paths filter external story/settings relationships and read package bytes/strings: src/convert/mod.rs:21283-21319; src/opc/mod.rs:555-563. The root policy states external relationships are not fetched during processing: SECURITY.md:72-80. This does not prohibit authorized updater or module-loader networking.
- JSON edit plans cross from caller intent to document mutation. V1 source SHA-256 binding is optional at the library layer and checked when present; V2 requires its source digest. Preparation resolves operations, checks tracked-edit constraints, applies in memory, verifies realized effects and checks candidates before returning bytes: src/edit.rs:2072-2094; src/edit/v2_apply.rs:80-98; src/edit/prepared.rs:196-235. Typed CLI delivery additionally requires a bound legacy plan unless explicitly waived, supports dry run, and rechecks named source bytes before publication: src/bin/jubarte/edit_typed.rs:263-288; src/bin/jubarte/edit_typed.rs:605-611; src/bin/jubarte.rs:1642-1656; src/bin/jubarte.rs:1799-1805. Digests bind document revisions; they do not authenticate an author or approve a caller.
- Native CLI users authorize ambient input/output paths. The native wrapper delegates file publication to publication::publish_paths; that API opens each ambient destination parent and does not impose an MCP-style root: src/bin/jubarte.rs:261-273; src/publication.rs:203-225. Publication is atomic per file and can report a committed subset; the typed out-dir bundle uses a separate directory-publication path: src/publication.rs:168-174; src/bin/jubarte/edit_typed.rs:701-710.
- Python and npm CLI runners independently own ambient filesystem access. Python reads Path values and writes with Path.write_bytes; Node reads and writes with fs.readFileSync/fs.writeFileSync. Their overwrite prechecks and native/WASM computation do not make them equivalent to native staged publication or MCP capability confinement: jubarte-python/python/jubarte_redlines/__main__.py:61-89; jubarte-python/python/jubarte_redlines/__main__.py:101-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-79; jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111.
- MCP stdio clients can invoke registered document read and write tools within the operator-granted root, including overwrite when supplied. Python path resolution provides early diagnostics, while _OutputRoot performs the actual native capability-relative I/O: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; jubarte-python/src/lib.rs:1244-1277; src/publication.rs:146-199. ToolAnnotations are hints, not separate per-tool authorization checks: jubarte-python/python/jubarte_redlines/mcp_server.py:54-55. The server transport is stdio: jubarte-python/python/jubarte_redlines/mcp_server.py:373-381.
- Native rendering has ambient font/cache authority separate from document-output capabilities. It reads configured/platform font directories and a persistent source-path index, and may write parent(user_font_dir)/font-index.tsv through a PID-suffixed temporary file. MCP's OutputRoot does not mediate these internal font operations: src/convert/font.rs:2258-2315; src/convert/font.rs:2637-2652; src/convert/font.rs:3090-3107; src/convert/font.rs:3154-3189; src/convert/font.rs:3211-3229. Document-supplied cloud-font family names are constrained to a single normal path component: src/convert/font.rs:2225-2236.
- Browser/Node module initialization loads trusted executable WASM separately from document data. npm export conditions select node/web or slim variants; Node reads its adjacent jubarte_wasm_bg.wasm, while the browser default fetches that filename relative to import.meta.url and permits an explicitly supplied initialization resource: jubarte-wasm/npm/package.json:34-75; jubarte-wasm/npm/node/jubarte_wasm.js:2552-2556; jubarte-wasm/npm/web/jubarte_wasm.js:2571-2594. Module distribution and hosting are trust prerequisites; document bytes do not select this startup resource.
- Self-update crosses from explicit local operator action and GitHub release assets into installed executable replacement. Noninteractive installation needs --yes, while --check performs lookup without installing. The selected member is jubarte-<version>-<platform>/jubarte[.exe]; SHA256SUMS is enabled and extracted binaries must be regular files. Effective signature enforcement is disabled because RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None: src/update.rs:25-48; src/update.rs:102-125; src/update.rs:198-257; src/update.rs:307-320.
- Tag-triggered GitHub release jobs build read-only, while the release job receives contents:write. The version job compares tag and manifest version; signing receives only a secret reference at its step, decodes keys under RUNNER_TEMP/zipsign.<random>/keyN, signs archive filenames and verifies against committed public keys; publication sends dist/* to the selected repository release: .github/workflows/release.yml:15-21; .github/workflows/release.yml:40-49; .github/workflows/release.yml:230-308; .github/workflows/release.yml:356-369. Local scripts/release.sh is a distinct maintainer workflow with local credentials, security checks, optional ordinary-gate reuse, a typed tag confirmation unless --yes, and registry-specific publishing: scripts/release.sh:655-678; scripts/release.sh:886-900; scripts/release.sh:919-959; scripts/release.sh:1063-1069.

## Attacker Capabilities

- A document supplier can control DOCX ZIP structure, XML, relationship targets, embedded images/fonts, legacy DOC bytes, document text and metadata presented to an authorized engine caller. The supplier does not thereby control process environment, module distribution, release repository, filesystem permissions or selected output paths: src/admission.rs:13-28; src/legacy_doc.rs:13-50; src/convert/font.rs:2225-2236. An untrusted Markdown author can likewise control serialized drawing payload graphs accepted by markdown_to_docx: src/markdown/write.rs:59-110; src/markdown/write.rs:4188-4198.
- An agent/MCP client possessing the stdio connection can request registered read/write operations for files within the operator-granted root, obtain document contents, select output names and request overwrite. Confidentiality inside that granted root is therefore an intentional capability; access outside it or modification beyond granted paths would be a meaningful capability gain: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; jubarte-python/python/jubarte_redlines/mcp_server.py:152-217; jubarte-python/python/jubarte_redlines/mcp_server.py:258-277.
- A caller supplying an edit plan controls operation content and declared author metadata. Source hashes and anchor checks establish document consistency, not identity or authorization. An author name must not be treated as an authenticated principal: src/edit.rs:2081-2094; src/edit/v2_apply.rs:84-98.
- A separate local filesystem actor may race names only where deployment permissions already let that actor modify relevant directories. Persistent directory capabilities and no-clobber installation constrain resulting writes. This prerequisite must be established before asserting cross-user impact: src/publication.rs:146-165; src/publication.rs:419-469; src/publication.rs:558-569.
- A release-asset attacker is distinct from a malicious document supplier. Installed binaries currently rely on GitHub/HTTPS and co-hosted checksum integrity, so release-asset replacement authority is material; ordinary document input does not grant it. Release signing and registry publishing require maintainer/CI authority absent from the document-input model: src/update.rs:25-48; src/update.rs:198-257; docs/SELF_UPDATE.md:59-80; .github/workflows/release.yml:230-285.

## Security Objectives

- Refuse malformed or over-budget untrusted packages before uncontrolled decompression or DOM construction, preserving active caller-specified limits: src/admission.rs:439-575; src/admission.rs:788-821; src/inspect.rs:604-622.
- Keep package relationships within package data and avoid automatic external relationship fetching or executing document macros; parsing/rendering must not acquire arbitrary filesystem/network authority from relationship strings: src/admission.rs:13-22; src/opc/mod.rs:555-563; src/convert/mod.rs:21283-21319; SECURITY.md:72-80.
- Ensure checked XML entrypoints validate before DOM construction, preserving the documented caller obligation for unchecked permissive APIs: src/xmllinq/parse.rs:84-135.
- Bind edit plans to intended source where required; resolve all operations and check candidate integrity before producing publishable bytes; separate dry-run document publication from apply: src/edit/prepared.rs:196-235; src/edit/v2_apply.rs:84-98; src/bin/jubarte/edit_typed.rs:263-288; src/bin/jubarte/edit_typed.rs:605-611.
- Confine MCP document reads and artifact writes to held root capability despite path changes, reject unsafe export names and output symlinks, and require explicit overwrite: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/publication.rs:146-199; src/publication.rs:228-255; src/publication.rs:448-463.
- Preserve existing native destinations on staging failures, verify staged bytes, install no-clobber outputs atomically, and accurately report partial commit/durability outcomes. Multi-file publication is not rollback: src/publication.rs:83-143; src/publication.rs:168-174; src/publication.rs:535-570.
- Restrict updater execution to explicit operator invocation and install intended platform member only after effective checksum/signature policy and file-type checks. Distinguish available signature support from configured trust keys: src/update.rs:102-125; src/update.rs:198-257; src/update.rs:274-285; src/update.rs:307-320.
- Keep release credentials confined to authorized publication workflows and bind release artifacts to intended versions/destinations. Signing precedes checksums; local ordinary-gate reuse must not skip security checks: .github/workflows/release.yml:40-49; .github/workflows/release.yml:252-308; .github/workflows/release.yml:317-322; scripts/release.sh:655-678.

- Updater extraction/replacement is delegated to self_update. Repository configuration and regular-file hook were inspected, not full dependency implementation. GitHub protections, signing-secret provisioning, registry permissions and deployed credential storage are external unknowns: src/update.rs:198-210; src/update.rs:307-320; .github/workflows/release.yml:261-285.
- Legacy DOC conversion uses a separate OLE/parser path and documented loss of unsupported content, not DOCX ZIP admission: src/legacy_doc.rs:13-50. Fidelity, privacy-removal completeness and all parser paths require separate coverage.
