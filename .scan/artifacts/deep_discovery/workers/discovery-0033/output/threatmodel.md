# Threat Model

Jubarte is an in-process Rust DOCX comparison, revision, editing and rendering engine exposed through a native CLI, PyO3 Python library/CLI, WebAssembly Node/browser bindings and an optional Python stdio MCP server. Inputs include untrusted OPC/ZIP/XML packages, legacy DOC, Markdown, edit-plan JSON, embedded images and fonts. The shared engine returns document/render/report bytes; host interfaces own file selection and publication. Normal document processing does not require a network service. Conditional privileged paths include self-update, registry/release publication and GitHub review/remediation workflows. This is a source-backed architecture map of the current repository, not completed security-audit coverage. Evidence: src/lib.rs:110-165; src/admission.rs:439-499; src/legacy_doc.rs:180-215; jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21; .github/workflows/release.yml:15-25.

## Assets

- Confidential document text, comments, revisions, metadata, media and rendered output. These reach CLI-selected files, MCP-root outputs and tool responses; MCP text/render/report responses can expose document contents to the connected client. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:185-217,229-255.
- Integrity of source documents, clean/redline results, edit anchors and source revisions. A plan's optional source_sha256 is checked against actual source bytes; schema and author are checked, and signed or macro-bearing edit sources are refused. Evidence: src/edit.rs:2073-2105.
- Availability of the host process parsing and rendering attacker-supplied ZIP/XML, DOC, images and fonts. Admission defaults are 64 MiB compressed/part, 256 MiB inflated, 10,000 entries and XML depth 256; comparison defaults are 512 MiB compressed/part and 2 GiB inflated with the same entry/depth limits. Render uses comparison admission. Evidence: src/admission.rs:63-99; src/document_comparer.rs:4922-4927; src/convert/mod.rs:769-778.
- Host filesystem authority, including documents, publication staging and rendering font state. MCP document I/O uses a held directory capability; render additionally reads host fonts and can maintain a per-user font index outside that document root. Evidence: src/publication.rs:146-199; src/convert/font.rs:2637-2652,3095-3106,3213-3229.
- Installed executable integrity and distributed Rust, Python, npm and CLI artifacts. Current self-update trusts GitHub release assets plus their same-release SHA256SUMS.txt; compiled signing keys are empty and FIRST_SIGNED_RELEASE is None. Evidence: src/update.rs:25-48,198-210,245-256.
- Release/review credentials and associated publication authority: Cargo credential references, npm session/OTP, UV_PUBLISH_TOKEN, GitHub release token, optional ZIPSIGN_PRIVATE_KEY and JULES_API_KEY. Secret contents were not inspected. Evidence: scripts/release.sh:374-388,919-954,1069; .github/workflows/release.yml:261-285,356-369; .github/workflows/jules-review.yml:28-39.

## Trust Boundaries

- Document supplier -> shared parsing engine: package bytes cross into OPC/ZIP/XML structures. admit prechecks budgets, checks archive defects, safe part names, duplicate identities and encryption before processing. Checked XML APIs validate before DOM construction, while raw parse_xdocument deliberately does not enforce policy. Evidence: src/admission.rs:439-499; src/opc/archive.rs:34-51; src/xmllinq/parse.rs:90-135.
- Caller policy -> resource budgets: WmlDocument construction and rendering admit under comparison limits; Markdown reading uses MarkdownOptions.input_limits, defaulting to the smaller default budget, and intentionally tolerates some malformed auxiliary XML. These entry points must not be modeled as identical admission contracts. Evidence: src/wml_document.rs:20-58; src/convert/mod.rs:769-778; src/markdown/mod.rs:302-308,342-345,647-677.
- Edit-plan author -> document mutation: optional source hash and explicit schema bind a plan to a source, while preparation resolves and validates edits before returning in-memory results. The caller decides whether and where to publish; the engine does not itself provide an authenticated approval identity. Evidence: src/edit.rs:1727-1749,1760-1761,1785-1814,2073-2105.
- Native CLI operator -> ambient output paths: publish_paths grants access to caller-selected local parent directories. It holds parent handles, stages under a UUID .jubarte-*.partial directory, verifies bytes, then renames for overwrite or uses an atomic no-clobber hard link. Publication is atomic per file, not across a set; errors identify committed files. Directory durability sync is a no-op on Windows. Evidence: src/bin/jubarte.rs:261-273; src/publication.rs:83-143,203-225,387-405,421-505,545-570.
- Python CLI and Node CLI operator -> ambient filesystem: these wrappers read and write selected paths using their host filesystem APIs. Existing-output checks are distinct from the native capability/staged publication implementation. Evidence: jubarte-python/python/jubarte_redlines/__main__.py:101-130; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-79,106-110.
- MCP client -> document filesystem: startup resolves --root, default cwd, and opens _OutputRoot once. Lexical paths undergo containment diagnostics; actual reads and publication are capability-relative. Outputs reject unsafe portable names and output symlinks; overwrite defaults false. MCP tool hints describe operations but are not separate caller authorization. All clients of one server share its root authority. Transport is stdio, not an independently exposed HTTP listener. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,374-381; jubarte-python/src/lib.rs:1245-1276; src/publication.rs:146-199,228-273,448-463.
- Gemini host -> MCP startup grant: gemini-extension.json launches uvx with jubarte-redlines[mcp], jubarte-mcp and --root ${workspacePath}. Thus its document capability is the host-provided workspace, rather than an unrelated fixed sandbox. Package resolution and Gemini's surrounding permissions are external controls. Evidence: gemini-extension.json:5-11.
- Markdown author -> native image loader: effective root is explicit --resource-path or the Markdown input's parent, with '.' fallback. Percent-decoded image targets are checked for URL schemes and containment; a held OutputRoot performs the actual read. Rust library callers may supply their own ImageLoader; its default is absent, so the library's callback authority is caller-owned. Python markdown_to_docx supplies no loader and reads no image files. Evidence: src/bin/jubarte.rs:2811-2878,2936-2943; src/markdown/mod.rs:159-170; jubarte-python/src/lib.rs:1194-1218.
- Document font requests -> native rendering host resources: renderer calls add_installed_faces; family discovery reads system/Word/user fonts and uses FONT_INDEX. User fonts resolve through JUBARTE_FONT_DIR or platform per-user data paths. Default index is font-index.tsv in the parent of that fonts directory; JUBARTE_FONT_INDEX explicitly overrides it, while empty/off disables it. Index writes use a PID-suffixed temporary file and rename under ambient OS permissions, not the MCP OutputRoot. Cloud font family construction restricts document names to one normal path component. Evidence: src/convert/mod.rs:848-857; src/convert/font.rs:2225-2235,2258-2275,2637-2652,2855-2862,3095-3106,3154-3169,3213-3229,3395-3424.
- Operator-requested update -> executable replacement: only self-update enters updater configuration. Noninteractive install requires --yes, --check performs lookup without installation, requested versions can downgrade, and selected assets belong to jandira-tech/jubarte-redlines with platform-specific archive paths. Installer receives checksum verification and a regular-file verification hook; signatures are conditional and currently disabled by empty compiled keys. Dependency-owned extraction, token lookup, HTTPS redirect behavior and executable swap require separate verification. Evidence: src/update.rs:25-48,91-108,120-125,144-160,186-257,307-320.
- Maintainer/tag authority -> release/public registry authority: v* tags trigger CI builds; tag version must match Cargo.toml. Build jobs read repository contents, while release job receives contents:write and publishes dist/* to the current GitHub repository. Optional signing secret reaches the signing step, is decoded under RUNNER_TEMP/zipsign.XXXXXX/keyN, and is removed by a trap. Local release.sh separately consumes registry credentials and invokes an external app checkout selected by JUBARTE_APP_DIR or jubarte-app. Evidence: .github/workflows/release.yml:15-25,40-49,230-239,261-310,356-369; scripts/release.sh:374-389,919-954,1069,1112-1113.
- Repository contributor/reviewer -> external review/remediation automation: Jules review runs only for same-repository, non-Dependabot PRs, grants PR/check writes and sends key/token references to a pinned external action without local checkout. The companion workflow additionally checks out the exact PR head, grants PR/issues write, and gates session creation to trusted author/dispatcher arthrod. Its external action receives JULES_API_KEY, starting_branch, AUTO_CREATE_PR and require_plan_approval:false. The external action implementation and Jules account authority are absent from inspected repository source. Evidence: .github/workflows/jules-review.yml:19-41; .github/workflows/jules-el-conejo-review.yml:35-54,64-92,258-272,320-324.
- Benchmark harness -> developer worker: jubarte-rust-inproc accepts COMPARE commands over stdin and performs ambient reads and writes of protocol-supplied paths. It is explicitly a speed-harness worker, not evidence of a remotely available service or a sandboxed tool. Evidence: jubarte-rust-inproc/src/main.rs:5-20,29-68,91-98.

## Attacker Capabilities

- A document supplier can control package structure, XML, relationships, embedded media/fonts and legacy DOC data delivered to public parsing APIs, without already controlling the host filesystem or environment. Meaningful failures could affect host availability or integrity; no particular deployed shared service is established. Evidence: SECURITY.md:38-40; src/admission.rs:439-499.
- An MCP caller can request reads, edits, renders, compares and revision resolution within the root granted by the launching host, including replacement only when overwrite is requested. Document contents returned by authorized reads are expected tool capabilities. Root escape would be additional authority; access inside the granted root is not itself a boundary bypass. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:38-55,67-108,152-217,220-255.
- A Markdown author can select resource names processed by a native loader but does not thereby select its trusted root. A library integrator controls callback behavior and must provide its own confinement if enabling ImageLoader. Evidence: src/bin/jubarte.rs:2811-2878,2936-2943; src/markdown/mod.rs:159-170.
- A lower-trust local writer might control a shared destination directory or cache only if deployment permissions permit it. Such access, environment control and secret access cannot be assumed from document submission. Capability publication and ordinary ambient wrappers have different controls. Evidence: src/publication.rs:146-199,448-505,558-569; jubarte-python/python/jubarte_redlines/__main__.py:126-130.
- Repository contributors can supply PR code and text under workflow event restrictions; they do not automatically possess maintainer secrets, tag creation, registry accounts or Jules trusted-user status. External review actions have their own granted capabilities and must not be conflated with release-token authority. Evidence: .github/workflows/jules-review.yml:19-39; .github/workflows/jules-el-conejo-review.yml:35-54,258-272; .github/workflows/release.yml:230-239.

## Security Objectives

- Reject malformed or resource-excessive untrusted inputs at the appropriate public boundary and preserve configurable limit semantics. Default bounds do not replace process memory/CPU controls. Evidence: src/admission.rs:63-99,439-499; src/xmllinq/parse.rs:119-135; SECURITY.md:71-74.
- Preserve source/plan binding where requested and refuse ambiguous or invalid mutations before publication. Source SHA-256 is an integrity guard, not user authentication or document ownership. Evidence: src/edit.rs:1739-1759,1785-1814,2073-2105; SECURITY.md:78-85.
- Keep MCP document reads and writes inside the launch-granted root despite symlink changes, enforce portable export names, and require overwrite for existing outputs. Keep independently ambient font discovery/cache authority explicit. Evidence: src/publication.rs:146-199,228-273,431-463; jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/convert/font.rs:3095-3106,3213-3229.
- Stage and verify native outputs before per-file commit, preserve old outputs on staging failure, report partial commits honestly and avoid claiming a cross-file rollback transaction or Windows directory fsync. Evidence: src/publication.rs:83-143,168-174,387-405,545-570.
- Prevent document-controlled Markdown image targets from fetching URLs or reading outside the configured resource capability; do not claim this constrains integrator-supplied callbacks. Evidence: src/bin/jubarte.rs:2811-2878; src/markdown/mod.rs:159-170.
- Bind updater installation to operator choice, target repository/platform/version and checksum verification, and distinguish current checksum-only trust from future cryptographic signing. Evidence: src/update.rs:25-48,91-108,186-257; docs/SELF_UPDATE.md:57-80.
- Keep publication credentials scoped to their consumers and preserve artifact provenance/version checks. Treat review/remediation automation, registry publication and app deployment as independent grants. Evidence: .github/workflows/release.yml:40-49,230-239,261-310,356-369; scripts/release.sh:374-389,919-954,1069,1112-1113.

## Assumptions

- No user deployment context, authoritative knowledge base or preexisting threat model was supplied. No remote listener, tenants, container mounts or externally deployed shared service was established. This review used offline source inspection only; no application execution or audit-completion claim is made.
- MCP documentation says tools 'only touch files under root' at jubarte-python/python/jubarte_redlines/mcp_server.py:67-68, and document argument I/O is capability-confined at :72-108. However docx_render invokes native rendering at :234-236, whose font discovery/cache performs ambient host I/O at src/convert/mod.rs:857 and src/convert/font.rs:2637-2652,3095-3106,3213-3229. The broad claim therefore needs a font/cache qualification. This observation alone establishes neither arbitrary file access nor an exploitable attacker.
- SELF_UPDATE documentation explicitly describes staged signing and checksum-only operation until keys are committed, matching current RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None. Signature support must not be reported as active authentication. Evidence: docs/SELF_UPDATE.md:57-80; src/update.rs:44-48,245-249.
- SELF_UPDATE documentation claims GH_TOKEN/GITHUB_TOKEN lift lookup limits, but the inspected wrapper does not explicitly consume those variables. Exact dependency-owned environment precedence, recipients, redirect policy, archive extraction and executable replacement remain unverified here. Evidence: docs/SELF_UPDATE.md:22-24; src/update.rs:198-218.
- Native publication comments explicitly limit atomicity to each file and expose partial commit/durability status. Python/Node wrapper parity comments describe command behavior, but their actual writers are direct host writes; native staged-publication guarantees must not be transferred to them. Evidence: src/publication.rs:5-7,123-130; jubarte-wasm/cli/bin/jubarte-redlines.mjs:6-8,106-110; jubarte-python/python/jubarte_redlines/__main__.py:126-130.
- Font directory/cache effective paths below are deterministic configuration formulas, not observed machine environment values. For example, setting JUBARTE_FONT_DIR=/srv/fonts makes the default index /srv/font-index.tsv, because the consumer joins the parent of the fonts directory. An explicit JUBARTE_FONT_INDEX replaces that location. Evidence: src/convert/font.rs:2637-2652,3100-3106.
- Root SECURITY.md identifies raw permissive XML parsing and requires callers to use checked APIs or prior admission for untrusted data. Checked versus unchecked parsing is an intentional public API distinction, not proof every caller has been audited. Evidence: SECURITY.md:53-59; src/xmllinq/parse.rs:90-135.
- Release.sh delegates app deployment to an external, untracked checkout. Its selected entrypoint and supplied arguments are known, but app secrets, account, destinations, approval logic and deployment readback are absent from the authorized inspected source. Evidence: scripts/release.sh:382-389,1112-1113.
- Pinned external Jules actions and platform permission enforcement were not fetched or executed. Their repository workflow grants are established; their internal prompt/data handling and account capabilities remain unresolved. Evidence: .github/workflows/jules-review.yml:28-41; .github/workflows/jules-el-conejo-review.yml:258-272,320-324.
- Browser/WebAssembly hosts control module loading, input selection and output handling. The npm CLI explicitly performs Node host I/O; native filesystem guarantees cannot be inferred from sharing Rust parser code. Bundled WASM implementation and all generated glue imports were not exhaustively reviewed. Evidence: jubarte-wasm/Cargo.toml:18-32; jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21,52-79,106-110.
- Validation reconciliation: byte/XML budget presence is not a blanket no-DoS guarantee. Confirmed findings identify semantic count expansion, namespace storage amplification, relationship algorithmic cost and consumers that parse XML before or outside admission. Native/MCP document-root confinement remains distinct from conditional ambient CLI/cache writes.
- Final Standard reconciliation retained 17 source-validated instances (12 medium, 5 low) plus rejected hypotheses, explicit exclusions and incomplete review work. Source completeness is partial; the architecture model does not assert that every file, dependency or downstream action was audited.
