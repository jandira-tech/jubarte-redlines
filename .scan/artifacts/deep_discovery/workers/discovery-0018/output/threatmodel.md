# Threat Model

Jubarte is a Rust DOCX comparison, inspection, editing, validation, scrubbing, Markdown and PDF/PNG conversion engine, exposed through a native CLI, PyO3 Python library/CLI, wasm-bindgen Node/browser APIs and npm CLI, and an optional Python MCP stdio server. Document bytes pass through ZIP/OPC/XML processing into in-memory transformations and returned artifacts; host adapters separately own filesystem authority. The library forbids unsafe Rust in its own code (src/lib.rs:7-30,85-86,96-165). Native publication and MCP use Rust directory capabilities; Python/npm CLI output implementations remain separate. The explicitly invoked native self-update command contacts GitHub and replaces the installed executable. Maintainer release tooling publishes to GitHub and package registries and invokes an external app checkout whose implementation is outside inspected source (src/update.rs:186-257; scripts/release.sh:82-106,385-388). This is source-backed architecture mapping, not completed audit coverage.

## Assets

- Confidential input documents, their text, revisions, comments, metadata, embedded media and fonts; clean/redline DOCX, Markdown patches, reports, PDFs and PNG outputs (src/lib.rs:17-29; jubarte-python/python/jubarte_redlines/mcp_server.py:161-168,185-217).
- Host files writable by ambient local CLI authority; separately, documents and outputs beneath the MCP server's directory capability. MCP --root defaults to cwd and is resolved/opened once (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,374-381; src/publication.rs:149-199,203-225).
- Native font files and persistent font-index state. Default font directories are ~/Library/Application Support/jubarte/fonts on macOS, ${XDG_DATA_HOME:-$HOME/.local/share}/jubarte/fonts on other non-Windows platforms, and %APPDATA%\jubarte\fonts on Windows, overridden by nonempty JUBARTE_FONT_DIR. The index defaults to the font directory's parent/font-index.tsv, not its fonts child; JUBARTE_FONT_INDEX overrides or disables it, and index saves use a PID-named temporary sibling (src/convert/font.rs:2633-2652,3095-3106,3183-3229).
- Integrity of edit source snapshots and exact published bytes. Legacy plan source_sha256 is optional and checked only when supplied; publication stages and reads back bytes before commit, but multi-file sets have separate commit points (src/edit.rs:2081-2089; src/publication.rs:168-174,533-570).
- Process availability and memory/CPU resources across ZIP/XML, document comparison, legacy DOC, font/image parsing and rendering. Default admission allows 64 MiB compressed/per-part and 256 MiB inflated, while compare allows 512 MiB compressed/per-part and 2 GiB inflated; both allow 10,000 entries and XML depth 256 (src/admission.rs:63-99).
- Installed jubarte executable and release authenticity. Updater selects jandira-tech/jubarte-redlines and SHA256SUMS.txt; currently RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None, so signature verification is not active (src/update.rs:25-48,198-210,245-257).
- Maintainer GitHub/package-registry credentials and optional release signing key. GitHub Actions release job has contents:write, signing secret is passed to the signing step, decoded into $RUNNER_TEMP/zipsign.*/keyN, and cleaned by a trap; local release tooling uses cargo/npm/uv/gh credentials (.github/workflows/release.yml:230-239,261-309,356-369; scripts/release.sh:101-106,919-956,1069).

## Trust Boundaries

- Untrusted DOCX supplier -> ZIP/OPC/XML engine -> in-memory parts/DOM. Admission enforces compressed/entry/inflation/XML budgets, duplicate identities and ZIP consistency before use; admitted main parts are checked even when their filename lacks an XML extension. PartFs::open separately defaults to compare budgets rather than InputLimits::default (src/admission.rs:439-470,473-513,516-569; src/opc/mod.rs:488-524). Checked XML APIs enforce policy; infallible parse_xdocument is not that gate (src/xmllinq/parse.rs:91-134).
- Caller-provided Markdown and edit plans -> document construction and edits. Exact anchor resolution and optional SHA-256 source checking protect document intent, but caller-selected author/plan/source are not authenticated identities. Legacy source_sha256 is optional (src/lib.rs:51-64; src/edit.rs:2073-2094). Legacy binary DOC import is a distinct parser path and intentionally omits pictures, macros and many ancillary stories; encryption/obfuscation is refused (src/legacy_doc.rs:13-50).
- Native Markdown image names -> host image files. --resource-path overrides the Markdown parent's directory (or cwd). URL schemes are refused after percent decoding; canonical containment plus a held OutputRoot capability confines the actual read to that resource root. This capability is independent of ambient CLI output authority (src/bin/jubarte.rs:2811-2870,2936-2943).
- Local native CLI operator -> ambient document/output paths. publish_paths grants ambient access to explicitly chosen output parents. Per-file exclusive staging, byte readback and rename/hard-link install enforce replacement/no-clobber semantics; errors preserve committed-path/durability state. This is not a hosted-root sandbox (src/publication.rs:203-225,419-470,480-505,533-570).
- Python/npm CLI operator -> ambient host files through adapter-owned I/O. Python _write directly calls Path.write_bytes and npm write directly calls fs.writeFileSync; their plan recorders use predictable PID partial siblings followed by replace/rename. Native publisher guarantees must not be attributed to these independent implementations (jubarte-python/python/jubarte_redlines/__main__.py:126-133,403-414; jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111,408-426,539-552).
- MCP stdio client -> shared root-granted read/edit/render tools -> native _OutputRoot. Python resolved-path checks provide diagnostics; actual document reads/writes delegate to Rust held-directory capability. Writes default to overwrite=false; names are validated, output symlinks refused and no-clobber installs use hard links. Tool annotations are hints, not separate read/write authorization. The configured client can call all registered tools; no tenant/session isolation was established (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,126-168,374-381; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:161-199,448-463,563-569).
- Native renderer -> ambient installed font files and persistent index. Document family names influence font selection; cloud-family directory names must be a single normal path component. Font-index entries contain filesystem paths/stamps and are loaded/read/saved outside the MCP document capability using ambient std::fs. MCP --root therefore constrains adapter document I/O, not every renderer resource (src/convert/font.rs:2225-2236,2258-2315,2637-2652,3095-3106,3155-3169,3183-3229). Browser/WASM host filesystem publication is compiled out (Cargo.toml:150-158; src/lib.rs:163-165).
- Explicit updater invocation -> GitHub release assets -> replacement executable. Preflight refuses noninteractive installation without --yes; --check does not install; normal selection only upgrades, while --version permits explicit downgrades. The updater configures SHA-256 verification and a regular-file extraction hook; trusted signing keys are presently absent. GitHub release asset control is therefore an authenticity prerequisite, not an input-document capability (src/update.rs:120-125,144-160,186-257,307-320).
- Tag-pushing maintainer -> GitHub Actions build/release and registry publication. v* triggers build jobs with contents:read; release job gains contents:write and publishes resulting dist artifacts. Local release script separately requires version confirmation unless --yes, calls mandatory security checks even with --skip-gates, publishes registries and invokes a separately configured app release script. External GitHub settings, registry permissions and external app deployment controls are not established by this repository (.github/workflows/release.yml:15-25,51-89,230-239,261-309,356-369; scripts/release.sh:385-388,655-656,875-895,919-956,1069).
- Parent source validation established that auxiliary relationship-routed XML can evade filename-selected admission and reach unchecked DOMs in converter/comparer/edit consumers (src/admission.rs:533-569; src/convert/font_table.rs:66-78; src/document_comparer.rs:4685-4752,4869-4880; src/edit.rs:2154-2158,5552-5563). Physical ZIP limits also do not budget semantic spans, repeated chunk expansion, logical legacy stories or quadratic metadata/field work. These are retained findings; checked consumers at src/inspect.rs:795-807, src/comments.rs:457-468 and src/edit.rs:1436-1443 remain effective at their call sites.

## Attacker Capabilities

- A document supplier can provide malformed ZIP/OPC/XML, embedded images/fonts, relationships, Markdown and supported legacy DOC bytes to a caller that chooses to process them. This establishes parser/resource boundaries without implying an exposed network service (src/admission.rs:439-569; src/legacy_doc.rs:13-50; src/lib.rs:17-30).
- A Markdown supplier controls image target strings, but does not thereby choose --resource-path or acquire access outside the caller-granted image root. Actual reads retain capability confinement after canonicalization (src/bin/jubarte.rs:2815-2870,2937-2943).
- An MCP client can choose tool arguments, root-relative document/output names, plans and overwrite=true within the operator-granted root. The client does not choose the server startup root through tool arguments; transport is stdio, and remote HTTP exposure or multiple tenants would require additional deployment code (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,153-168,374-381).
- A concurrent local filesystem writer may race destination checks or mutate filesystem names where its existing OS permissions allow. Such access is a separate prerequisite; shared-user authority does not itself establish privilege escalation. Native publisher uses exclusive staging, directory handles and atomic no-clobber linking, whereas Python/npm CLI I/O must be assessed independently (src/publication.rs:419-505,558-569; jubarte-python/python/jubarte_redlines/__main__.py:403-414; jubarte-wasm/cli/bin/jubarte-redlines.mjs:408-426).
- A release-asset attacker would need GitHub release publication authority or compromise of that infrastructure to influence updater bytes and same-channel checksums. Ordinary document control supplies neither release authority nor local invocation of self-update. Installed signing keys are currently absent (src/update.rs:25-48,198-210,245-257).
- A code contributor is not assumed to possess tag push, signing-key, registry or external app deployment authority. Those conditional workflows become relevant only where actual repository/CI/account permissions admit the contributor's code (.github/workflows/release.yml:15-21,230-239,261-309,356-369; scripts/release.sh:101-106,385-388).

## Security Objectives

- Treat document contents, archive names, XML, embedded media/fonts and relationships as data: retain bounded package processing and no document-driven host extraction or network fetching; checked XML policy must precede untrusted DOM construction. Process memory/CPU confinement remains a host obligation (src/admission.rs:516-569; src/xmllinq/parse.rs:91-134; SECURITY.md).
- Keep MCP document reads and output publication inside the operator-granted held directory, including symlink races; preserve overwrite=false against concurrent destination creation. Root-level authority is not a per-tool, per-file or per-tenant authorization system (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/publication.rs:149-199,419-463,563-569).
- Keep Markdown image reads inside the caller-granted resource directory and refuse URL fetching; do not conflate this independently enforced input capability with CLI output authority (src/bin/jubarte.rs:2815-2870,2937-2943).
- Bind guarded edits to exact source bytes when a source hash is requested, fail invalid plans before publication, and report actual publication state. Do not imply that optional legacy source hashes are mandatory or that multi-file commits are globally atomic (src/edit.rs:2073-2094; src/publication.rs:168-174; docs/FILESYSTEM_PUBLICATION.md:40-58).
- Protect installed executable integrity with explicit updater invocation, HTTPS transport, matching release checksums and regular-file extraction verification. Describe the current checksum-only trust model accurately until keys and FIRST_SIGNED_RELEASE activate signature enforcement (Cargo.toml:137-148; src/update.rs:25-48,120-125,198-210,245-257,307-320).
- Limit release credentials to their publishing/signing consumers, bind version/tag/artifacts and retain mandatory security checks. Registry and external app authority must remain separate from untrusted document processing (.github/workflows/release.yml:31-49,230-239,261-309,356-369; scripts/release.sh:655-656,875-895,919-956,1069).
- Treat all redaction artifacts as confidentiality outputs, including JSON/JSONL/MCP reports and preserved DrawingML parts. Parent validation found report contexts and split DrawingML text violate the documented removal guarantee (src/edit.rs:626-630,2515,2695-2751,2934-2939,4727-4735; src/scrub.rs:556-567).
