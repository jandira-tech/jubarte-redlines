# Threat Model

Jubarte is an in-process Rust document engine exposed through a native CLI, PyO3 Python package and CLI, wasm-bindgen browser/Node APIs, an npm CLI, and a Python stdio MCP server. Document bytes pass through package admission, OPC/XML parsing, comparison/editing/rendering, then return as bytes or are published by the host adapter. Native rendering additionally reads installed fonts and persists a font index. Self-update and maintainer publication are separate privileged workflows. Sources: src/lib.rs:7-35, src/lib.rs:96-165, jubarte-python/pyproject.toml:43-49, jubarte-python/python/jubarte_redlines/mcp_server.py:373-381, jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21.

## Assets

- Confidential document text, revisions, comments, metadata, embedded media and generated DOCX/PDF/PNG/report artifacts; these are returned to the invoking caller or written to its selected destinations (src/lib.rs:17-29; jubarte-python/python/jubarte_redlines/mcp_server.py:195-217).
- Host filesystem authority: native CLI and ordinary Python/npm adapters possess ambient process access; the MCP document I/O capability is an opened root directory (src/publication.rs:146-165,203-225; jubarte-python/python/jubarte_redlines/__main__.py:126-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111).
- Process availability and memory across Rust, Python and WASM consumers. Default admission allows 64 MiB compressed/per part, 256 MiB total inflated, 10,000 entries and depth 256; comparison allows 512 MiB compressed/per part and 2 GiB total, with the same entry/depth limits (src/admission.rs:63-100).
- Installed executable integrity, release archives/checksums and conditional signing authority (src/update.rs:25-48,198-257; .github/workflows/release.yml:261-309).
- Native font files and persistent font-index.tsv, including cached font paths and temporary index files. Their authority follows host environment and filesystem permissions, independently of the MCP document root (src/convert/font.rs:2637-2652,3095-3107,3156-3165,3213-3229).
- Maintainer GitHub release token, conditional ZIPSIGN_PRIVATE_KEY, registry publication credentials and package integrity (.github/workflows/release.yml:234-235,261-309,356-369; scripts/release.sh:919-959,1063-1069).

## Trust Boundaries

- Untrusted DOCX -> admission -> OPC/XML: admission checks pre-index budgets, duplicate decoded/case-folded part names, ZIP structural defects, safe names, bounded inflation and XML policy; it does not extract entries to disk (src/admission.rs:439-490,522-575,736-760,788-803). The shared checked ZIP opener applies structural defects independently of higher-level admission (src/opc/archive.rs:34-51).
- Raw XML library caller -> DOM: try_parse_xdocument_with_limits validates before constructing a DOM; infallible parse_xdocument deliberately skips policy and requires caller validation. Attribute defaults are 1,024 attributes, 1,024-byte names, 64 MiB values and 128 MiB complete start tags (src/xmllinq/parse.rs:48-57,90-135). Low-level APIs must not inherit guarantees of higher-level admitted entrypoints merely by association.
- Caller edit plan -> source snapshot -> candidate: v1 source_sha256 is optional, verified when supplied; every operation resolves against the untouched source, and preview/application share preparation. The native CLI additionally rereads and hashes the named source before first publication and checks output aliases/collisions (src/edit.rs:5-24,97-106,2073-2094; src/bin/jubarte.rs:1642-1655,1764-1823). A hash is a freshness/integrity guard, not user authentication.
- Native CLI caller -> ambient output paths: publication opens and holds each parent, stages complete bytes in parent/.jubarte-<UUID>.partial/bytes, and commits per file. Existing files require overwrite/force. Set publication is not atomic; partial commits are reported. Ambient publication replaces a destination symlink itself instead of following its referent (src/publication.rs:168-174,203-225,421-514; src/bin/jubarte.rs:1764-1823).
- MCP stdio client -> document files: --root defaults to cwd, resolves once, and becomes native OutputRoot authority. Path canonicalization is an early diagnostic; actual reads/writes use root-relative cap-std operations. Output paths reject nonportable names and output symlinks, and overwrite defaults false. All tools share this root; read/write annotations are hints rather than separate caller authorization (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,373-381; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:146-199,228-245,431-462).
- Native Markdown -> local image loader: explicit --resource-path overrides the Markdown input's parent, defaulting to '.', and grants that directory's read capability. Percent-decoded URL schemes and resolved paths outside the canonical root are refused; reads use the opened root capability (src/bin/jubarte.rs:2811-2877,2936-2943). npm's adapter rejects resource_path (jubarte-wasm/cli/bin/jubarte-redlines.mjs:724-727).
- Native render -> font filesystem/cache: JUBARTE_FONT_DIR overrides user font locations; otherwise macOS uses HOME/Library/Application Support/jubarte/fonts, Linux uses XDG_DATA_HOME/jubarte/fonts or HOME/.local/share/jubarte/fonts, Windows uses APPDATA/jubarte/fonts. System/Word font directories and cached face paths are separate ambient reads. Font index precedence is JUBARTE_FONT_INDEX, with empty/off disabling persistence, otherwise parent(user_font_dir)/font-index.tsv. Saves use the index path with extension tsv.<pid>.tmp followed by rename. These operations are outside OutputRoot enforcement (src/convert/font.rs:2263-2275,2281-2315,2637-2652,2855-2862,3095-3107,3156-3165,3183-3189,3213-3229).
- Browser host -> WASM executable: default initialization fetches jubarte_wasm_bg.wasm beside the JavaScript module; the caller may supply another module/URL. This is a code-loading capability, distinct from document relationships. Browser/WASM byte APIs do not expose native publication; Python/npm host wrappers separately perform filesystem I/O (jubarte-wasm/npm/web/jubarte_wasm.js:2575-2594; src/lib.rs:163-165; Cargo.toml:150-153).
- Explicit self-update caller -> GitHub release -> installed executable: fixed repository jandira-tech/jubarte-redlines, platform archive and SHA256SUMS.txt; noninteractive installation requires --yes, while --check only looks up. Selected versions may downgrade. The binary inside the archive is jubarte-<version>-<target>/jubarte[.exe]; an extracted-binary lstat hook requires a regular file. Current RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None, so signatures are not enforced. Unix uses tar.gz and Windows zip; extraction/replacement are dependency-owned (src/update.rs:25-48,91-108,120-125,144-159,198-257,307-320; Cargo.toml:137-148).
- Maintainer publication -> public registries/release consumers: v* tag workflow builds binaries and wheels with read-only job permissions, then a distinct contents:write job publishes GitHub assets. ZIPSIGN_PRIVATE_KEY is exposed only to the signing step, decoded under RUNNER_TEMP/zipsign.XXXXXX/keyN and removed by an EXIT trap. Missing secrets are accepted only while no public keys are committed. Local release.sh separately publishes crates.io jubarte-redlines, npm jubarte-wasm and jubarte-redlines, and PyPI jubarte-redlines using operator credentials after a typed version confirmation unless skipped (.github/workflows/release.yml:15-21,51-89,230-309,356-369; scripts/release.sh:875-889,919-959,1063-1069).
- Developer tooling has separate ambient capabilities: jubarte-rust-inproc accepts COMPARE paths over stdin and directly reads/writes them; it is a benchmark worker, not a root-confined service. The evaluation harness launches configured agent argv in a run directory and new process session with captured stdout/stderr and a timeout; it does not establish an OS sandbox through these subprocess arguments (jubarte-rust-inproc/src/main.rs:5-20,29-68,91-99; eval/cli-v2-pilot/harness/exec.py:191-222,240-249).
- Validated audit qualifications: extension-selected admission misses relationship-selected auxiliary XML; ignored DOCTYPE events differ from permissive DOM declaration boundaries; Markdown drawing dependency graphs have no cycle check. These are retained as separate findings with source evidence, not safe-control assumptions (src/admission.rs:533-569,788-821; src/convert/mod.rs:3480-3497,20768-20795; src/xmllinq/parse.rs:539-546,660-663; src/markdown/from_docx/drawing.rs:1397-1408,1964-1974).
- Concrete MCP artifact consumers use <root>/<out> or <root>/<out_dir>/{clean.docx,redline.docx,patch.diff,report.json,redline.pdf,redline-page-NN.png}; rendering writes page-NN.png and render.pdf. Return recipients are the connected client and root filesystem readers, with OutputRoot publication and overwrite=false (jubarte-python/python/jubarte_redlines/mcp_server.py:195-255). Ordinary Python path.write_bytes and Node fs.writeFileSync remain ambient host-selected output operations (jubarte-python/python/jubarte_redlines/__main__.py:126-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111).
- Concrete ambient font resources: macOS scans /System/Library/Fonts[/Supplemental], /Library/Fonts[/Microsoft] and /Applications/Microsoft Word.app/Contents/Resources/DFonts; cloud families resolve beneath HOME/Library/Group Containers/UBF8T346G9.Office/FontCache/4/CloudFonts and require one normal path component. Windows system fonts derive from WINDIR else SystemRoot else C:\Windows, plus LOCALAPPDATA/Microsoft/Windows/Fonts (src/convert/font.rs:2228-2236,2281-2315,2855-2862). Font index overrides may be relative to process cwd; absent overrides derive parent(user_font_dir)/font-index.tsv, giving HOME/Library/Application Support/jubarte/font-index.tsv on macOS, XDG_DATA_HOME/jubarte/font-index.tsv or HOME/.local/share/jubarte/font-index.tsv on Linux, APPDATA/jubarte/font-index.tsv on Windows. Absent HOME/APPDATA can disable default paths; index empty/off disables persistence (src/convert/font.rs:2637-2652,3098-3107).
- Developer evaluation artifacts resolve to run_dir/stdout.txt, run_dir/stderr.txt and run_dir/task.output_path, and the configured executable inherits process authority. start_new_session and timeout/process-group termination are lifecycle controls, not filesystem/network authorization (eval/cli-v2-pilot/harness/exec.py:191-222,240-249).

## Attacker Capabilities

- A document producer can supply DOCX/legacy DOC/XML, embedded font/image bytes, relationship metadata, text, comments and formatting to an invoking host, without necessarily controlling its filesystem, environment, credentials or process limits (SECURITY.md:38-74; src/admission.rs:439-575).
- An MCP client can invoke the registered read and write tools and choose document-relative paths, output paths and overwrite values within the operator-granted root. The root is shared authority, not tenant separation or per-tool approval (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,152-160,258-277,373-381).
- A caller controlling library configuration can deliberately raise InputLimits, omit a v1 source hash, supply an image loader or choose a WASM initialization resource. Such authorized configuration control is not an attacker privilege gain by itself (src/admission.rs:103-144; src/edit.rs:103-106; jubarte-wasm/npm/web/jubarte_wasm.js:2575-2594).
- A release-asset attacker would need authority beyond ordinary document input. With the current empty signing key list, replacing both archive and adjacent checksum is outside SHA-256's authenticity protection; this limitation is documented (src/update.rs:44-48; docs/SELF_UPDATE.md:59-80).
- A local actor manipulating native font index/files, publication parents or deployment environment needs corresponding filesystem/environment access. Impact beyond that existing authority requires a separate victim invocation and privilege/readability difference; none is supplied here.

## Security Objectives

- Refuse malformed or over-budget packages before unbounded package inflation/DOM work; preserve active limits through higher-level consumers; use checked XML APIs for untrusted raw XML (src/admission.rs:439-575; src/xmllinq/parse.rs:119-135; SECURITY.md:54-74).
- Document-supplied relationships must not cause arbitrary host reads, network retrieval, macro execution or process execution. Native Markdown local-image access is an explicit, separately confined capability (src/admission.rs:13-22; src/bin/jubarte.rs:2811-2877).
- MCP document paths and publications remain under the opened operator root despite pathname replacement; output overwrite requires an explicit parameter (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/publication.rs:146-199,448-462).
- Apply the plan to its intended source, refuse stale supplied hashes and invalid anchors, and avoid publishing an incomplete staged candidate. Report partial commit/durability outcomes honestly (src/edit.rs:5-24,2073-2094; src/bin/jubarte.rs:1764-1823; src/publication.rs:168-174).
- Install only the explicitly selected platform/version through the self-update flow, verify checksums and regular-file extraction, and distinguish conditional signature support from currently enforced authenticity (src/update.rs:91-108,198-257,307-320).
- Keep document processing, browser code loading, native cache I/O, MCP file authority, developer subprocess authority and release publication privileges distinct; host process/OS controls remain necessary for resource and credential isolation (SECURITY.md:71-85).

## Assumptions

- No user deployment context, supplied inventory, supplied threat model or knowledge base was provided. This is a read-only architecture review of inspected repository source, not completed vulnerability-audit coverage or runtime verification.
- The library provides no user authentication, password storage, encryption or key agreement; no network-facing multi-tenant service or tenant isolation is established by this source (SECURITY.md:84-85). MCP is configured for stdio (jubarte-python/python/jubarte_redlines/mcp_server.py:381).
- Input budgets do not guarantee bounded CPU/memory for every transformation; host process limits are explicitly required. Native CLI/Python/npm adapters read complete source files before engine admission (SECURITY.md:71-74; src/bin/jubarte.rs:2740-2742; jubarte-python/python/jubarte_redlines/__main__.py:73-83; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-55).
- Documentation discrepancy retained: src/lib.rs:10-11 describes byte functions as using no temporary files, while native rendering can persist font-index.tsv through a tsv.<pid>.tmp file (src/convert/font.rs:3095-3107,3213-3229). The document package pipeline itself remains in memory.
- Documentation discrepancy retained: build_server claims tools only touch files under root (jubarte-python/python/jubarte_redlines/mcp_server.py:67-68), while native rendering can read ambient font files and write the independently configured font index outside that root (src/convert/font.rs:2281-2315,2637-2652,3095-3107,3156-3165,3213-3229). MCP document path arguments remain capability-confined; broader exploitability is not established.
- Documentation discrepancy retained: docs/SELF_UPDATE.md:22-24 says GH_TOKEN/GITHUB_TOKEN raise the API budget, but src/update.rs:198-210 configures neither auth_token nor auth_token_from_env. Offline installed self_update 1.3.1 dependency source has auth_token=None by default and an explicit opt-in environment setter; current integration therefore appears anonymous. Dependency anchors: self_update-1.3.1/src/backends/common.rs:1027-1053; self_update-1.3.1/src/backends/github.rs:391-406.
- Signing is explicitly staged rather than currently guaranteed: docs/SELF_UPDATE.md:69-80 agrees with RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None (src/update.rs:44-48). Any actual GitHub secret, deployed release signing status, repository branch/tag protection or registry account policy is unknown.
- Policy dependency wording is stale relative to source: SECURITY.md:89-94 names rdocx-opc 0.2/quick-xml 0.41, whereas Cargo.toml uses oxml-opc 0.14.2, quick-xml 0.42 and a separate quick-xml 0.41 alias. This disagreement does not establish an advisory regression; actual resolved dependency behavior needs audit-specific assessment.
- Debug is a deliberate unchecked ZIP triage exception, not evidence that normal admission accepts such archives (src/opc/archive.rs:15-19; SECURITY.md:131-136). Raw Relationships::from_xml and infallible DOM parsing have different contracts from admitted document processing (src/opc/mod.rs:45-51; src/xmllinq/parse.rs:90-135; SECURITY.md:92-95).
- Font/cache effective paths below are fully derived configuration expressions. No runtime environment, mounted directories, OS ACLs or deployed service account was supplied; a concrete host-specific absolute path cannot be asserted. Browser code origin/CSP and release dependency extraction internals are not fully reviewed.
