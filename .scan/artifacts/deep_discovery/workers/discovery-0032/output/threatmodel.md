# Threat Model

Jubarte is a local DOCX comparison, editing, inspection and rendering engine, exposed through a Rust library/native CLI, a PyO3 extension/Python facade and CLI, wasm-bindgen byte APIs/Node CLI, and an optional Python MCP server over stdio. Inputs include untrusted DOCX ZIP/XML/media, legacy DOC and Markdown; outputs include changed DOCX, text/JSON reports, PDF and PNG. High-level operations admit packages before opening/DOM processing, with distinct default and comparison budgets. Rendering additionally discovers native host fonts and maintains a persistent font index. The native CLI explicitly supports GitHub self-update, including release lookup, checksum verification, delegated extraction and replacement of the running executable. Release tooling separately holds package-registry, GitHub and optional archive-signing authority. These are distinct interfaces and controls, not a single sandbox. Evidence: src/lib.rs:7-35, src/lib.rs:147-165, src/admission.rs:63-100, jubarte-python/pyproject.toml:47-55, jubarte-python/python/jubarte_redlines/mcp_server.py:373-381, jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21, src/update.rs:186-257, .github/workflows/release.yml:230-269.

## Assets

- Confidential input documents, extracted text/comments/authors, edit plans, resulting document bytes, reports and rendered pages. MCP text/inspection tools return document-derived content to the attached client; output paths also identify local resources. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:131-150, jubarte-python/python/jubarte_redlines/mcp_server.py:185-218, jubarte-python/python/jubarte_redlines/mcp_server.py:234-255.
- Host process availability and memory/CPU, including the embedding Python interpreter and browser/WASM instance. Input admission is a resource gate rather than process isolation; supplied repository policy explicitly assigns residual CPU/memory isolation to hosts. Evidence: src/admission.rs:5-7, src/admission.rs:39-60, SECURITY.md:70-74.
- Filesystem objects accessible through operator-authorized CLI paths, and document files beneath the MCP server's granted directory capability. Preserve existing outputs unless replacement is authorized, confine MCP document I/O, and expose partial-publication state. Evidence: src/publication.rs:146-206, src/publication.rs:448-469, src/publication.rs:558-570.
- Native renderer font inputs and persistent font-index integrity. Fonts can originate from package embeddings, bundled catalogue faces, configured user font folders, system/Word fonts and Office cloud-font caches; the persistent index contains source paths/stamps used for subsequent file reads. Evidence: src/convert/mod.rs:806-807, src/convert/mod.rs:857-878, src/convert/font.rs:2258-2276, src/convert/font.rs:2281-2315, src/convert/font.rs:3154-3171.
- Installed native executable integrity and release distribution authority. The updater currently trusts HTTPS release metadata/assets and SHA256SUMS.txt without a compiled release-signing key. The optional signing secret, CI GitHub token and local registry credentials are privileged workflow assets, independent of document processing. ## Trust Boundaries

- Untrusted DOCX bytes -> admission -> OPC parts -> DOM/comparison/edit/rendering. InputLimits::default is 64 MiB compressed, 10,000 entries, 64 MiB per part, 256 MiB inflated total, XML depth 256. InputLimits::compare is 512 MiB compressed/per part and 2 GiB inflated total, with the same entry/depth limits. Both use defaults of 1,024 element attributes, 1,024 attribute-name bytes, 64 MiB raw/decoded attribute-value bytes and 128 MiB start-tag bytes. Overrides replace individual fields and reject unknown JSON keys. Evidence: src/admission.rs:63-164, src/xmllinq/parse.rs:48-57.
- Different consumers have different admission budgets: inspect/edit Opened uses defaults, WmlDocument uses compare limits, and PDF/PNG layout calls document_comparer::admit_package, which uses compare limits. Raw file reads occur before the engine sees the bytes. These limits must not be modeled as an OS-level cap or a streaming limit on wrapper file acquisition. Evidence: src/inspect.rs:604-620, src/wml_document.rs:50-56, src/convert/mod.rs:769-778, src/document_comparer.rs:4926-4927, src/bin/jubarte.rs:2740-2742, jubarte-python/python/jubarte_redlines/document.py:141-145, jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-55.
- ZIP container metadata -> package identity and decompression. Admission checks preindex budgets, dual-header/extent/special-entry defects, safe part names, case-insensitive duplicate identities, encryption and compression methods before bounded reads; inflated bytes are counted rather than trusting declared sizes. Normal archive opening also runs zip_defects. Debug has a deliberate unchecked opener for triage. Evidence: src/admission.rs:439-553, src/opc/archive.rs:15-51.
- Raw XML -> checked DOM construction versus explicitly permissive parsing. validate_xml_with_limits uses TagPolicy, enforces nesting/root structure and refuses DTD declarations and unsupported entities; public permissive parse_xdocument is not an admission boundary. OPC metadata has an independent 256-attribute cap. Evidence: src/xmllinq/parse.rs:918-958, src/opc/mod.rs:433-449, SECURITY.md:54-69.
- Untrusted edit-plan data -> document mutation. The legacy edit transaction checks schema, optional exact source SHA-256, nonempty author and package admission before applying changes; a supplied source hash mismatching current bytes returns STALE_SOURCE. This optional digest binds bytes, not user identity or authorization. Evidence: src/edit.rs:2072-2099.
- Native CLI -> ambient operator-authorized filesystem publication. publish_paths holds each chosen parent directory, stages bytes under that parent in .jubarte-<UUID>.partial/bytes, verifies length/content and installs by rename when overwrite is enabled or hard-link no-clobber otherwise. Unix staging directories use mode 0700. A group is atomic per file, not all-or-nothing, and errors record committed outputs and durability uncertainty. Evidence: src/publication.rs:83-143, src/publication.rs:203-220, src/publication.rs:420-505, src/publication.rs:535-570.
- Python and Node CLI wrappers -> ambient filesystem authority, independently of native publication. Python Document.read reads the caller path; Python CLI _write uses Path.write_bytes, while Node CLI read/write uses fs.readFileSync/fs.writeFileSync and a separate exists/force check. Do not transfer native staged-publication guarantees to these wrappers. Evidence: jubarte-python/python/jubarte_redlines/document.py:141-145, jubarte-python/python/jubarte_redlines/__main__.py:116-132, jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-79, jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-110.
- MCP client -> explicitly granted document-directory capability. Startup resolves --root, defaulting to startup cwd, then holds _OutputRoot(cap_std::fs::Dir). Requested input names undergo containment diagnostics and are actually read through the held root; writes use capability-relative publication. docx_edit's derived outputs are <root>/<out_dir>/clean.docx, redline.docx, patch.diff and report.json, optionally redline.pdf and redline-page-NN.png. docx_render derives page-NN.png and optional render.pdf. Overwrite defaults false. Tool annotations are metadata; access is shared by the attached stdio client rather than separate per-tool identities. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:54-108, jubarte-python/python/jubarte_redlines/mcp_server.py:153-217, jubarte-python/python/jubarte_redlines/mcp_server.py:220-255, jubarte-python/python/jubarte_redlines/mcp_server.py:373-381, jubarte-python/src/lib.rs:1244-1277, src/publication.rs:146-199.
- Native renderer -> user font folder, outside any MCP document root. Effective folder precedence is nonempty JUBARTE_FONT_DIR, otherwise macOS $HOME/Library/Application Support/jubarte/fonts; Linux nonempty $XDG_DATA_HOME/jubarte/fonts or $HOME/.local/share/jubarte/fonts; Windows $APPDATA/jubarte/fonts. The host process and OS permissions own this capability. Evidence: src/convert/font.rs:2633-2652.
- Native renderer -> persistent font index, separately from the font folder. JUBARTE_FONT_INDEX empty/off disables it; another value names the index directly. Otherwise parent(user_font_dir)/font-index.tsv yields macOS $HOME/Library/Application Support/jubarte/font-index.tsv, Linux $XDG_DATA_HOME/jubarte/font-index.tsv or $HOME/.local/share/jubarte/font-index.tsv, and Windows $APPDATA/jubarte/font-index.tsv. JUBARTE_FONT_DIR therefore also relocates the default index into its parent. IndexEntry::load checks directory/file stamps before reading cached face paths; save merges and writes <index-path with extension tsv.<pid>.tmp> then renames it. This uses ambient fs access rather than OutputRoot. Evidence: src/convert/font.rs:3095-3107, src/convert/font.rs:3154-3171, src/convert/font.rs:3182-3229.
- Native renderer -> installed/Office font sources, independently of user-font and index resources. Family discovery includes fixed macOS font/Word directories and Windows ($WINDIR or $SystemRoot or C:\Windows)/Fonts plus $LOCALAPPDATA/Microsoft/Windows/Fonts. Office cloud candidates derive from $HOME/Library/Group Containers/UBF8T346G9.Office/FontCache/4/CloudFonts/<family>; family is constrained to one normal path component. Evidence: src/convert/font.rs:2225-2235, src/convert/font.rs:2281-2315, src/convert/font.rs:2855-2862.
- Explicit native self-update -> GitHub metadata/assets -> installed executable. The fixed owner/repository is jandira-tech/jubarte-redlines; platform maps to macos/linux aarch64/x86_64 or windows-x86_64. Archive binary path is jubarte-<version>-<target>/jubarte[.exe]. The builder delegates checksum/extraction/swap to self_update 1.3.1, configures SHA256SUMS.txt and rejects extracted binaries that lstat as anything other than regular files. Interactive confirmation or --yes is required for installation; --check performs lookup only; explicit --version permits downgrade. RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None mean no signature is required now. Evidence: src/update.rs:25-48, src/update.rs:91-108, src/update.rs:120-125, src/update.rs:144-160, src/update.rs:186-257, src/update.rs:307-320, Cargo.toml:137-148.
- Tag/release maintainers -> release artifacts/signing/publication. CI builds five native targets, checks tag/version equality, and grants contents:write only to release publication. Optional ZIPSIGN_PRIVATE_KEY is injected only into Sign archives, decoded into $RUNNER_TEMP/zipsign.<random>/keyN, used to sign dist/jubarte-*.tar.gz or *.zip and deleted by trap. Committed public keys require signing and verify every signed archive; checksums follow signing. GH_TOKEN receives secrets.GITHUB_TOKEN for gh release create in the current github.repository, publishing dist/*. Evidence: .github/workflows/release.yml:15-49, .github/workflows/release.yml:58-74, .github/workflows/release.yml:230-307, .github/workflows/release.yml:317-322, .github/workflows/release.yml:356-369.
- Local maintainer release process -> independently authenticated package registries. scripts/release.sh requires main/origin alignment and clean state, then checks Cargo credential files or CARGO_REGISTRY_TOKEN, npm identity, gh authentication and UV_PUBLISH_TOKEN. cargo publish publishes the root crate; npm publish separately publishes jubarte-wasm/npm and jubarte-wasm/cli, optionally passing NPM_OTP; uv publish sends dist/pypi/* with UV_PUBLISH_TOKEN. The script additionally executes an external app checkout's release-engine.sh; that implementation is absent from this repository and its authority cannot be established here. Evidence: scripts/release.sh:360-388, scripts/release.sh:914-919, scripts/release.sh:928-959, scripts/release.sh:1059-1069.
- Developer-only benchmark worker -> ambient local paths. jubarte-rust-inproc is a long-lived stdin COMPARE worker, reading both requested paths and directly writing its output path. It is documented as a benchmark harness, not an authenticated hosted service. Evidence: jubarte-rust-inproc/src/main.rs:5-20, jubarte-rust-inproc/src/main.rs:29-68, jubarte-rust-inproc/src/main.rs:91-99.
- Post-admission document metadata -> generated output/layout resources. HTML colspan expands into grid XML (src/convert/altchunk.rs:469-491,562-567); ordinary WML spans/skips expand layout vectors (src/convert/mod.rs:13600-13619,14204-14223,14340-14353); numbering levels/counters drive separate loops/labels (src/convert/mod.rs:5518-5533,5610-5629,6015-6019). Original package budgets do not by themselves bound these generated resources. These scenarios are reconciled with separate reported controls and deferred full renderer review.
- Legacy DOC logical CP ranges -> character materialization. Public legacy read accepts FIB ccp_text and piece FC references (src/legacy_doc.rs:180-193,914-920,1084-1112), then produces StoryChar per logical character (src/legacy_doc.rs:1181-1225). Physical compound-file chain/offset checks do not impose a logical expansion budget. This boundary is reported separately from DOCX admission.
- Embedded font bytes -> PDF subsetting. Package font parsing and glyf-backed face selection (src/convert/font_table.rs:212-242,src/convert/font.rs:1480-1501) precede raw table preservation, sfnt arithmetic and cmap enumeration (src/convert/pdf.rs:1208-1220,1286-1313,1434-1449,1531-1536). The caller must bound work/output even for a dependency-accepted font. Duplicate-directory arithmetic and cmap enumeration are independently reported.
- Distinct local writer -> mutable wrapper publication names. Python and Node CLIs use preflight existence checks followed by truncating writes (jubarte-python/python/jubarte_redlines/__main__.py:101-133,jubarte-wasm/cli/bin/jubarte-redlines.mjs:76-112) and predictable non-exclusive plan staging (jubarte-python/python/jubarte_redlines/__main__.py:403-413,jubarte-wasm/cli/bin/jubarte-redlines.mjs:419-428). These conditional local boundaries differ from MCP/native held-handle publication and are reported separately.
- Permitted PR contribution -> self-hosted runner account/private network. CI checks out PR-controlled source and executes local actions/Cargo on self-hosted runners (.github/workflows/ci.yml:13-49); the configured mbx action documents a shared private cache network and persistent stores (.github/actions/mbx/action.yml:8-38). Docs, roundtrip and adoption expose sibling paths. Fork-run approval and actual runner isolation are external prerequisites; cache poisoning/root/release compromise are not established.

## Attacker Capabilities

- A document supplier can control document ZIP/XML structure, relationships, embedded fonts/images, text and metadata presented to an authorized CLI/library/MCP operation, without initially controlling the invoking account, environment, filesystem outside granted data, release infrastructure or package-registry identities. Evidence for recognized untrusted types: SECURITY.md:38-41.
- An authorized MCP client can request the registered read/edit/render/compare/accept/reject tools with file names and plan/options under the configured root, and can explicitly request overwrite. The source establishes stdio access and shared root authority; it does not establish public network exposure, multiple tenants or independent tool callers. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:38-55, jubarte-python/python/jubarte_redlines/mcp_server.py:67-108, jubarte-python/python/jubarte_redlines/mcp_server.py:373-381.
- Control of CLI paths or host environment by the same operating-system user is not itself a new privilege. A file-access or cache-impact story needs an additional lower-trust input-to-path transition, a distinct local writer, or a deployment that deliberately grants less authority to the requester than the host has.
- Control of GitHub release assets is separate from document input. With current checksum-only verification, archive and checksum integrity depend on release publication authority and transport. A claim of update compromise needs that authority or another demonstrated verification failure; it must not assume a document author can replace release assets. Evidence: src/update.rs:25-48, src/update.rs:198-210, docs/SELF_UPDATE.md:59-80.
- Native/WASM boundary failure could affect the embedding process or instance; memory/CPU denial-of-service scope depends on host process isolation and caller limits, which are not supplied deployment facts. Evidence: src/admission.rs:5-7, SECURITY.md:70-74.

## Security Objectives

- Apply each consumer's actual admission budget before package/DOM work; preserve bounded inflation, canonical part identity and ZIP consistency checks without treating them as proof against all CPU/memory exhaustion. Evidence: src/admission.rs:439-553, src/opc/archive.rs:34-51, SECURITY.md:70-74.
- Keep document relationship targets as package data and prevent unintended external fetching or macro execution during processing. This is the supplied repository policy objective; representative rendering resolves altChunk through package part bytes, but this architecture review is not exhaustive proof of every consumer. Evidence: SECURITY.md:70-74, src/convert/mod.rs:789-793.
- Use checked XML APIs for untrusted raw XML and preserve independent OPC metadata limits. Do not treat permissive DOM APIs as validating parsers. Evidence: SECURITY.md:54-69, src/xmllinq/parse.rs:918-958, src/opc/mod.rs:433-449.
- Confine MCP document reads/writes to the startup-granted directory using actual capability-relative operations, preserve no-clobber defaults and report partial publication/durability failures. Keep ambient renderer font/cache access explicitly separate from document-path confinement. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108, src/publication.rs:146-199, src/publication.rs:448-469, src/publication.rs:558-570, src/convert/font.rs:3095-3107.
- Bind guarded edit plans to the exact source snapshot and distinguish a content digest from authentication. Evidence: src/edit.rs:2081-2088, SECURITY.md:76-85.
- Perform self-update only on explicit invocation/authorization; select the intended repository, platform and version; verify downloaded checksums and extracted regular-file type, and require release signatures only when compiled policy actually enables them. Evidence: src/update.rs:25-48, src/update.rs:91-108, src/update.rs:186-257, src/update.rs:307-320.
- Keep release-signing secrets, GitHub release authority and separate registry credentials bound to their intended consumers; distinguish optional signing from current end-user signature enforcement. Evidence: .github/workflows/release.yml:261-307, .github/workflows/release.yml:356-369, scripts/release.sh:374-380, scripts/release.sh:928-959, scripts/release.sh:1069.

## Assumptions

- This is a focused source-backed architecture map, not completed security-audit coverage, runtime verification or findings. No application execution, network access, generated exploit inputs or source modification was performed. The parent should reconcile the observed current HEAD with the scan revision before using these anchors for another revision.
- No user deployment context or CODEX_SECURITY_KNOWLEDGE_BASE was supplied. Public service exposure, tenant boundaries, process limits, OS account separation, root ownership and CI secret provisioning remain deployment prerequisites rather than established facts.
- Documentation/configuration qualification: jubarte-python/python/jubarte_redlines/mcp_server.py:5-9 and :67-68 advertise that every path/tool touches only root. Document I/O does use OutputRoot, but native rendering additionally accesses configured/system font locations and parent(user_font_dir)/font-index.tsv through ambient filesystem APIs. Retain both the documented claim and the narrower implemented document-path boundary. Inspected cached self_update 1.3.1 source defaults auth_token=None and auth_token_from_env=false; therefore this consumer currently performs unauthenticated lookup despite those variables. - Current signature enforcement agrees with the staged-signing documentation: RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None; signature support compiled into a binary is not evidence that signatures are required. Remote release-secret state was not queried. Evidence: src/update.rs:44-48, docs/SELF_UPDATE.md:69-82, .github/workflows/release.yml:267-275.

Its installed dependency was partially inspected, but detailed extraction/redirect/transport and OS replacement controls are not fully mapped here. Windows ZIP and Unix tar extraction must remain distinct.
- Python and Node CLIs claim command/flag/output parity with the native CLI, but their direct write implementations do not establish native staged-publication parity. This is a control distinction rather than a validated vulnerability. Evidence: jubarte-python/python/jubarte_redlines/__main__.py:5-7, jubarte-python/python/jubarte_redlines/__main__.py:126-132, jubarte-wasm/cli/bin/jubarte-redlines.mjs:6-8, jubarte-wasm/cli/bin/jubarte-redlines.mjs:76-79, jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-110, src/publication.rs:83-143.
