# Threat Model

Jubarte is a Rust Word-document engine for comparison, tracked edits, revision resolution, inspection, validation, scrubbing, Markdown conversion and PDF/PNG rendering. Its normal interfaces are the native CLI, Rust byte APIs, PyO3 Python APIs/CLI, WASM byte APIs/Node CLI, and optional Python MCP stdio server. Rust/Python/WASM share the engine, while their host adapters own filesystem access (src/lib.rs:7-35; Cargo.toml:58-60,82-99,160-162; jubarte-python/Cargo.toml:35-39; jubarte-wasm/Cargo.toml:18-32; jubarte-python/pyproject.toml:42-49).
The MCP server grants every connected stdio caller document access beneath one operator-selected root, defaulting to the process working directory. Python diagnostics resolve paths; actual reads and publication use a native directory capability held open for the server lifetime. It exposes read and write tools rather than separate authenticated user roles (jubarte-python/python/jubarte_redlines/mcp_server.py:54-108,126-159,373-381; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:146-200).
DOCX flows through admission, strict-to-transitional translation, in-memory OPC parts and XML parsing before conversion. Rendering uses native font shaping, image decoding, PDF emission and tiny-skia rasterization rather than Word, LibreOffice or an external rasterizer. Legacy DOC has a distinct compound-file parser (src/convert/mod.rs:769-798; src/legacy_doc.rs:180-216; src/convert/raster.rs:5-19; Cargo.toml:104-125).
Privileged conditional surfaces include explicit native self-update, tag-driven GitHub releases, local registry publication, automated external Jules review/remediation, and repository code executed on self-hosted CI runners (src/update.rs:186-257; .github/workflows/release.yml:15-21,230-263,356-369; scripts/release.sh:919-969,1069-1070; .github/workflows/ci.yml:13-48; .github/workflows/jules-review.yml:18-50; .github/workflows/jules-el-conejo-review.yml:259-278).

## Assets

- Confidential input documents, their extracted text, revision/comment authors and dates, embedded media/fonts, and generated document/PDF/PNG/report bytes. MCP returns document text and inspection results to its connected client, so granting a root authorizes disclosure of readable documents within that root (jubarte-python/python/jubarte_redlines/mcp_server.py:84-108,131-150,194-218,245-255).
- Integrity and availability of caller-selected output files. MCP publication validates portable relative names, rejects existing destinations unless overwrite is authorized, stages bytes before publication, and reports partial commits; native ambient publication intentionally accepts operator-authorized local paths (src/publication.rs:83-143,175-225,228-273,431-505).
- Host memory, CPU and filesystem authority across CLI/Python/MCP deployments; browser/WASM heap availability; renderer font files and persistent font index. Admission and raster limits are finite product budgets rather than process isolation (src/admission.rs:39-99; src/convert/raster.rs:24-42; jubarte-wasm/src/lib.rs:80-85; SECURITY.md:71-74).
- Installed executable integrity and distribution provenance. Current updater trusts GitHub release assets and adjacent SHA256SUMS.txt; compiled release verification keys are empty. Conditional signing credentials, GitHub publishing authority, local registry credentials and Jules API credentials are separate authorities (src/update.rs:25-48,198-210,245-257; .github/workflows/release.yml:234-263,269-307,356-369; scripts/release.sh:374-380,934-955,1069; .github/workflows/jules-review.yml:35-50).
- Self-hosted runner accounts, private build-cache contents and network access are assets separate from GitHub token permissions. Repository CI invokes Cargo and local scripts on self-hosted runners and configures an unauthenticated HTTP cache endpoint; host isolation is not established by these files (.github/workflows/ci.yml:26-48,72-99,114-138; .github/workflows/docs.yml:76-99; .github/actions/mbx/action.yml:8-22).

## Trust Boundaries

- Untrusted document bytes cross into the engine. Admission checks pre-index budgets, duplicate identities, ZIP structural defects, safe part names, encryption/compression policy and declared entry sizes; public renderer entrypoints call compare-budget admission before normalization and parsing. A malicious document causing excessive allocations or computation is an availability scenario whose impact depends on host/process limits (src/admission.rs:439-512; src/convert/mod.rs:769-798; src/document_comparer.rs:4926-4927; SECURITY.md:71-74).
- MCP client-selected input and output paths cross into operator-granted directory authority. --root takes precedence over cwd, is expanded/resolved at startup and opened once. Actual reads use OutputRoot.read; writes pass relative paths to OutputRoot.publish. Lexical diagnostics are not the sole authorization control. ReadOnlyHint and other tool annotations describe behavior, while the root capability and overwrite flag enforce filesystem policy (jubarte-python/python/jubarte_redlines/mcp_server.py:54-108,373-381; jubarte-python/src/lib.rs:1252-1278; src/publication.rs:153-199,431-463).
- CLI path arguments grant ambient local authority, independently of MCP confinement. Native publication opens explicit destination parents; Python and Node CLIs directly read/write local paths. A user already authorized to invoke these CLIs with arbitrary paths does not gain new authority merely by selecting an arbitrary destination (src/publication.rs:203-225,431-445; jubarte-python/python/jubarte_redlines/__main__.py:73-88,126-130; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-73,106-110).
- Markdown image names are lower-trust than the operator-selected resource root. Native CLI --resource-path overrides the Markdown file's parent directory, or '.' for a bare filename. Image names are percent-decoded, URL schemes refused, canonicalized beneath that root and read through a held capability. Escape or URL-fetch scenarios must account for these controls (src/bin/jubarte.rs:2811-2848,2851-2878,2936-2943).
- Native rendering crosses beyond document-root authority into ambient font resources. JUBARTE_FONT_DIR overrides platform user-font defaults; JUBARTE_FONT_INDEX independently selects or disables the cache. Otherwise the index is the parent of the font directory plus font-index.tsv. Cached entries contain face paths which are stat-checked and read; cache writes use a PID-specific sibling temporary file and rename. These resources are not confined by MCP OutputRoot (src/convert/font.rs:2633-2652,3090-3107,3154-3172,3182-3229).
- Remote release metadata/assets cross into executable replacement only on explicit native self-update. Noninteractive installation requires --yes; --check stops before installation; a named version may downgrade. Target asset and internal binary path are derived from OS/architecture; extraction is delegated to self_update and a repository hook refuses a nonregular extracted binary. Current authenticity is checksum-only because no verification key is compiled (src/update.rs:87-108,120-125,144-161,186-257,307-320).
- Tag-authorized build products cross into public release distribution. Hosted build jobs have read access; the release job has contents:write, combines workflow artifacts, optionally signs archives before hashing and publishes dist/*. Signing secret material is scoped to the signing step, decoded under RUNNER_TEMP, and cleaned by a trap (.github/workflows/release.yml:15-21,51-75,153-158,230-307,317-322,356-369).
- Pull-request source crosses into self-hosted runner execution and remote cache access. CI and Docs trigger on pull_request, use self-hosted runners and execute checked-out build/scripts. The mbx configuration claims PRs only read the cache, but its enforcement belongs to the pinned external action/server rather than any inspected repository ACL (.github/workflows/ci.yml:13-48,72-99; .github/workflows/docs.yml:42-86,98-99; .github/actions/mbx/action.yml:8-22).
- External agent workflows receive PR context and repository/API authority. The basic Jules workflow excludes forks/Dependabot, provides Jules and GitHub tokens, grants PR/check write permissions, and explicitly disables approval. The companion-fix workflow resolves same-repository PRs and gates session creation on trusted author/dispatcher plus event conditions. External action behavior and actual service/account permissions were not available in inspected source (.github/workflows/jules-review.yml:18-50; .github/workflows/jules-el-conejo-review.yml:35-52,65-92,259-278,324).

## Attacker Capabilities

- A document sender can control DOCX ZIP structure, XML, relationships, images, fonts, Markdown and legacy DOC bytes without controlling the operator account, trusted environment or filesystem. Potential capability gains include host-resource exhaustion or unauthorized resource access if parsing/path boundaries fail; none is established as a finding by this architecture pass (src/admission.rs:439-512; src/legacy_doc.rs:180-216; src/convert/mod.rs:769-798).
- A connected MCP client can supply tool parameters, document paths, edit plans, destinations and overwrite=true. It is intentionally authorized to access documents beneath the granted root and replace permitted root outputs when requested. A meaningful escape scenario must reach outside the held directory capability, rather than merely modify an authorized root file (jubarte-python/python/jubarte_redlines/mcp_server.py:75-108,153-159; src/publication.rs:153-200,431-463).
- An untrusted document cannot be assumed to control JUBARTE_FONT_DIR, JUBARTE_FONT_INDEX, HOME, APPDATA, XDG_DATA_HOME, release assets, a signing key or local registry credentials. Font-cache tampering scenarios require separate write access to the effective cache location; update-tampering scenarios require release-asset/distribution authority or a demonstrated transport/dependency failure (src/convert/font.rs:2637-2652,3100-3107,3182-3229; src/update.rs:25-48,198-210).
- A PR author can propose repository/build/workflow changes. Configured PR CI executes repository code on self-hosted runners, but whether an outside contributor's run requires approval and whether the runner is ephemeral or isolated are deployment prerequisites absent from source. GitHub contents:read alone does not establish host isolation (.github/workflows/ci.yml:13-48,72-99; .github/workflows/docs.yml:42-86,98-99).
- A party controlling release assets could alter both archive and adjacent checksum while current binaries have no trusted signing key. This is the documented checksum-only trust model, not proof that an ordinary document sender controls releases (src/update.rs:44-48,207,245-257; docs/SELF_UPDATE.md:59-80).

## Security Objectives

- Refuse malformed or policy-exceeding document inputs before expensive package/XML processing; preserve explicit caller-selected budgets. Default admission is 64 MiB compressed/per part, 256 MiB inflated, 10,000 entries and depth 256; compare/render admission is 512 MiB compressed/per part and 2 GiB inflated with the same entry/depth bounds. JSON overrides reject unknown fields and replace only supplied values (src/admission.rs:63-108,130-153; src/convert/mod.rs:769-774; src/document_comparer.rs:4926-4927).
- Keep MCP document I/O inside the initially granted directory despite path/symlink changes, preserve existing files unless overwrite is requested, and accurately report publication state. Publication is atomic per file, not across a multi-file set (jubarte-python/python/jubarte_redlines/mcp_server.py:75-108; src/publication.rs:83-143,153-200,431-505).
- Do not fetch Markdown image URLs or permit document-specified images to escape the explicitly granted native CLI resource directory (src/bin/jubarte.rs:2811-2878,2936-2943).
- Reject invalid PNG DPI and oversized individual rasters; require embedding hosts to apply memory/CPU limits suitable for concurrent or untrusted use rather than treating document budgets as a sandbox (src/convert/mod.rs:602-607,619-632; src/convert/raster.rs:24-42; SECURITY.md:71-74).
- Bind executable updates to the selected project, platform and version, verify release checksum, require user confirmation or --yes, and refuse nonregular extracted binaries. Signature enforcement remains conditional on committed keys and first-signed-release policy (src/update.rs:25-48,87-108,198-210,223-257,274-285,307-320).
- Keep publication credentials confined to their intended workflows and recipients; distinguish build jobs from publishing/signing authority, and distinguish agent comments/fix PRs from human approval (.github/workflows/release.yml:153-158,230-263,277-307,356-369; scripts/release.sh:934-955,1069; .github/workflows/jules-review.yml:28-50).

## Assumptions

- No user deployment context, supplied threat model or authoritative knowledge base was provided. No public HTTP application, tenant model, production container, mount layout or remote MCP exposure is established. MCP's implemented transport is stdio (jubarte-python/python/jubarte_redlines/mcp_server.py:373-381).
- Applicable root SECURITY.md treats document formats/media as untrusted and requires external process memory/CPU limits; those policy statements do not prove such limits exist in actual deployments (SECURITY.md:33-74).
- MCP documentation's path-argument/output confinement is implemented for document I/O, but the broader implementation docstring 'tools only touch files under root' requires qualification: native rendering also reads ambient fonts and maintains a font index outside that root by default. This is a documentation/resource-boundary discrepancy, not a demonstrated document-controlled escape (jubarte-python/python/jubarte_redlines/mcp_server.py:67-72; docs/adoption/mcp.md:61-76; src/convert/font.rs:2633-2652,3090-3107,3154-3229).
- The library overview describes byte-oriented operation with no temporary files, while optional native publication stages files and renderer font indexing writes a temporary sibling. These are actual native host side effects and should remain distinct from in-memory document transformation (src/lib.rs:7-11; src/publication.rs:472-505; src/convert/font.rs:3211-3229).
- SECURITY.md still identifies rdocx-opc 0.2, but the current production manifest uses oxml-opc 0.14.2, quick-xml 0.42 plus a 0.41 compatibility dependency, and zip 9.0.5. Treat dependency-specific policy prose as potentially stale rather than as proof of the current dependency implementation (SECURITY.md:89-94; Cargo.toml:104-117).
- Signing is currently staged but inactive: RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None. docs/SELF_UPDATE.md explicitly describes the checksum-only era; enabling a CI signing secret alone does not add trusted keys to already built clients (src/update.rs:29-48,245-249; docs/SELF_UPDATE.md:59-80; .github/workflows/release.yml:252-275).
- Updater HTTPS/checksum/extraction details and GH_TOKEN/GITHUB_TOKEN precedence are delegated to self_update. Repository code configures rustls/checksum support but no auth-token builder call; dependency implementation was not independently inspected here (Cargo.toml:137-148; src/update.rs:198-210; docs/SELF_UPDATE.md:22-36).
- The private-cache network reachability and push-only publication guarantees in mbx comments depend on the external action/server and runner deployment. No server ACL, container configuration, PR approval settings or runner teardown policy was supplied (.github/actions/mbx/action.yml:8-22).
- The local release script has a separate fallback that creates a GitHub release from workflow artifacts and generates checksums without traversing release.yml's signing step. It checks wheel completeness, but future signed-era compatibility must account for this distinct path (scripts/release.sh:976-1012; .github/workflows/release.yml:252-307).
- The release script also calls an app release helper in a separately located checkout after registry verification. That helper's implementation and deployment credentials are outside the inspected repository evidence (scripts/release.sh:1103-1113).
- Architecture mapping is not a full security audit. No application code, tests, scans or network operations were executed, and no vulnerability is claimed by the independent architecture review.
