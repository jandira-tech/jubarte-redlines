# Threat Model

Jubarte is a local Rust DOCX processing engine with native CLI, PyO3 Python APIs/CLI/MCP stdio server, and wasm-bindgen browser/Node APIs plus an npm CLI. Inputs include DOCX ZIP/XML, legacy OLE DOC, Markdown, JSON edit plans, embedded drawings/images/fonts, and caller-provided conversion options. The engine compares, edits, resolves revisions, inspects, repairs, scrubs, appends, and renders documents into DOCX/PDF/PNG/text/reports (src/lib.rs:7-35,96-165; src/legacy_doc.rs:13-50). Package admission and checked XML parsing precede sensitive parser work on representative engine routes; comparison has larger configurable budgets than ordinary admission (src/admission.rs:63-98,439-470,511-550; src/document_comparer.rs:4907-4927,6530-6559). Native rendering additionally discovers host fonts and maintains a persistent host font index. MCP confines explicitly supplied file paths through a held native directory capability, whereas native CLI/Python/Node command adapters have ambient local filesystem authority (src/publication.rs:146-205; jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-55,106-108). Network access and executable replacement form a separate optional native self-update workflow; release signing/publication are privileged maintainer workflows (src/update.rs:186-258; .github/workflows/release.yml:230-369; scripts/release.sh:875-919,1039-1069).

## Assets

- Confidential document content, authors/comments, revision history, embedded media and generated readable views, patches, reports, DOCX/PDF/PNG outputs. The MCP server returns text, snapshots and reports to its connected stdio client and publishes named files under its configured root (jubarte-python/python/jubarte_redlines/mcp_server.py:131-150,185-218,234-255).
- Integrity of source snapshots, exact anchored edits and output-role separation. Edit plans optionally bind source bytes using SHA-256; native typed delivery rechecks source/plan/text payload and output identities before commit (src/edit.rs:2081-2089; src/bin/jubarte/edit_typed.rs:673-699).
- Host filesystem contents and MCP's caller-granted root directory capability. Native OutputRoot grants the configured existing root once and confines subsequent reads/writes; ambient publish_paths instead operates on operator-authorized local parents (src/publication.rs:146-205).
- Host CPU/memory availability during archive inflation, XML parsing, comparison/layout, images/fonts and legacy DOC conversion. Default admission permits 64 MiB compressed and per part, 256 MiB total inflated, 10,000 entries and depth 256; compare permits 512 MiB compressed/per part and 2 GiB inflated with the same entry/depth defaults (src/admission.rs:63-98).
- Native installed-font bytes and font-index metadata. JUBARTE_FONT_DIR overrides platform font roots; otherwise macOS uses $HOME/Library/Application Support/jubarte/fonts, Linux uses $XDG_DATA_HOME/jubarte/fonts or $HOME/.local/share/jubarte/fonts, Windows uses $APPDATA/jubarte/fonts. JUBARTE_FONT_INDEX overrides the index path, empty/off disables it, otherwise the index is parent(font directory)/font-index.tsv; writes use a sibling with extension tsv.<pid>.tmp then rename (src/convert/font.rs:2633-2652,3090-3107,3182-3229).
- Installed native executable and trusted release channel. Updater selects jandira-tech/jubarte-redlines, SHA256SUMS.txt and jubarte-<version>-<platform>/jubarte[.exe]; current compiled RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None, so installations are checksum-only (src/update.rs:25-48,91-108,198-210,245-257).
- Release signing key and publication authority: ZIPSIGN_PRIVATE_KEY is consumed only by the signing step, decoded into $RUNNER_TEMP/zipsign.<random>/keyN and removed by an EXIT trap; GitHub release publication uses the job's contents:write GITHUB_TOKEN. Local release additionally consumes existing Cargo/npm credentials and UV_PUBLISH_TOKEN for separate registries (.github/workflows/release.yml:230-239,261-309,356-369; scripts/release.sh:904-919,932-958,1039-1069).

## Trust Boundaries

- Untrusted document producer to engine parser: ZIP names/headers, XML and embedded payloads cross into in-process allocation and parsing. Admission prechecks declared budgets, rejects duplicate identities and structural ZIP defects, and bounds actual inflation/XML before downstream processing; shared production archive opens also run zip_defects. These are input/resource controls, not OS isolation (src/admission.rs:439-470,511-550; src/opc/archive.rs:34-51; SECURITY.md:70-74).
- Raw XML caller to checked versus unchecked DOM APIs: try_parse_xdocument_with_limits validates before construction; parse_xdocument deliberately does not enforce input policy. Direct callers must choose the checked API for untrusted XML; package admission is a separate gate (src/xmllinq/parse.rs:91-134; SECURITY.md:54-65).
- Untrusted Markdown to package construction and optional external-resource callback: the library defaults to no image loader, supports inline drawing/data payloads, and delegates named-image resolution to the supplied callback. Native CLI's own callback resolves URLs/percent escapes and uses a root capability restricted to --resource-path or the Markdown source parent; caller-supplied library callbacks own their own authority (src/markdown/mod.rs:159-170,196-198; src/markdown/write.rs:4183-4221; src/bin/jubarte.rs:2811-2871,2936-2943).
- MCP client to root-scoped document operations: --root defaults to cwd, is expanded/resolved and opened once in _OutputRoot. load uses capability-relative native reads, publication uses the same capability, output symlinks/conflicts are rejected and overwrite is explicit. Tool annotations describe behavior; the native capability owns filesystem confinement. The stdio client receives both read and write tools without separate per-tool principal authorization in this adapter (jubarte-python/python/jubarte_redlines/mcp_server.py:54-108,126-168,373-381; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:146-199,447-463).
- Native rendering to ambient host fonts/cache: renderer extracts document font names and invokes installed-face discovery; the font subsystem reads system/user/Office fonts and the persistent font index using std::fs, independently of MCP OutputRoot. macOS cloud-font child paths are restricted to a single normal family-name component, but the index and host font filesystem authority belong to the process (src/convert/mod.rs:806-809,857-867; src/convert/font.rs:2225-2235,2258-2276,2633-2652,3090-3107,3155-3169,3211-3229,3395-3447).
- Native CLI to local document/report publication: explicit output parents are held open; bytes are written, flushed, synced and read back in private staging before per-file atomic replacement or atomic no-clobber hard link. Multi-file publication can partially commit and reports committed state; Windows directory synchronization is intentionally a no-op. Typed edit bundle delivery instead stages a directory and renames the bundle (src/publication.rs:168-174,203-209,387-394,419-514,534-570; src/bin/jubarte/edit_typed.rs:701-747).
- Python and npm CLI host authority is distinct from native CLI publication: Python path reads/write_bytes and Node readFileSync/writeFileSync use ambient host paths. Their supported-operation checks reject unavailable options; sharing the Rust grammar does not establish identical I/O controls (jubarte-python/python/jubarte_redlines/document.py:136-145; jubarte-python/python/jubarte_redlines/__main__.py:101-130,1048-1064; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-78,106-108,713-730).
- Edit plan to document mutation: plan schema/author/source guard and exact operation resolution protect document integrity; signed or macro-bearing packages are refused by Transaction::start. Optional source_sha256 is an integrity precondition, not authentication or user approval (src/edit.rs:2072-2105; src/bin/jubarte/edit_typed.rs:605-612,673-699).
- Operator to native executable update: explicit command and interactive confirmation/--yes gate executable replacement, --check avoids install, explicit --version may downgrade. Platform archive selection, release checksum and regular-file verification precede delegated replacement. The current empty trusted-key set means release-asset control remains release-installation authority; signatures are supported but not currently required (src/update.rs:44-48,91-108,120-125,144-160,186-258,299-321; docs/SELF_UPDATE.md:57-82).
- Maintainer-controlled tag/build to public artifacts and registries: tag version must match Cargo.toml; binary/wheel builders have read-only contents permission, while the release publisher has contents:write. Signing consumes a separately scoped secret and verifies against committed public keys when present. Local release confirms the version unless --yes, checks the generated engine stamp, and invokes independent Cargo/npm/PyPI publication before a separate app-release handoff (.github/workflows/release.yml:15-49,51-89,230-309,356-369; scripts/release.sh:870-919,932-958,1039-1069,1104-1113).

## Attacker Capabilities

- A document producer can control document bytes, relationship strings, part names, XML structure, embedded images/fonts and Markdown including inline payloads. They do not thereby control trusted environment variables, server root selection, installed host fonts/index, release signing keys or publication credentials.
- A library caller may supply input limits, edit plans and an image callback. That caller already owns its process authority; an embedded document causing access beyond the selected callback/root or consuming additional shared resources would be a meaningful boundary failure. No observed remotely hosted multi-tenant deployment is established.
- An MCP client can invoke the registered read/mutation tools and supply relative paths, output directories and overwrite=true within the operator-granted root. Root access is intentionally shared across that server's tools; client access to files elsewhere, or unintended use of ambient rendering resources, would require separate analysis.
- An attacker controlling only malformed input can target parser availability and generated output integrity, but cannot be assumed to possess the operator account, writable trusted font cache, private release infrastructure or registry credentials.
- An attacker controlling release assets could supply an executable accepted by checksum-only updates if able to replace the archive and matching sums. This is a conditional release-channel prerequisite, not a finding that such control exists (src/update.rs:44-48,198-210,245-257; docs/SELF_UPDATE.md:59-80).
- Repository/tag writers and release operators possess existing build/publication authority. CI/release scenarios must identify additional credential, workflow or artifact authority gained rather than treating authorized release actions as exploitation.

## Security Objectives

- Refuse malformed, ambiguous, unsupported or over-budget package/XML input before expensive downstream work where the checked entry point promises admission; maintain explicit refusal behavior for unchecked developer APIs and debug triage (src/admission.rs:439-470,511-550; src/opc/archive.rs:15-19,34-51; SECURITY.md:54-74).
- Keep untrusted document relationships and Markdown names from causing unintended network or filesystem access. Native CLI's named-image reads must remain within the effective resource root; library callbacks remain caller-owned capabilities (src/bin/jubarte.rs:2811-2871; src/markdown/mod.rs:159-170,196-198; SECURITY.md:70-74).
- Confine MCP argument-derived input/output operations to the held root capability, preserve existing outputs unless overwrite is granted, and accurately distinguish renderer ambient cache/font effects from root-confined document publication (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/publication.rs:146-199,447-463; src/convert/font.rs:3090-3107,3182-3229).
- Bind edits and delivery to the intended immutable source/payload, refuse output aliases, preserve refusal atomicity before publication, and accurately report partial commits/durability limitations (src/edit.rs:2081-2089; src/bin/jubarte/edit_typed.rs:605-612,673-747; src/publication.rs:168-174,387-394,534-570).
- Preserve document confidentiality across generated views, patches, logs and exports; the caller selects recipients and storage. Scrub/repair/Word-fidelity claims require operation-specific verification and do not imply general sanitization or safe opening in third-party document applications.
- Permit executable replacement only through the explicit operator update workflow, selected platform/release and effective checksum/signature policy; protect signing and registry credentials in their respective privileged workflows (src/update.rs:186-258,299-321; .github/workflows/release.yml:261-309,356-369; scripts/release.sh:875-919,1039-1069).

## Assumptions

- This is an independent source-backed architecture pass, not completed security-audit coverage or a vulnerability assessment. No application code, tests, malicious inputs or external services were executed. Current authorized checkout HEAD was observed as 4e10eca69c42211651ca907f38b74b6d19e6928c; directory naming does not pin source revision.
- The engine supplies no application authentication/tenant system. The MCP implementation inspected serves stdio; remote exposure, multiple mutually distrustful clients, authentication and OS resource sandboxing would be deployment assumptions, not established features (SECURITY.md:70-85; jubarte-python/python/jubarte_redlines/mcp_server.py:373-381).
- Admission limits are not complete CPU/memory isolation. Compare defaults allow 2 GiB inflated input, and WASM binding documentation expressly tells browser hosts to lower the budget. Actual host memory/CPU ceilings remain caller-owned (src/admission.rs:85-98; jubarte-wasm/src/lib.rs:63-97; SECURITY.md:70-74).
- Documentation/current-code disagreement: src/lib.rs:7-11 describes the toolkit as complete-package byte operations with no temporary files; native rendering actually reads host fonts, persists parent(font directory)/font-index.tsv and writes a sibling tsv.<pid>.tmp before rename (src/convert/mod.rs:806-809,857-867; src/convert/font.rs:3090-3107,3182-3229). This is an architectural side effect; attacker impact requires a separately established access/integrity consequence.
- Documentation/control qualification: MCP's module/build_server wording says tools only touch root files and every path must remain under root (jubarte-python/python/jubarte_redlines/mcp_server.py:5-9,67-68), and actual argument-derived document I/O is capability confined (75-108). Its rendering tool calls the native renderer, whose font/index accesses are ambient and may lie outside root (234-250; src/convert/font.rs:2633-2652,3090-3107,3182-3229). No claim of exploitable root escape follows solely from this cache behavior.
- Documentation/current dependency disagreement: SECURITY.md:89-95 names rdocx-opc 0.2 and patched quick-xml 0.41; current Cargo.toml:104-117 consumes oxml-opc 0.14.2 with optional cryptography disabled, quick-xml 0.42 for checked parsing and renamed quick-xml 0.41 for OPC error compatibility. The policy's intended advisory requirements and current dependency graph must be assessed separately.
- Documentation/updater configuration disagreement: docs/SELF_UPDATE.md:22-24 says GH_TOKEN/GITHUB_TOKEN lift lookup limits. src/update.rs:198-210 sets neither auth_token nor auth_token_from_env. Supporting locally installed self_update 1.3.1 source has opt-in environment-token setters and defaults auth_token to None; the inspected updater configuration does not consume these token variables. Dependency source is supporting evidence outside the repository.
- Current updater signing behavior agrees with staged-signing documentation: RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None mean checksum-only installation, while signing workflow and documentation support future keys (src/update.rs:44-48,245-285; docs/SELF_UPDATE.md:67-82; .github/workflows/release.yml:261-309). Repository secrets and external protection rules were not inspected.
- The separate app repository invoked by scripts/release.sh:1104-1113 is absent from this architecture review. Its deployment accounts, app signing, frontend hosting and publication controls remain unresolved external handoff details.
- Generated WASM packages were inventoried, but this architecture pass did not independently prove committed generated artifacts match current Rust sources. Build provenance and runtime parity remain separate verification tasks.
