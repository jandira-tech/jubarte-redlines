# Threat Model

Jubarte is a local Rust DOCX processing engine with a native CLI, PyO3 Python library/CLI, wasm-bindgen browser/Node bindings, a Node CLI, and an optional Python MCP server over stdio. Normal document processing transforms caller-supplied package/Markdown bytes into document views, edits, tracked changes, PDF/PNG, and reports. Native CLI startup dispatches shared commands on an 8 MiB worker stack; Python wraps the Rust engine, and Node explicitly performs filesystem I/O around WASM calls. The MCP adapter additionally brokers root-confined document reads and output publication. Explicit self-update and maintainer publication are separate privileged workflows. Evidence: Cargo.toml:83-99; src/bin/jubarte.rs:3555-3583; jubarte-python/src/lib.rs:5-15; jubarte-wasm/src/lib.rs:77-97; jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21,52-73,106-111; jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381. Scope is current source under repository '.', userContext=null; no supplied threat model or knowledge base.

## Assets

- Confidential document text, revisions, comments, metadata, images, embedded fonts, generated DOCX/PDF/PNG, patches, and reports. These cross API and MCP responses and caller-selected filesystem outputs. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:131-150,161-218,220-255.
- Host process availability and memory/CPU; default admission permits 64 MiB compressed/per-part and 256 MiB inflated, while comparison and native PDF layout use the roomier 512 MiB compressed/per-part and 2 GiB inflated policy. Both cap entries at 10,000 and XML nesting at 256. XML tag limits are 1,024 attributes, 1,024 name bytes, 64 MiB value bytes, and 128 MiB start-tag bytes. MCP document/output authority is a held cap_std directory; native font discovery/cache accesses remain ambient. Evidence: src/publication.rs:146-165,175-199,203-218; src/bin/jubarte.rs:2858-2871,2936-2943; src/convert/font.rs:2258-2276,2633-2652,3095-3107,3182-3227.

## Trust Boundaries

- Document supplier to Rust parsers: DOCX/legacy DOC/XML/images/fonts are untrusted data. Admission checks archive metadata and names, duplicate identities, supported compression/encryption, structural ZIP defects, bounded inflation and XML policy before ordinary downstream processing. No document parts are extracted to disk by admission. The checked XML APIs validate before constructing DOM nodes; public infallible parse_xdocument deliberately does not enforce policy. Evidence: SECURITY.md:38-74; src/admission.rs:13-28,439-548; src/opc/archive.rs:35-51; src/xmllinq/parse.rs:90-135.
- Admission policy to actual consumers: comparison supports caller overrides over InputLimits::compare; WASM retains the same 2 GiB default despite documenting that it exceeds a 32-bit heap. PDF layout also calls admit_package and therefore uses comparison limits. Archive limits govern admitted processing, while native/Python/Node CLI input files are initially read into memory using ambient filesystem APIs. Host process and ingress quotas remain separate responsibilities. Evidence: jubarte-wasm/src/lib.rs:63-97; jubarte-python/src/lib.rs:65-79; src/convert/mod.rs:769-778; src/bin/jubarte.rs:2740-2742; jubarte-python/python/jubarte_redlines/__main__.py:73-81; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-68.
- MCP client to document filesystem: startup expands/resolves --root, defaulting to cwd, and opens one native _OutputRoot. Each document path passes an early containment diagnostic and is then read relative to the held capability. Output publication validates portable relative paths, uses capability-relative parent traversal, refuses output symlinks, and honors overwrite. This is distinct from advisory MCP ToolAnnotations, and from the ambient filesystem authority available to native/Python/Node CLIs. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,373-381; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:146-218,431-463.
- MCP edit/render request to publication: docx_edit computes clean.docx, redline.docx, patch.diff, report.json and optional redline.pdf/redline-page-NN.png under root/out_dir; docx_render computes page-NN.png and optional render.pdf. All files stage and validate before commits, but replacement is atomic per file, not across the set; commit errors can report already committed files. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:161-218,229-255; src/publication.rs:168-174.
- Markdown image target to native CLI resource authority: --resource-path overrides the Markdown source's parent directory, with '.' for a bare input filename. The loader decodes targets, refuses URL schemes, canonicalizes containment, and reads through an OutputRoot capability. Library DocxOptions defaults to no image loader, making any supplied callback a separate host-granted capability. Evidence: src/bin/jubarte.rs:2835-2871,2936-2943; src/markdown/mod.rs:159-177,196-198,216-226.
- Document font names to native host font resources: rendering resolves fonts through installed/system/Word/cloud and configured per-user directories. The cloud family component must be exactly one normal path component, but native font I/O and the persistent index are not governed by the MCP document OutputRoot. JUBARTE_FONT_DIR overrides the platform directory; JUBARTE_FONT_INDEX overrides the cache, with empty/off disabling it. Otherwise the cache is font-index.tsv in the parent of the effective font directory. Defaults resolve to ~/Library/Application Support/jubarte/font-index.tsv on macOS, $XDG_DATA_HOME/jubarte/font-index.tsv or ~/.local/share/jubarte/font-index.tsv on Linux, and %APPDATA%/jubarte/font-index.tsv on Windows. Evidence: src/convert/font.rs:2225-2236,2258-2276,2281-2315,2633-2652,2855-2862,3095-3107,3154-3168,3182-3227.
- Package relationships to resource consumers: document processing uses package part lookups rather than granting general network/file fetches from relationship targets. Representative rendering story/auxiliary-part selection filters External relationships, while altChunk loading resolves targets into package bytes. This is different from native host font reads and explicitly authorized self-update networking. Evidence: SECURITY.md:70-74; src/convert/mod.rs:789-793,21283-21319.
- Operator to installed executable: only explicit self-update dispatch invokes updater installation. The updater fixes owner/repository to jandira-tech/jubarte-redlines, selects five desktop OS/architecture targets and archive child jubarte-<version>-<target>/jubarte[.exe], verifies SHA256SUMS.txt, applies configured signature policy, and checks the extracted candidate with symlink_metadata before swap. --check does not install; a terminal confirmation or --yes authorizes replacement, and explicit --version permits downgrade. RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None currently disable signature enforcement. Evidence: src/bin/jubarte.rs:3892-3896; src/update.rs:25-48,91-108,120-125,144-160,198-257,307-320.
- Release maintainer to public distribution: v* tags trigger read-only binary/wheel build jobs and a contents-write publication job. Optional signing receives ZIPSIGN_PRIVATE_KEY only in the signer step, decodes keys into $RUNNER_TEMP/zipsign.XXXXXX/keyN, signs dist/jubarte-*.tar.gz and dist/jubarte-*.zip before checksums, and verifies against committed keys/*.pub. Publication attaches dist/* to the current repository/tag. Local scripts/release.sh additionally uses Cargo/npm/PyPI credentials, mandatory security-check.sh, an explicit version confirmation unless --yes, and a separately configured external app checkout. Evidence: .github/workflows/release.yml:15-21,51-89,230-310,317-321,356-369; scripts/release.sh:374-389,655-660,777-784,875-919,934-937,1069.
- PR source to self-hosted CI and remote cache: the docs workflow runs pull_request source on self-hosted runners and invokes a local composite action configuring a pinned external mbx action at http://mbx-cache:7543. The composite's protected-branch-only write claim and private-network-only access are not independently enforced by local source visible here; external action/server and runner provisioning own those controls. The action inserts ${XDG_DATA_HOME:-$HOME/.local/share}/mbx/bin into PATH and configures a 20 GiB store GC target, separate from server authorization and job isolation. Evidence: .github/workflows/docs.yml:42-86,98-99; .github/actions/mbx/action.yml:8-22,33-52.
- PR review authority is separate from companion remediation authority. The standard Jules reviewer runs for same-repository non-Dependabot PRs, receives JULES_API_KEY and a GitHub token with pull-request/check write permissions, delegates to a pinned external action, and disables approval. The companion workflow resolves a same-repository PR, checks out its exact head SHA, posts a report, and grants creation of a Jules fix session only to trusted author/dispatcher arthrod under specified events. The external session uses AUTO_CREATE_PR, require_plan_approval=false, and a branch name; remote source integration and head/target revision binding are absent implementation details, not established controls. Evidence: .github/workflows/jules-review.yml:19-50; .github/workflows/jules-el-conejo-review.yml:46-54,64-102,231-254,259-324.
- Document sanitization to shared artifacts: scrub options select identifying metadata removal; redact promises both document erasure and report secrecy. Actual redaction enforcement scans clean/redline packages through scrub::leaks, while operation reports clone source-derived diagnostics. UTF-16 XML is accepted at admission yet leak scanning assumes UTF-8 for XML. Relocated property names and sibling edit contexts are separately reported privacy failures. Evidence: src/scrub.rs:8-24,39-75,357-384,467-472; src/edit.rs:2476-2526,2695-2751,2931-2939,4727-4746; src/edit/prepared.rs:873; README.md:823.

## Attacker Capabilities

- A document supplier can choose package entries, XML, relationship strings, embedded media/fonts, Markdown and edit-plan data accepted by the caller, without already owning process credentials, environment variables, filesystem roots, or release infrastructure. Parser failure could add process denial of service or unintended host resource access; ordinary requested document transformations are not privilege escalation. Evidence: SECURITY.md:38-74; src/admission.rs:439-548.
- An MCP client can invoke registered tools and choose paths, output directories, edit plans, and overwrite flags within the host-granted root. This adapter supplies no per-tool tenant/identity partition; its transport is stdio, and selecting the root is host authority. Potential boundary failure concerns resources outside that grant, not access already intentionally granted within it. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,152-160,373-381.
- A Markdown author can name image targets; native CLI containment limits that capability to the caller-selected resource directory. A library-supplied image callback may grant different authority and must be evaluated as host code. Evidence: src/bin/jubarte.rs:2835-2871,2936-2943; src/markdown/mod.rs:159-163,196-198.
- Control of JUBARTE_FONT_DIR, JUBARTE_FONT_INDEX, host font files or the existing font index requires an additional local configuration/state capability; it must not be inferred from control of a document's font names. Evidence: src/convert/font.rs:2637-2652,3100-3107,3154-3168,3182-3227.
- A release-asset publisher can affect archive and colocated checksum integrity under today's checksum-only updater policy. This requires release publication compromise or equivalent trusted distribution control, not an ordinary document. A signing-key holder or privileged release runner has separate authority. Evidence: docs/SELF_UPDATE.md:59-80; src/update.rs:44-48,245-257.
- PR authors can provide code and review text. Review/remediation workflows restrict same-repository access, while self-hosted PR CI is a separate boundary whose runner/cache network isolation is not established by workflow permissions. Companion-session spending additionally requires the configured trusted author/dispatcher condition. Evidence: .github/workflows/docs.yml:42-86; .github/workflows/jules-review.yml:19-39; .github/workflows/jules-el-conejo-review.yml:259-269.

## Security Objectives

- Refuse unsupported, structurally inconsistent or over-budget packages before downstream inflation/DOM processing, and use checked XML APIs for new untrusted raw-XML consumers. Preserve the intentionally unchecked API contract rather than treating its existence as a defect. Evidence: src/admission.rs:439-548; src/xmllinq/parse.rs:90-135,919-954.
- Keep MCP document reads and requested outputs inside the host-granted directory through actual capability-relative I/O, rather than relying only on string containment or tool visibility hints. Preserve overwrite policy and report partial commit/durability outcomes honestly. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:75-108; src/publication.rs:146-199,431-463.
- Keep native CLI Markdown image reads within the caller-selected resource authority and avoid fetching document-supplied URLs. Treat ambient CLI paths, library callbacks and native font access as separate capabilities. Evidence: src/bin/jubarte.rs:2835-2871,2936-2943; src/markdown/mod.rs:159-163; src/convert/font.rs:2258-2276,3182-3227.
- Apply caller-owned ingress, memory and CPU limits for shared services, Python hosts and browser/WASM usage; package admission is not a process sandbox or full denial-of-service guarantee. Evidence: SECURITY.md:71-74; jubarte-wasm/src/lib.rs:80-85.
- Bind self-update to the selected repository, version, platform archive and regular-file candidate; require actual compiled trusted keys before claiming publisher-independent signature authentication. Evidence: src/update.rs:25-48,91-108,198-257,307-320.
- Keep release signing credentials limited to the signing step, preserve signature-before-checksum ordering, and retain publication permissions only in the publishing job. External release scripts/checkouts and package registries remain trusted privileged consumers. Evidence: .github/workflows/release.yml:230-310,317-321,356-369; scripts/release.sh:374-389.
- Keep automated review, PR commenting/check writing, companion branch creation, self-hosted job execution and cache publication as distinct authorities with separately established controls. Evidence: .github/workflows/jules-review.yml:28-50; .github/workflows/jules-el-conejo-review.yml:259-324; .github/actions/mbx/action.yml:8-22.
- Honor selected metadata scrubbing and redact's complete artifact privacy promise: no retained removable identifying property at relationship-derived paths, no leaked redacted value in supported XML encodings, reports, refusals or confirmations. Source: src/scrub.rs:16-20,357-384; src/edit.rs:626-630; README.md:823. Violations are reported separately by broken control.

## Assumptions

- This is source-backed architecture mapping, not a completed vulnerability audit. No application execution, network requests, attack inputs, modifications, or history review were performed. The applicable SECURITY.md resolved to the root policy for '.', src, jubarte-python, jubarte-wasm and .github.
- No observed production service, remote tenant model, runner provisioning, filesystem mounts, deployment environment values, or caller process quotas were supplied. Effective platform paths are configuration expressions, not claims about the reviewing machine's actual values.
- Documentation/current-control distinction: docs/SELF_UPDATE.md:32-35 describes signatures once signing is enabled; its explicit staged policy at docs/SELF_UPDATE.md:69-80 agrees with current RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None at src/update.rs:44-48. Signature support must not be reported as currently required authentication. Whether a release secret exists remotely is unknown and unnecessary to establish the updater's compiled policy.
- MCP scope distinction: mcp_server.py:7-9,45-46 promises argument/output paths under root, and native capability I/O supports that claim. Interpreting it as process-wide filesystem confinement would exceed the implementation: native font files and font-index.tsv are consumed via ambient fs APIs. The index default follows the parent of effective JUBARTE_FONT_DIR, so a custom '/some/fonts' directory derives '/some/font-index.tsv'. Evidence: src/convert/font.rs:2637-2652,3100-3107,3182-3227.
- MCP publication is staged before committing but atomic only per file; this does not establish rollback of an entire output set after a commit failure. Evidence: src/publication.rs:168-174. docx_edit's all-or-nothing anchor refusal is a separate pre-publication engine guarantee; mcp_server.py:163-168.
- Cache claim versus visible enforcement: .github/actions/mbx/action.yml:8-12 claims only private-network runners reach a tokenless HTTP server and only protected-branch pushes publish. The local configuration at lines 17-22 supplies URL/namespace to an external pinned action; server ACLs, external action enforcement and runner network isolation are not present here. No unauthorized cache write is established. Runner network access and checkout reuse are documented rather than live-inspected.
- The pinned external Jules actions are implementation gaps for remote tool/session permissions, provider credential handling and exact revision binding. Workflow-side grants and filters are established; broader restrictions are not. Evidence: .github/workflows/jules-review.yml:35-50; .github/workflows/jules-el-conejo-review.yml:259-324.
- Local release app execution resolves JUBARTE_APP_DIR, otherwise repository-relative jubarte-app, then executes scripts/release-engine.sh with version and --engine-dir $PWD; that checkout is explicitly untracked by this repository. Its downstream deployment credentials and controls are unknown. Evidence: scripts/release.sh:382-389.
- The updater delegates HTTPS/download/extraction/replacement internals to self_update with rustls and platform archive features. Wrapper configuration and its regular-file verification hook were inspected; dependency extraction internals were not independently reviewed in this architecture pass. Evidence: Cargo.toml:141-148; src/update.rs:198-210,307-320.
- Additional verified native resource values: Windows installed font roots use WINDIR then SystemRoot then C:\Windows with child Fonts, plus LOCALAPPDATA/Microsoft/Windows/Fonts; persistent font-index writes use a sibling tsv.<pid>.tmp file (src/convert/font.rs:2855-2862,3182-3227). Environment and host-file manipulation require extra local authority and were not inferred from document font-name control.
