# Threat Model

Jubarte is an in-process Rust Word-document engine for comparison, inspection, edit plans, tracked-change resolution, Markdown conversion, legacy DOC import, validation, scrubbing and PDF/PNG rendering. Native CLI, PyO3/Python and wasm-bindgen/Node/browser surfaces call the shared engine (src/lib.rs:7-35; jubarte-python/Cargo.toml:35-39; jubarte-wasm/Cargo.toml:18-32). A separately installed Python MCP server brokers document tools over stdio under one directory capability; the Gemini extension starts this server with workspacePath as its root (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381; gemini-extension.json:5-9). Native CLI self-update is a distinct optional network-and-executable-replacement workflow. Tag releases, local registry publication, CI and external Jules review/remediation are conditional maintainer workflows, not document-runtime capabilities.

## Assets

- Document text, comments, authors, revisions, embedded media/fonts and retained OPC parts; derived Markdown, JSON snapshots, edit reports, clean/redline DOCX and PDF/PNG can contain the same confidential material (src/lib.rs:17-29; jubarte-python/python/jubarte_redlines/mcp_server.py:185-217).
- Host-process memory/CPU availability. Inspection/edit defaults admit 64 MiB compressed, 64 MiB per part, 256 MiB inflated, 10,000 entries and XML depth 256; comparison and rendering use 512 MiB compressed/per part and 2 GiB inflated, with the same entry/depth caps (src/admission.rs:63-99; src/inspect.rs:604-620; src/document_comparer.rs:4926-4927; src/convert/mod.rs:769-778).
- Filesystem authority granted to MCP: the existing expanded/resolved --root directory, default current directory, held through _OutputRoot. Edit artifacts are root/out_dir/{clean.docx,redline.docx,patch.diff,report.json}, optionally redline.pdf and redline-page-NN.png; rendering emits root/out_dir/page-NN.png and optional render.pdf (jubarte-python/python/jubarte_redlines/mcp_server.py:69-108,185-217,234-255,373-381; jubarte-python/src/lib.rs:1244-1278).
- Ambient native/Python renderer fonts and persistent font index. JUBARTE_FONT_DIR overrides platform user-font locations; JUBARTE_FONT_INDEX overrides the index, with empty/off disabling it. Defaults resolve to ~/Library/Application Support/jubarte/font-index.tsv on macOS, $XDG_DATA_HOME/jubarte/font-index.tsv or ~/.local/share/jubarte/font-index.tsv on Unix, and %APPDATA%/jubarte/font-index.tsv on Windows. The index is beside, not inside, fonts, and saves via a sibling .tsv.<pid>.tmp file (src/convert/font.rs:2633-2652,3090-3107,3182-3229).
- Installed native jubarte executable and GitHub release integrity. The updater consumes jandira-tech/jubarte-redlines releases, SHA256SUMS.txt and the platform archive's jubarte binary; RELEASE_KEYS is currently empty and FIRST_SIGNED_RELEASE is None, so effective authentication is HTTPS plus same-release checksum, not Ed25519 signature verification (src/update.rs:25-48,91-108,198-210,245-257).
- Privileged publication resources: GitHub release write token; optional ZIPSIGN_PRIVATE_KEY decoded beneath RUNNER_TEMP/zipsign.<random>/keyN; local crates.io credentials, npm account/OTP and UV_PUBLISH_TOKEN for PyPI. These have separate provider authority and are used only in release workflows (.github/workflows/release.yml:230-285,297-307,356-369; scripts/release.sh:374-380,919,934-956,1069).
- CI runner workspace/cache integrity and external-review credentials. Standard CI runs PR code on self-hosted runners with contents:read and nonpersistent checkout credentials. External Jules review separately receives JULES_API_KEY and a GitHub token with pull-request/check write permissions; companion remediation receives JULES_API_KEY under a trusted-user/event gate (.github/workflows/ci.yml:13-46; .github/workflows/jules-review.yml:20-50; .github/workflows/jules-el-conejo-review.yml:35-54,261-272,320-324).

## Trust Boundaries

- Caller-supplied DOCX/ZIP/XML/media/fonts cross into the host engine. Admission counts actual inflation, checks package identity, names and XML limits; production archive opening rejects header/extent/special-entry defects. Low-level permissive parse_xdocument does not apply input policy: callers of raw XML APIs must select checked parsing or prevalidate. The deliberate debug archive reader is an inspection exception (src/admission.rs:13-28,439-566; src/opc/archive.rs:20-51; src/xmllinq/parse.rs:21-36,98-135; SECURITY.md:132-139).
- Legacy DOC is a separate OLE/FIB/piece-table parser, not a ZIP-admission path. It converts the supported main story to Markdown/DOCX and explicitly excludes encrypted/obfuscated and older Word formats (src/legacy_doc.rs:13-50).
- Edit-plan author transfers requested mutations and optionally source identity to the engine. Schema version and a supplied source_sha256 are checked; the v1 source guard is optional, not an authorization or mandatory freshness credential (src/edit.rs:97-106,2072-2094). Filesystem publication is a separate boundary from in-memory edit acceptance.
- Native CLI uses ambient caller-selected output paths. publish_paths holds each parent directory, stages into parent/.jubarte-<uuid>.partial/bytes, uses Unix staging mode 0700, and commits per file; OutputRoot additionally validates portable relative names and confines capability-relative I/O. Multi-file publication is explicitly not atomic across the set, and errors record already committed files (src/publication.rs:83-143,146-225,228-273,420-505). Python and npm general-output helpers instead directly call Path.write_bytes/fs.writeFileSync; native publication controls cannot be assumed for those helpers (jubarte-python/python/jubarte_redlines/__main__.py:101-113,126-132; jubarte-wasm/cli/bin/jubarte-redlines.mjs:76-79,106-110).
- MCP caller gains document read/write operations only within the operator-selected root. Python resolve-based checks are early diagnostics; native cap-std OutputRoot owns the actual read/write confinement. overwrite is caller-controlled, false by default; annotations are hints, not per-tool authorization. stdio possession is the transport access boundary; no distinct users/tenants are established by this adapter (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,152-160,373-381; src/publication.rs:146-199).
- Native Markdown image references cross from document content into local reads. Effective resource root is --resource-path or the Markdown file's parent, falling back to current directory. Percent-decoded targets must canonically remain under that root and actual reads use its held OutputRoot capability; URL schemes are refused. The library's image callback is separately supplied by the embedding caller, while Python/npm CLI reject resource_path support (src/bin/jubarte.rs:2811-2870,2936-2943,3365-3400; src/markdown/mod.rs:196-198; jubarte-python/python/jubarte_redlines/__main__.py:1057-1064; jubarte-wasm/cli/bin/jubarte-redlines.mjs:724-727).
- Native/Python rendering may read installed fonts and update the ambient per-user/configured index even when invoked through MCP. MCP's document-path capability is not a whole-process filesystem sandbox. Browser/WASM uses embedded/bundled faces rather than installed fonts; its byte APIs do not expose native OutputRoot publication (src/convert/font.rs:2258-2285,2633-2652,3095-3107,3182-3229; README.md:901-920; Cargo.toml:149-152).
- Self-update crosses from GitHub release service/assets into executable replacement. Noninteractive operation requires --check or --yes; a terminal otherwise confirms replacement. Default selection installs newer versions; explicit --version permits downgrade. Unix archive member is jubarte-<version>-<target>/jubarte, Windows member ends jubarte.exe; an extracted regular-file verification hook runs before the delegated swap. Current release keys are empty, so signature support is compiled but not enforcing (src/update.rs:91-124,144-160,186-257,307-320).
- Tag-triggered release builders have contents:read; the separate release job has contents:write. Archives/wheels are downloaded into dist, optional signing rewrites archives before SHA256SUMS.txt generation, then gh publishes dist/* to the tag. The signing private key is step-scoped and decoded into a temporary directory removed by EXIT trap (.github/workflows/release.yml:15-21,51-89,230-285,297-307,317-322,356-369).
- Local scripts/release.sh uses the operator's separate registry credentials, validates tool/auth availability, verifies the tagged engine stamp and prompts for the exact version unless YES bypass applies. It also executes an external app checkout's scripts/release-engine.sh selected by JUBARTE_APP_DIR or jubarte-app; that external implementation and its downstream authority are absent from this repository (scripts/release.sh:374-389,870-899,919,934-956,1069).
- Ordinary PR CI crosses into self-hosted execution with contents:read and persist-credentials:false; those settings govern GitHub-token persistence/permissions, not runner filesystem isolation. Jules review and companion remediation are independent grants: reviewer action receives PR/check-write GitHub token and Jules key, with enable_approve:false; remediation permits only configured trusted author/dispatcher/event combinations, then requests AUTO_CREATE_PR with require_plan_approval:false and starting_branch equal to mutable PR head_ref. The static analysis checkout is bound to head_sha, but the external session input is a branch name (.github/workflows/ci.yml:13-46; .github/workflows/jules-review.yml:20-50; .github/workflows/jules-el-conejo-review.yml:74-102,261-272,320-324).
- Gemini extension startup passes --from jubarte-redlines[mcp] without a version pin to uvx; package resolution is host/package-manager authority before MCP opens workspacePath as root (gemini-extension.json:5-9).

## Attacker Capabilities

- A document supplier can control DOCX/ZIP/XML, embedded media/fonts, legacy DOC bytes and Markdown; it need not control host accounts or filesystem configuration. Denial-of-service and unintended host access boundaries are relevant for library callers even without a demonstrated public deployment.
- An MCP client can invoke exposed document tools and choose relative paths, plans and overwrite within the operator-granted root. It does not thereby possess arbitrary host-path, network, release or registry authority. Directory contents visible to other MCP clients are not isolated per caller by this adapter (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,152-160).
- A same-repository PR contributor can control reviewed source/diff and PR metadata and cause applicable CI/review workflows. Fork PR eligibility, GitHub workflow approval settings and self-hosted runner registration determine additional reachability; no assumption of repository-secret or runner-administrator control is needed or granted by this model.
- A release-asset adversary would need authority over published release artifacts, beyond normal document input. Current checksum-only update trust means archive and matching checksum share the release service's authority; documentation acknowledges this limitation. Signing keys, registry credentials and repository-write tokens are separate capabilities (docs/SELF_UPDATE.md:59-80; src/update.rs:44-48).
- External Jules actions receive explicitly configured credentials and repository context, but their internal authorization, remote session permissions and enforcement cannot be established from this repository's workflow declarations alone.

## Security Objectives

- Refuse unsafe or resource-policy-violating untrusted packages before unbounded package/DOM work, while preserving explicit caller obligations for permissive low-level APIs and process-level CPU/memory limits (src/admission.rs:13-28,63-99; src/xmllinq/parse.rs:21-36; SECURITY.md:69-75).
- Keep document relationships from becoming unintended network/filesystem authority; preserve separate explicit image-loader and native font-resource policies (src/admission.rs:20-22; src/bin/jubarte.rs:2811-2870; src/convert/font.rs:2633-2652).
- Keep MCP document reads/writes beneath the held directory capability, refuse unsafe portable output names and default to preserving existing outputs; distinguish per-file atomicity from multi-output transaction success (src/publication.rs:146-199,228-273; jubarte-python/python/jubarte_redlines/mcp_server.py:91-108).
- Bind supplied edit snapshots to actual source bytes, accurately report refusal/partial publication, and keep author labels and SHA content keys distinct from user authentication (src/edit.rs:2081-2089; src/publication.rs:89-98,123-130; SECURITY.md:77-86).
- Only explicitly requested native self-update may replace the executable; enforce configured checksum/signature policy and regular-file extraction verification without presenting current checksum-only operation as signed-release authentication (src/update.rs:120-124,234-257,307-320).
- Keep release signing, GitHub publication, crates.io, npm, PyPI, review-report writing and remote remediation independently authorized; do not treat prompt instructions or tool annotations as an enforcement substitute (.github/workflows/release.yml:234-235,261-285,356-369; .github/workflows/jules-review.yml:28-50; .github/workflows/jules-el-conejo-review.yml:261-272,320-324).

## Assumptions

- userContext was null; no deployed service, tenants, listener, host mounts, container isolation or external account configuration was supplied. This is a source-backed architecture map, not evidence that every surface has been security-audited.
- Root SECURITY.md applies. Its untrusted-input/process-limit obligations remain relevant: admission budgets are not a proof against every denial of service (SECURITY.md:36-75). Tests/examples/fuzzing and jubarte-rust-inproc are developer/benchmark consumers, not established production servers (jubarte-rust-inproc/Cargo.toml:5-11).
- Documentation says complete-package APIs use no temporary files (src/lib.rs:9-11; docs/rust.md:111-113), but native rendering persists a font index and a sibling .tsv.<pid>.tmp during save (src/convert/font.rs:3182-3229). Retain both facts: the package transformation is byte-based, while rendering can perform ambient font/cache I/O.
- docs/SELF_UPDATE.md:22-24 says setting GH_TOKEN or GITHUB_TOKEN increases API quota. src/update.rs:198-210 does not call auth_token_from_env or auth_token. The locally installed self_update 1.3.1 source defaults auth_token to None and requires the explicit opt-in setter; therefore the documented token behavior is not wired by this consumer. Supporting dependency evidence: /Users/arthrod/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/self_update-1.3.1/src/backends/github.rs:347-359,391-406 and src/backends/common.rs:1052-1053,1081-1085.
- Signature support is present but staged off: RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None agree with the documented checksum-only pre-signing phase (src/update.rs:44-48; docs/SELF_UPDATE.md:67-80). Whether a particular published archive was optionally signed cannot be inferred from repository source or secret declarations.
- MCP root confinement applies to document-path I/O, not all rendering dependencies. Native font discovery/index locations can lie outside root. The operator owns root selection, environment configuration, OS permissions and process/resource isolation.
- GitHub token permissions and persist-credentials:false do not establish isolation of persistent self-hosted runner files/caches. Repository/fork workflow approval rules, runner provisioning and residual host credentials are unknown (.github/workflows/ci.yml:13-46; .github/workflows/docs.yml:76-88).
- Pinned external Jules actions and external app release checkout implementations are not included in inspected repository source. Their internal controls, remote identity, final capability grants and exact session/revision binding remain review gaps; workflow configuration alone does not prove them.
- Standard Python/npm CLI help describes shared output behavior, but general-output helpers use direct host writes, unlike native capability-backed publication. This map does not establish transactional parity across every specialized runner path (jubarte-python/python/jubarte_redlines/__main__.py:5-7,126-132; jubarte-wasm/cli/bin/jubarte-redlines.mjs:6-8,106-110; src/publication.rs:203-225).
- Independent source validation found admission and representation-work controls incomplete on the reported paths; architecture-level policy descriptions above state intended controls, not a claim that every consumer enforces them.
