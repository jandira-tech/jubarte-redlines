# Threat Model

Jubarte is an in-process Rust DOCX comparison, editing, inspection, conversion and revision-processing engine. Rust byte APIs are exposed through a native CLI, PyO3 Python bindings and Python CLI, wasm-bindgen browser/Node bindings and a Node CLI. An optional Python MCP server exposes document tools over stdio with a directory capability. Inputs flow through package admission into OPC/XML processing, comparison/editing/layout, then returned bytes or caller-selected filesystem outputs. Rendering additionally reads installed fonts and maintains a host font index; these operations have authority separate from document publication. Explicit native self-update retrieves GitHub release assets and replaces the executable. Tag-driven GitHub Actions builds and publishes releases. Evidence: src/lib.rs:7-30; jubarte-python/python/jubarte_redlines/__main__.py:5-27; jubarte-wasm/src/lib.rs:7-28; jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21; jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381; src/convert/font.rs:3090-3107; src/update.rs:186-257; .github/workflows/release.yml:15-21,230-245,356-369.

## Assets

- Confidential document contents, media, revision histories, author/comment metadata and rendered text. Read/inspection tools intentionally disclose these to their caller; edit/render workflows write derived DOCX, PDFs, PNGs and reports. Evidence: src/lib.rs:17-28; jubarte-python/python/jubarte_redlines/mcp_server.py:131-150,185-218,229-255.
- Integrity of source-bound edits and explicitly selected output files. Legacy EditPlan source_sha256 is optional and checked when present; CLI additionally provides source-recheck machinery. Evidence: src/edit.rs:5-13,2081-2089; src/bin/jubarte.rs:1642-1655.
- Host memory and CPU consumed by untrusted ZIP/XML, images, fonts, legacy DOC and document layout/comparison. Admission bounds input structures but is not a whole-process resource sandbox. Evidence: SECURITY.md:39-77; src/admission.rs:63-99,439-553.
- MCP root contents and output integrity; host-installed font files and font-index metadata; updater executable integrity; release signing and GitHub publication authority. Evidence: src/publication.rs:146-205; src/convert/font.rs:2633-2652,3098-3107,3155-3168,3213-3229; src/update.rs:198-207; .github/workflows/release.yml:234-235,261-307,356-369.

## Trust Boundaries

- Untrusted document producer to engine: complete package bytes enter admission before representative comparison/rendering paths. Default limits are 64 MiB compressed, 10,000 entries, 64 MiB per part, 256 MiB total inflated and XML depth 256; comparison limits are 512 MiB compressed/per part and 2 GiB total, with the same entry/depth caps. Python/WASM comparison options apply explicit overrides to the comparison settings. Admission checks ZIP defects, canonical part identity, encryption/compression, declared and actual inflation and XML policy. Evidence: src/admission.rs:63-99,137-153,439-553; src/document_comparer.rs:4903-4918,6530-6559; src/convert/mod.rs:769-778; jubarte-python/src/lib.rs:65-79; jubarte-wasm/src/lib.rs:63-74.
- Raw XML caller to DOM: checked parsing applies XML policy, while public infallible parse_xdocument is a lower-level permissive interface whose caller must gate untrusted XML. The tag defaults are 1,024 attributes, 1,024-byte attribute names, 64 MiB raw/decoded values and 128 MiB complete start tags. Evidence: src/xmllinq/parse.rs:44-57,91-98,111-134.
- Agent/client to edit engine: plans select exact anchors against the untouched source; optional legacy source hash rejects stale bytes. This establishes document consistency, not authentication or approval of the requested change. Evidence: src/edit.rs:5-24,2073-2094.
- Native CLI/operator to local filesystem: explicitly selected paths use ambient authority. The Rust publisher holds destination-parent handles, stages and verifies complete bytes, and commits each file separately; failures report already committed files. Existing destinations require overwrite authorization. This is not the MCP directory confinement boundary. Evidence: src/publication.rs:83-130,168-205,211-225,421-480.
- MCP client to document filesystem: --root defaults to process cwd and is expanded/resolved once; build_server opens a native OutputRoot capability. All document loads and outputs route through that held directory. Python resolve/is_relative_to checks provide early diagnostics; actual I/O is capability relative. Outputs reject unsafe relative names, escaping resolution and output symlinks, with overwrite false by default. All connected stdio clients share this root and the registered read/write tools; ToolAnnotations are hints, not per-client authorization. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,152-160,373-381; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:146-199,228-245,431-463.
- Markdown author to CLI image loader: document image names are percent decoded, URL schemes are refused and resolved targets must remain inside --resource-path or the Markdown file's parent, falling back to cwd. A held OutputRoot performs the actual read. This resource capability is independent of ambient output authority. Evidence: src/bin/jubarte.rs:2811-2848,2851-2870,2936-2943.
- Document-selected font families to renderer/host: renderer searches installed font locations and its configured per-user directory; a persistent index can directly select stored face paths after file/directory stamp checks. JUBARTE_FONT_DIR overrides the platform directory. JUBARTE_FONT_INDEX overrides the index path; empty/off disables it. Otherwise the index is a sibling of fonts, at parent(user_font_dir)/font-index.tsv, with staging at the same path after replacing its extension with tsv.<pid>.tmp. These operations use ambient std::fs and do not pass through MCP OutputRoot. Evidence: src/convert/font.rs:2633-2652,2814-2862,3098-3107,3155-3168,3182-3229.
- Browser WASM host to byte API: browser/Node wasm-bindgen functions accept and return byte arrays/strings; filesystem publication is separately performed by a host adapter. The Node CLI explicitly has node:fs authority and directly reads/writes caller-selected paths. Do not transfer native Rust publication guarantees to that adapter. Evidence: jubarte-wasm/src/lib.rs:7-28; jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21,52-73,76-79,106-110.
- Release infrastructure to explicit updater: the target is fixed to jandira-tech/jubarte-redlines and the platform-specific archive entry jubarte-<version>-<target>/jubarte[.exe]. Checksums come from SHA256SUMS.txt in the same release. Current RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None, so signatures are not enforced. Noninteractive replacement requires --yes; --check performs lookup only; named versions can intentionally downgrade. An extracted-binary hook rejects nonregular files. Evidence: src/update.rs:25-48,91-108,120-125,144-160,198-257,274-285,299-320.
- Maintainer/tag authority to release publication: v* tag pushes run a version-match check, read-only build jobs and a distinct contents:write release job. Signing receives secrets.ZIPSIGN_PRIVATE_KEY in its signing step, decodes keys into a temporary runner directory, removes that directory on exit and verifies against committed public keys when present. GitHub publication receives secrets.GITHUB_TOKEN and uploads dist/* to github.repository. Evidence: .github/workflows/release.yml:15-21,31-49,51-89,230-245,261-309,317-322,356-369.

## Attacker Capabilities

- A document supplier can control document/archive/XML/media/font payloads, Markdown image references and document-selected font families, without controlling the host environment, chosen resource root, installed font index, operator account or release infrastructure. Failure at parsing/layout could add denial of service or unauthorized resource access; those impacts require separate validation.
- An MCP caller can read supported documents under the granted root and request exposed editing/rendering writes there, including overwrite=true. This is intentionally granted authority; there is no established tenant or per-tool identity separation. Reading outside the capability or causing writes outside the document root would require a separate control failure or an independently reachable host subsystem.
- An attacker who can only supply input documents is not assumed able to set JUBARTE_FONT_DIR/JUBARTE_FONT_INDEX, modify installed font/index files, publish release assets or push tags. Control of those resources is a distinct prerequisite.
- A release-asset attacker could affect the updater only when the user invokes update and consumes the affected release. Current checksums provide corruption detection without independent signer authentication, as the documentation explicitly recognizes.

## Security Objectives

- Refuse malformed or policy-exceeding packages before representative comparison/rendering work; preserve effective overridden limits instead of silently weakening them. Resource limits remain caller/host responsibilities beyond admission. Evidence: src/admission.rs:63-99,439-553; SECURITY.md:39-77.
- Keep MCP document reads and outputs within the originally granted directory capability, resist escaping symlink resolution, and require explicit replacement authorization. Distinguish this from renderer ambient font/cache access. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/publication.rs:146-199,431-463; src/convert/font.rs:3182-3229.
- Bind prepared edits to their intended source when the relevant guard is supplied or workflow requires it; resolve plan failures before publishing. Publish verified bytes with accurate partial-commit and durability reporting. Evidence: src/edit.rs:5-13,2081-2089; src/bin/jubarte.rs:1642-1655; src/publication.rs:83-130,168-173.
- Restrict Markdown image reads to the selected resource root and refuse network image schemes. Evidence: src/bin/jubarte.rs:2811-2870,2936-2943.
- Keep updater replacement explicit and platform/version bound, verify checksums and regular-file identity, and enforce signatures if trusted keys are enabled. Limit release publication authority to its privileged job and keep private signing material out of published artifacts. Evidence: src/update.rs:120-125,198-257,274-285,307-320; .github/workflows/release.yml:234-235,261-309,356-369.

## Assumptions

- No exact deployment context or authoritative knowledge base was supplied. The model describes supported code paths, not observed production exposure, remote service access, tenant isolation or active release settings.
- Repository SECURITY.md is inherited policy and analysis data. It declares untrusted document inputs and process memory/CPU isolation obligations; this pass does not certify that every exported operation or decoder enforces every declared limit. Evidence: SECURITY.md:39-77.
- Documentation/configuration disagreement: MCP build_server says tools only touch files under root, and its module documentation describes outputs under root, but native rendering has ambient font reads and persistent font-index writes outside that root. Preserve both facts: OutputRoot confines document I/O; the process is not globally filesystem confined. Native macOS fonts default to $HOME/Library/Application Support/jubarte/fonts and index to $HOME/Library/Application Support/jubarte/font-index.tsv. Linux uses $XDG_DATA_HOME/jubarte/fonts or $HOME/.local/share/jubarte/fonts with the index in the parent; Windows uses $APPDATA/jubarte/fonts with index in its parent and system fonts from WINDIR/SystemRoot/LOCALAPPDATA. Nonempty JUBARTE_FONT_DIR overrides fonts; JUBARTE_FONT_INDEX explicitly selects index, empty/off disables it. Temporary sibling replaces extension with tsv.<pid>.tmp. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:5-9,67-72,234-236; src/convert/font.rs:2633-2652,2831-2862,3098-3107,3155-3168,3182-3229. No exploit or unauthorized new capability is established by this architectural discrepancy alone.
- Documentation/configuration disagreement: crate overview says every function returns bytes with no temp files, whereas native rendering maintains a font index using a temporary sibling file and rename. This does not imply document bytes are written to that index; it records lookup/path/stamp metadata. Evidence: src/lib.rs:7-11; src/convert/font.rs:3090-3096,3192-3229.
- Self-update documentation describes signed releases conditionally and explicitly says an empty trusted-key list means checksum-only. Current code matches the staged, checksum-only state; presence of signature dependencies does not establish active signature enforcement. Evidence: docs/SELF_UPDATE.md:29-35,59-80; src/update.rs:44-48,245-249,274-285.
- docs/SELF_UPDATE.md:22-24 claims GH_TOKEN/GITHUB_TOKEN raise the API budget. src/update.rs:198-210 does not explicitly pass an auth token. Whether the dependency automatically consumes these variables was not inspected; credential recipients and this documentation claim remain unresolved.
- Actual OS permissions, environment values, MCP launch cwd/root, font availability, writable-cache state, tag protections, GitHub environment approvals and configured secret presence are not established by source alone.
- External relationship fetching, all legacy-DOC/media decoders, platform-specific dependency extraction internals, all CLI wrapper publication paths and package-manager publication scripts were not exhaustively inspected. They remain explicit coverage gaps; this is an architecture pass without runtime execution.
