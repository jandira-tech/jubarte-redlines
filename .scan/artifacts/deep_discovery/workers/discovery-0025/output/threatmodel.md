# Threat Model

Jubarte is an in-process DOCX comparison, inspection, editing, validation, metadata-scrubbing and PDF/PNG rendering engine, exposed through a native Rust API and CLI, Python/PyO3, and Node/browser WebAssembly. Normal processing transfers complete input bytes into the shared Rust engine and returns new document/report/render bytes; host wrappers own filesystem I/O (src/lib.rs:7-30; src/lib.rs:96-165; jubarte-python/python/jubarte_redlines/document.py:116-145; jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21,52-74,106-111). A separately launched optional Python MCP server serves tools over stdio and grants access to a configured root using the native OutputRoot directory capability (jubarte-python/pyproject.toml:42-49; jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381). Native rendering also reads host fonts and maintains a persistent font index, independently of document output publication (src/convert/font.rs:2258-2315,2633-2652,3090-3107,3182-3229). The default native CLI includes an explicitly invoked GitHub self-update feature; Python and WASM disable that engine default feature (Cargo.toml:82-99; jubarte-python/Cargo.toml:35-39; jubarte-wasm/Cargo.toml:18-23). Tag-driven CI builds five desktop targets and publishes release archives, optionally signing them; these privileged publication operations are distinct from document editing (src/update.rs:186-258; .github/workflows/release.yml:15-21,51-74,261-309,356-369). This model describes inspected current source at /Users/arthrod/temp/T/jubarte-redlines, observed HEAD 4e10eca69c42211651ca907f38b74b6d19e6928c; it is architecture mapping, not completed security-audit coverage.

## Assets

- Confidential source document bytes, text, tracked changes, comments, embedded media and other preserved package parts; generated clean/redline DOCX, PDF/PNG, Markdown diffs and reports contain document-derived information (src/lib.rs:15-30; jubarte-python/python/jubarte_redlines/mcp_server.py:185-218,234-255).
- Host filesystem read/write authority: ambient caller-selected CLI/Node paths are different capabilities from the MCP server's held OutputRoot directory. OutputRoot confines relative reads and publication to its directory capability; publish_paths deliberately uses ambient local authority (src/publication.rs:146-226; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-78,106-111).
- Integrity of edit targets and resulting review artifacts. Legacy plans optionally bind source_sha256; v2 plans require a structured source hash. These are document-consistency controls, not caller authentication (src/edit.rs:97-106,2081-2088; src/edit/v2.rs:506-531).
- Availability and memory/CPU of the embedding native process, Python interpreter, or WASM instance when processing attacker-influenced packages, XML, images, fonts or edit plans. Default admission permits 64 MiB compressed input, 10,000 entries, 64 MiB per part, 256 MiB total inflated bytes and XML depth 256; comparison/WmlDocument uses 512 MiB compressed/per-part and 2 GiB total inflated bytes (src/admission.rs:42-98; src/wml_document.rs:50-57).
- Native renderer's host font files and mutable per-user font-index.tsv, including cached face source paths and filesystem metadata. Font-cache writes use ambient filesystem operations and are not mediated by OutputRoot (src/convert/font.rs:2633-2652,3090-3107,3154-3171,3182-3229).
- Installed native CLI executable and release provenance. Current updater trust keys are empty and its first-signed-release threshold is unset, so deployed source enforces checksum-only installation unless these constants change (src/update.rs:25-48,198-210,245-257).
- Conditional CI secrets and publication capabilities: ZIPSIGN_PRIVATE_KEY is delivered to the signing step, decoded into temporary runner files and used to sign dist/jubarte archives; the release step receives GITHUB_TOKEN as GH_TOKEN and creates release assets (.github/workflows/release.yml:261-309,356-369). Jules review receives JULES_API_KEY and GITHUB_TOKEN with separately declared review permissions (.github/workflows/jules-review.yml:17-50).

## Trust Boundaries

- Document producer to shared Rust parser: caller-controlled DOCX/legacy DOC/XML/media enters package admission, OPC handling, DOM construction, editing and rendering. Admission enforces configurable archive and XML limits; WmlDocument first admits under the comparison budget before opening the package. Library unsafe Rust is forbidden, but dependency safety and process resource limits remain separate controls (src/admission.rs:42-98,399-448,486-543; src/wml_document.rs:50-57; src/lib.rs:85-87; SECURITY.md:38-74).
- ZIP central/local metadata to OPC package identity: production open_archive wraps unchecked archive open and validates defects; admission runs the defect pass while preserving typed refusal. Debug inspection intentionally has a different acceptance mode and must not be treated as the production admission boundary (src/opc/archive.rs:20-44,339-364,388-484; src/admission.rs:439-448; SECURITY.md:111-136).
- Raw XML caller to DOM: checked APIs are the intended policy boundary; infallible parse_xdocument deliberately does not enforce input policy. A caller invoking raw low-level APIs owns admission obligations rather than gaining protection solely by linking the crate (SECURITY.md:43-66; src/wml_document.rs:85-96).
- Agent/client to MCP filesystem broker: startup resolves --root, defaulting to cwd, opens _native._OutputRoot once, and serves stdio. Tool paths receive early Python containment checks, but actual reads/publication use the native directory capability; annotation hints are descriptive metadata rather than independent authorization. Every connected caller receives the configured tool capabilities; no per-user ownership or tenant model is established by this source (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,373-381; src/publication.rs:146-200).
- MCP edit intent to published artifacts: docx_edit resolves a plan in memory, constructs clean.docx, redline.docx, patch.diff and report.json under caller-selected out_dir inside root, optionally adds rendered artifacts, then calls the broker's publish operation. Invalid plans are reported before publication; actual filesystem publication is atomic per file, not across the output set, and errors identify already committed files (jubarte-python/python/jubarte_redlines/mcp_server.py:153-218; src/publication.rs:83-143,168-199). No human approval boundary is implemented or claimed here.
- Local CLI caller to ambient host publication: native publish_paths grants explicit local path authority, while Node's wrapper directly reads/writes paths with fs and checks overwrite separately. These interfaces do not inherit MCP's root confinement merely because the engine/parser is shared (src/publication.rs:203-225; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-78,106-111,137-153).
- Document font family/native rendering to host font resources: installed_family_faces obtains the environment-derived user font folder and Word cloud-font root and scans known font directories. Cloud family names must be one normal path component; cached index entries can subsequently name font files directly. Persistent font-index loading/saving and font reads operate with ambient process authority (src/convert/font.rs:2225-2235,2258-2315,2633-2652,3090-3107,3154-3171,3182-3229). This boundary exists during native MCP rendering even when document paths are confined.
- Local operator to executable update: self-update checks interactivity before network lookup, chooses one of five OS/architecture targets, obtains the project's GitHub release, requires explicit intent for downgrades and confirmation unless --yes, downloads the target with SHA256SUMS.txt verification, registers a regular-file extracted-binary hook and replaces the executable through self_update. Current source has no trusted signing key, so GitHub release-asset integrity remains part of the trust chain (src/update.rs:25-48,83-109,120-125,144-161,186-258,299-307).
- Maintainer/tag authority to public release artifacts: v* pushes trigger builds; tag and Cargo version must match; binary jobs have contents:read; signing consumes a step-scoped private-key secret and checks archives against committed public keys when present. Release publication consumes a separate GitHub token. Actual repository protection, environment approvals and external registry/account configuration are not established by these workflow declarations (.github/workflows/release.yml:15-49,51-74,261-309,356-369).
- Same-repository PR content to external Jules reviewer: the review workflow excludes fork/Dependabot PRs, performs no local checkout, delegates to a SHA-pinned external action, grants read content plus write PR/check permissions, and disables model approval. External action/Jules implementation is absent from inspected repository source, so its downstream session controls and secret handling remain unresolved (.github/workflows/jules-review.yml:17-50). The separate el-conejo workflow resolves a same-repository PR and checks out its exact head with persisted credentials disabled; it has its own author/dispatcher trust configuration and should not be collapsed into the first workflow's authority (.github/workflows/jules-el-conejo-review.yml:35-52,58-102).

## Attacker Capabilities

- An input producer can supply document/package/XML/media bytes and content such as relationships, font-family names, tracked-change authors, comments and text, without already controlling the host account, environment, trusted output root, release infrastructure or signing keys (SECURITY.md:38-74; src/convert/font.rs:2225-2235). Boundary failure could add host-process availability impact, unintended filesystem access, or document/output corruption; this model does not claim such a failure.
- An MCP client can select paths and output names within the operator-granted root, submit JSON edit plans, invoke rendering and request overwrite=true. Those are intentionally granted tool operations. Access outside that root, unrelated ambient process capabilities, or cross-client ownership controls must not be assumed authorized merely from tool visibility (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,153-168,220-277).
- Native and Node CLI users select local input/output paths and operate with their host account's filesystem permissions. Self-only arbitrary path writes requested by that same operator are not privilege escalation; MCP confinement is a separate boundary (src/publication.rs:203-225; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-78,106-111).
- A contributor may influence PR source and review inputs, but is not assumed able to push trusted release tags, change branch protections, retrieve CI secrets or alter an installed binary's embedded update policy. Same-repository PR and trusted-user requirements are workflow prerequisites; external action implementation is not available here (.github/workflows/jules-review.yml:19-50; .github/workflows/jules-el-conejo-review.yml:35-52).
- A party able to alter only release assets cannot change public keys compiled into an already installed binary, but current source compiles no trusted keys. The documented staged signature design must therefore be distinguished from the effective checksum-only policy (src/update.rs:44-48,245-249; docs/SELF_UPDATE.md:59-87). No release compromise is alleged.

## Security Objectives

- Refuse malformed, ambiguous or over-budget untrusted package/XML inputs before expensive downstream processing; preserve package identity across archive metadata representations and avoid unsafe entry types. Admission limits do not replace host-enforced CPU/memory isolation (src/admission.rs:399-448,486-543; src/opc/archive.rs:388-484; SECURITY.md:38-74).
- For MCP tool document I/O, actual filesystem resolution must remain within the held operator-granted root even if pathnames or symlinks change. Overwrite requires an explicit flag; staging failures preserve existing outputs, and partial commit/durability failures must be reported accurately (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/publication.rs:36-46,83-143,146-200).
- Preserve exact edit-source/anchor consistency and refuse invalid plans before output publication. Treat hashes as consistency evidence and distinguish optional legacy guards from required v2 source metadata (src/edit.rs:97-106,2081-2088; src/edit/v2.rs:506-531; jubarte-python/python/jubarte_redlines/mcp_server.py:170-218).
- Keep independent filesystem capabilities explicit: OutputRoot confines brokered document reads/writes, ambient CLI APIs intentionally grant local path access, and native font lookup/cache operations require their own host controls. Avoid claiming process-wide confinement from a document-output capability (src/publication.rs:146-225; src/convert/font.rs:2633-2652,3090-3107,3182-3229).
- Never turn document relationships into unrequested network fetches during processing; external relationships are untrusted document metadata. The repository states this guarantee, but a complete all-consumer verification was not performed in this architecture pass (SECURITY.md:38-74).
- Require deliberate operator initiation and appropriate artifact verification before executable replacement; preserve no-background-update behavior and disclose the actual signing state. Current implementation's keys/threshold are empty rather than activated (src/update.rs:44-48,186-258; docs/SELF_UPDATE.md:9-41,59-87).
- Keep CI signing and publication credentials separate from ordinary untrusted document processing and restrict their recipients to the corresponding workflows/steps. Do not infer external secret storage, branch-protection or runner guarantees from YAML alone (.github/workflows/release.yml:261-309,356-369; .github/workflows/jules-review.yml:28-50).

## Assumptions

- Scope is the supplied repository path '.', with no supplied user deployment context, immutable revision requirement, scoped-source inventory or authoritative supplied model. The artifact working-directory name is not an authorization to substitute its embedded hash for current source. Observed current HEAD is 4e10eca69c42211651ca907f38b74b6d19e6928c.
- The repository supplies a library, CLI and local stdio MCP server rather than an established internet-facing multitenant service. A deployment that exposes these through an HTTP/API service must provide authentication, authorization, quotas and isolation; those deployment controls are not established here (src/lib.rs:7-35; jubarte-python/python/jubarte_redlines/mcp_server.py:373-381; SECURITY.md:71-85).
- Documentation says every MCP path/tool only touches files under --root and Python Document operations write no output files. Actual brokered document I/O uses OutputRoot, but rendering also reads ambient font directories and writes an ambient per-user font index. Therefore the broad root-only wording must not be interpreted as process-wide filesystem confinement (jubarte-python/python/jubarte_redlines/mcp_server.py:5-11,67-108,234-255; jubarte-python/python/jubarte_redlines/document.py:116-123; src/convert/font.rs:2633-2652,3090-3107,3182-3229).
- Documentation says core operations use complete bytes with no temporary files. Native font-index persistence creates a sibling PID-suffixed .tmp file before renaming, and host publication deliberately creates staging. The byte-level document-processing statement and incidental host filesystem behavior must both remain visible; this architecture difference is not by itself a vulnerability (src/lib.rs:7-11; src/convert/font.rs:3221-3229; src/publication.rs:284-312).
- Self-update documentation describes staged signing and correctly says empty embedded keys mean checksum-only operation. Actual RELEASE_KEYS=&[] and FIRST_SIGNED_RELEASE=None confirm that signing support is currently inactive in the updater. Whether GitHub's private signing secret exists is not inferable from source (docs/SELF_UPDATE.md:59-87; src/update.rs:44-48; .github/workflows/release.yml:261-275).
- SECURITY.md describes rdocx-opc 0.2 and quick-xml 0.41 remediation. Current manifest instead uses oxml-opc 0.14.2, quick-xml 0.42 for checked admission and an explicitly aliased 0.41 for OPC error compatibility. Preserve this documentation/dependency-name discrepancy without inferring either an exploit or lack of patched behavior (SECURITY.md:89-97; Cargo.toml:102-117; src/opc/mod.rs:15-17,161-164).
- Default and comparison admission budgets are materially different. WmlDocument admits under the roomier comparison budget, so a general statement that the default 64 MiB/256 MiB budget protects every public use would be inaccurate (src/admission.rs:25-27,63-98; src/wml_document.rs:50-57).
- Output publication is atomic per file rather than transactional across an output set, and it reports partial commits. Python plan-level atomicity claims must not be generalized into rollback of successful filesystem commits (src/publication.rs:5-7,36-46,83-143,168-174; jubarte-python/python/jubarte_redlines/mcp_server.py:161-168,217).
- Native font-cache locations depend on operator environment, cwd when overrides are relative, and platform. Actual runtime environment values, host ACLs, mounted directories, network filesystem behavior and externally imposed resource limits were not supplied and were not inspected (src/convert/font.rs:2633-2652,3098-3107,3213-3229).
- External crate implementations, generated WASM correspondence to current Rust source, external GitHub/Jules services, account/branch protections and full privileged remediation workflow details were not completely inspected. These are explicit coverage limits, not findings.
- Validation refined the architecture's expected resource controls: the pre-index EOCD count can differ from zip's selected record (src/admission.rs:399-407,444-455,590-602); tolerant XML admission and recursive DOM consume unquoted attributes differently (src/admission.rs:788-820; src/xmllinq/parse.rs:554-593,660-663). Thus archive entry count and admitted XML depth are intended controls with specific validated bypasses, not universal effective guarantees.
- Logical and generated-output work requires separate limits: table spans, numbering ranges/labels, altChunk expansion, repeated relationship repair, legacy piece expansion, field-state scans, escaping and table padding contain independently validated resource issues. The ordinary byte/depth limits and recommended process isolation remain material mitigations with bounded coverage (src/convert/mod.rs:13601-13615,5518-5532,6015-6019,773-798; src/opc/mod.rs:99-125; src/legacy_doc.rs:511-527,575-598,1176-1227,1591-1621).
- Privacy scrub's intended selected-category guarantee is narrower in implementation because it selects conventional part locations rather than all relationship-selected semantic parts. Alternate main paths are explicitly supported by admission; sanitization must account for those paths before sharing (src/scrub.rs:211-216,271-289,353-385; src/admission.rs:1754-1769; src/cli.rs:1553-1557).
- The independent Node CLI plan recorder still follows predictable temporary paths despite native recording's secure publication. Conditional local shared-directory exposure is separate from normal ambient CLI path authority (jubarte-wasm/cli/bin/jubarte-redlines.mjs:408-427; src/edit/record.rs:142-149,161-167).
