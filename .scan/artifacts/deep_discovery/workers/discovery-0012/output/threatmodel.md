# Threat Model

Jubarte is an in-process Rust DOCX comparison, editing, inspection, revision-resolution and PDF/PNG rendering engine exposed through a native CLI, PyO3 Python bindings/facade, wasm-bindgen browser/Node bindings, Python and Node CLI adapters, and an optional Python MCP stdio server (README.md:12-40; src/lib.rs:15-35; jubarte-python/python/jubarte_redlines/mcp_server.py:373-381). Normal document processing accepts package bytes and returns transformed bytes or reports; host adapters supply filesystem authority. Package admission and checked XML APIs form the principal untrusted-document boundary. Native rendering additionally reads installed fonts and maintains an ambient font index. Conditional privileged workflows are explicit CLI self-update and maintainer release publication. No deployment/user context or authoritative knowledge base was supplied; this is a source-backed architecture map, not completed vulnerability-audit coverage.

## Assets

- Confidential document contents, comments, tracked changes, embedded media, generated PDF/PNG, edit reports and patches; MCP callers receive document text and reports over stdio and output files under their granted root (jubarte-python/python/jubarte_redlines/mcp_server.py:131-150,185-217,245-255).
- Integrity of original documents, selected output files, edit targets and source snapshots. Optional source_sha256 binds a semantic edit plan to exact source bytes; schema and anchor checks reject invalid edits (src/edit.rs:1735-1761,2073-2094).
- Host process memory/CPU availability against attacker-supplied ZIP/XML/media/font content; normal default and comparison admission budgets differ materially (src/admission.rs:39-100; SECURITY.md:38-74).
- Filesystem authority of the local CLI user versus the directory capability granted to an MCP server. Native CLI publication uses ambient authorized paths; MCP reads/publication use an open cap-std directory (src/publication.rs:146-225; jubarte-python/src/lib.rs:1244-1278).
- Installed executable integrity, GitHub release assets/checksums, optional release-signing private key, registry publication identities and generated npm/wheel/crate artifacts (src/update.rs:25-48,198-210; .github/workflows/release.yml:252-321,356-369; scripts/release.sh:872-899,919-959,1069).
- Ambient font metadata and source paths in the native renderer's font-index.tsv; cached entries cause direct reads of recorded face paths after metadata stamp checks (src/convert/font.rs:3090-3107,3154-3189,3213-3229).

## Trust Boundaries

- Untrusted DOCX bytes enter Rust processing through byte APIs and bindings. Admission limits compressed size, entry count, per-part/aggregate inflation, XML nesting and tag policy; no archive extraction, macro execution or external-reference resolution is intended (src/admission.rs:13-28,63-100; src/document_comparer.rs:6530-6567; src/xmllinq/parse.rs:19-36).
- Archive metadata crosses into package interpretation. Normal open_archive invokes zip_defects and refuses inconsistent headers, overlapping/extending entries and unsupported entry types; the deliberately unchecked debug opener is a distinct maintainer inspection path (src/opc/archive.rs:15-51).
- Raw XML callers may choose permissive parse_xdocument, which explicitly does not enforce input policy. Checked parsing or prior admission is the caller's responsibility; parsing must not be modeled as uniformly guarded (src/xmllinq/parse.rs:19-36,84-98; SECURITY.md:54-65).
- An edit-plan producer controls operations, replacement content and optional snapshot guard. Source hash validation is conditional on source_sha256 being present; semantic edits return memory results before host publication (src/edit.rs:1735-1761,2081-2089).
- An MCP client controls tool names, document paths, output paths, plans, rendering options and overwrite flags through a stdio connection. Every registered caller shares the configured directory authority; annotation hints are metadata rather than per-caller authorization. Root is --root or current directory, opened once through _OutputRoot. Python resolution is an early diagnostic; actual reads and writes use the capability (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,373-381; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:146-200).
- MCP document I/O and local CLI publication have independently enforced authority. OutputRoot validates portable relative paths and rejects output symlinks; publish_paths grants ambient local access. Publication stages every file first but commits per file, so a commit/durability failure can expose a reported partial set. Windows parent-directory sync is explicitly a no-op (src/publication.rs:83-143,168-225,228-273,387-405,431-480).
- Python and Node CLI adapters own ambient file access and do not inherit MCP confinement or native publication controls. Their general write helpers directly write destinations after adapter checks (jubarte-python/python/jubarte_redlines/__main__.py:101-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-79,106-111).
- Native rendering crosses into ambient font files and persistent font-index state, independently of document publication authority. JUBARTE_FONT_DIR overrides the platform font directory; JUBARTE_FONT_INDEX overrides or disables the index, otherwise the index is in the font directory's parent. Document family names used in cloud-font paths are restricted to one normal path component (src/convert/font.rs:2225-2236,2633-2652,3098-3107,3154-3169,3213-3229).
- Explicit self-update grants downloaded release code authority to replace the running executable. Repository/target/archive member and SHA256SUMS.txt are configured in code, a prompt or --yes gates installation, and a regular-file hook validates the extracted binary. Current compiled keys are empty and FIRST_SIGNED_RELEASE is None, so signature enforcement is currently inactive (src/update.rs:25-48,91-109,120-125,198-210,234-257).
- Tag pushes trigger build jobs with contents:read, then a contents:write release job publishes dist/* using GITHUB_TOKEN. Optional ZIPSIGN_PRIVATE_KEY reaches the signing step and temporary decoded key files; signatures precede checksums. The local release script separately uses operator registry identities and verifies artifact provenance against the tag (.github/workflows/release.yml:15-21,51-89,230-239,252-321,356-369; scripts/release.sh:872-899,919-959,1069).
- Markdown input contains active reconstruction metadata: drawing payload JSON indexes form an attacker-controlled dependency graph; table comments encode expansion counts. Optional reference DOCX templates cross a separate package/XML boundary before styles/section extraction (src/markdown/write.rs:59-108,1096-1123,1256-1283,4183-4201; src/markdown/from_docx/drawing.rs:1395-1409,1881-1904,1954-1983; src/markdown/package.rs:101-126,542-557). Legacy DOC story field-control characters cross a distinct parser-work boundary (src/legacy_doc.rs:180-215,1591-1620).

## Attacker Capabilities

- A document supplier can control DOCX ZIP records, XML, embedded media/fonts, relationships, revision/comment text and document font family names before a user or embedding service processes the document. They do not thereby control host environment variables, installed fonts, MCP startup root or release accounts (SECURITY.md:38-74; src/admission.rs:13-28; src/convert/font.rs:2225-2236).
- An authorized MCP client can invoke all registered tools and select files within the server's granted root, including overwrite=true. Root-wide access is the provided capability; no separate tenants, document ownership identities or per-tool authorization layer is established by this adapter (jubarte-python/python/jubarte_redlines/mcp_server.py:54-108,152-168,373-381).
- A less-trusted producer can supply edit JSON and anchored replacement content to a trusted caller. A failure could corrupt document edits or bypass snapshot/anchor invariants; source_sha256 is optional, and the model must not assume it always exists (src/edit.rs:106,1735-1761,2081-2089).
- A local actor who can modify shared output directories, font directories or font-index state has a materially different starting capability from a document-only attacker. Assess filesystem races and ambient font-cache integrity only with that prerequisite; do not assume document content controls these locations (src/publication.rs:146-148,431-480; src/convert/font.rs:3154-3189,3213-3229).
- An attacker controlling GitHub release assets could alter an archive and adjacent checksum in the current checksum-only updater trust model; this requires release-asset control and an operator invoking installation, rather than ordinary document processing. Documentation explicitly distinguishes corruption detection from independent authenticity (src/update.rs:44-48,245-256; docs/SELF_UPDATE.md:59-80).
- A contributor can propose repository/workflow changes, but no supplied context establishes tag-push rights, protected-branch bypass, registry credentials, release-signing keys or production deployment access. Privileged release impact needs that additional authorization or a separately demonstrated crossing (.github/workflows/release.yml:15-21,230-235,261-264,356-369).

## Security Objectives

- Refuse malformed or resource-excessive untrusted packages before uncontrolled inflation/DOM construction; preserve active configured limits across consumers. Defaults are 64 MiB compressed/per-part, 256 MiB aggregate, 10,000 entries and XML depth 256; comparison defaults are 512 MiB compressed/per-part and 2 GiB aggregate with the same entry/depth caps. Tag defaults include 1,024 attributes, 1,024-byte attribute names, 64 MiB attribute values and 128 MiB start tags (src/admission.rs:63-100; src/xmllinq/parse.rs:48-57).
- Keep document relationship targets as data during processing, avoid macro execution and archive extraction, and ensure normal readers interpret ZIP identity/content consistently (src/admission.rs:13-22; src/opc/archive.rs:34-51).
- Preserve semantic edit atomicity: reject invalid plans/anchors before returning results, validate a supplied source hash, and distinguish this in-memory guarantee from host filesystem transaction behavior (src/edit.rs:1735-1761,2081-2089; src/publication.rs:83-143).
- Confine MCP document reads/writes to its caller-granted directory capability, reject unsafe export names, require overwrite authorization for existing outputs, and report partial publication/durability outcomes accurately (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108; src/publication.rs:146-200,228-273,431-480).
- Bind self-update to the intended repository, platform, archive member and selected release, check its checksum, and enforce signatures when compiled policy enables them. Do not represent current checksum-only policy as independent release authenticity (src/update.rs:25-48,91-109,198-210,245-256; docs/SELF_UPDATE.md:59-80).
- Restrict publication credentials to privileged workflows; bind tagged engine provenance to generated artifacts and checksum the final signed archive bytes (.github/workflows/release.yml:19-21,230-235,252-321; scripts/release.sh:872-899).
- Bound semantic dimensions, metadata expansion, graph traversal and parser work after byte-level admission, including table spans, numbering levels, Markdown drawing graphs/row ranges and legacy field state. Admit every supplied reference package before unchecked XML DOM construction (locations retained in the corresponding validated findings).

## Assumptions

- No user deployment context, preexisting model or knowledge base was supplied. No production web service, network-accessible MCP transport, multi-tenant hosting, authentication service or container/mount layout is established. The observed MCP startup uses stdio (jubarte-python/python/jubarte_redlines/mcp_server.py:373-381).
- Process memory/CPU limits and isolation remain embedding-host obligations; configured archive/XML budgets are not a proof against all denial of service (SECURITY.md:70-74).
- The Rust library overview says operations use no temp files, but native font discovery can write font-index.tsv and a sibling font-index.tsv.<pid>.tmp through ambient std::fs. This is font metadata state rather than extracted document parts; applicability requires a rendering path that performs indexed font lookup and a usable configured/default path (src/lib.rs:7-11; src/convert/font.rs:3090-3107,3213-3229).
- MCP documentation promises paths under the server root; document path arguments are capability-confined, while native rendering's host-configured font/cache accesses are independent ambient resources. No evidence establishes that an MCP client can change their configuration (jubarte-python/python/jubarte_redlines/mcp_server.py:7-9,67-108; src/convert/font.rs:2633-2652,3098-3107).
- The Python/Node adapters advertise shared command behavior, but their general filesystem write helpers differ from native staged publication. Semantic-plan atomicity does not establish cross-adapter multi-file filesystem atomicity (jubarte-python/python/jubarte_redlines/__main__.py:5-7,126-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:6-8,106-111; src/publication.rs:168-174).
- Current signing is explicitly staged: RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None match documentation's checksum-only initial phase. Whether deployed older/newer binaries or GitHub secrets differ cannot be determined offline (src/update.rs:29-48; docs/SELF_UPDATE.md:67-80; .github/workflows/release.yml:252-275).
- SECURITY.md still describes rdocx-opc 0.2, while the inspected Cargo.toml configures oxml-opc 0.14.2 and two quick-xml versions for distinct consumers. Preserve this documentation/dependency-name disagreement for dependency investigation; it does not by itself establish an exploitable issue (SECURITY.md:87-94; Cargo.toml:102-117).
- The independent architecture phase mapped consumers and source anchors. The subsequent Standard audit source-validated the retained findings and control dispositions but did not execute application code, test controls or inspect live services. Full-file repository coverage remains explicitly partial.
- Verified effective native font index: explicit JUBARTE_FONT_INDEX wins; empty/off disables. Otherwise user_font_dir().parent()/font-index.tsv yields macOS $HOME/Library/Application Support/jubarte/font-index.tsv, Linux $XDG_DATA_HOME/jubarte/font-index.tsv or $HOME/.local/share/jubarte/font-index.tsv, Windows %APPDATA%/jubarte/font-index.tsv. Explicit JUBARTE_FONT_DIR maps index to its parent, not inside the font directory. PID sibling staging uses host filesystem authority (src/convert/font.rs:2633-2652,3100-3107,3213-3229).
- Verified effective release resources: zipsign private-key reference secrets.ZIPSIGN_PRIVATE_KEY is decoded under $RUNNER_TEMP/zipsign.<random>/key<n>, cleaned on EXIT, and used only in signing step before dist/* SHA256SUMS; GitHub release job uses secrets.GITHUB_TOKEN with contents:write; operator registry clients consume CARGO_REGISTRY_TOKEN, npm login/NPM_OTP and UV_PUBLISH_TOKEN. Provisioning, runner isolation and registry accounts are external unknowns (.github/workflows/release.yml:252-321,356-369; scripts/release.sh:370-380,655-656,872-899,919-959,1069-1097).
