# Threat Model

Jubarte is an in-process Rust DOCX comparison, editing, revision-resolution, validation, scrubbing and PDF/PNG rendering engine, exposed through the native CLI, PyO3 Python library/CLI, wasm-bindgen Node/browser APIs and an optional Python MCP server over stdio. Document bytes flow through package admission, OPC/XML processing and operation-specific logic into returned bytes, text or host-owned output files. Legacy DOC conversion is a separate OLE parser. The Rust library forbids unsafe code. The normal runtime is a caller-owned process, not a repository-provided multitenant web service. Separately privileged workflows publish releases and packages and run external Jules review/remediation actions. Evidence: README.md:13-41; src/lib.rs:86-165; src/legacy_doc.rs:13-50; jubarte-python/python/jubarte_redlines/mcp_server.py:373-381; .github/workflows/release.yml:230-369; .github/workflows/jules-el-conejo-review.yml:254-324.

## Assets

- Confidential document text, revisions, comments, images, embedded package parts and generated DOCX/PDF/PNG/diff/report bytes. Text-returning MCP tools intentionally disclose selected document content to the connected host; exported binary outputs are stored under the granted root. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:131-150; jubarte-python/python/jubarte_redlines/mcp_server.py:185-218; jubarte-python/python/jubarte_redlines/mcp_server.py:234-255.
- Integrity of input files, existing outputs, edit plans and source-to-edit correspondence. Legacy plans conditionally verify source_sha256; this is not unconditional authentication or authorization. Evidence: src/edit.rs:2081-2089; src/publication.rs:168-173.
- Process memory, CPU and availability while processing hostile ZIP, XML, OLE, font, raster-image and layout inputs. Default package budgets are 64 MiB compressed/per-part, 256 MiB inflated, 10000 entries and depth 256; comparison defaults instead permit 512 MiB compressed/per-part and 2 GiB inflated. Evidence: src/admission.rs:39-100; src/legacy_doc.rs:5-11; jubarte-wasm/src/lib.rs:77-96.
- Filesystem authority: native CLI ambient output paths; Python/Node host filesystem operations; MCP's separately granted, persistent directory capability; native Markdown image resource root; native renderer's installed/user font directories. These authorities are independently enforced and are not interchangeable. Evidence: src/publication.rs:146-225; src/bin/jubarte.rs:2851-2876; src/convert/font.rs:2633-2652; jubarte-python/python/jubarte_redlines/__main__.py:126-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111.
- Installed executable integrity and publication authority. Current self-update trusts HTTPS release assets plus same-release SHA-256 checksums; its compiled release-key list is empty and first-signed-release threshold is None. Release signing secret, GitHub publication token, local registry credentials, Jules API key and Codecov token are distinct sensitive capabilities. ## Trust Boundaries

- Untrusted DOCX bytes -> package admission -> OPC/XML engine: admission checks archive budgets, duplicate/case-folded names, allowed compression, encryption, structural ZIP defects, bounded inflated streams and XML policy. Normal archive opens reject zip_defects; debug intentionally uses the unchecked opener to inspect rejected packages. These are in-memory package names, not filesystem extraction destinations. Evidence: src/admission.rs:439-574; src/opc/archive.rs:15-51; docs/FILESYSTEM_PUBLICATION.md:9-12.
- Unchecked public XML -> DOM: permissive parse_xdocument explicitly does not enforce input policy. Callers must first admit package/XML or use checked APIs. Checked XML policy rejects DTD/custom entities and applies depth/tag/attribute limits; no blanket safety claim extends to raw permissive APIs. Evidence: src/xmllinq/parse.rs:19-36; src/xmllinq/parse.rs:48-65; src/wml_document.rs:50-55.
- Edit plan and document -> prepared result: schema and nonempty author checks, optional exact source SHA-256 guard, package restrictions and operation/anchor validation precede returned results. Preview and application are engine operations; publishing is separately host-owned. No user identity or human approval is established by an author string or source digest. Evidence: src/edit.rs:1740-1761; src/edit.rs:2074-2100; jubarte-python/python/jubarte_redlines/mcp_server.py:170-217.
- MCP client arguments -> root-confined document I/O: operator chooses --root, default cwd; build_server resolves it and opens native _OutputRoot once. Python containment is an early diagnostic; actual reads and publication use capability-relative operations. MCP tool hints inform hosts but do not implement per-user authorization or write approval. All connected callers share the configured root authority; overwrite is a caller-supplied option. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:54-108; jubarte-python/python/jubarte_redlines/mcp_server.py:373-381; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:146-199; docs/adoption/mcp.md:39-41.
- MCP edit/render -> root-relative outputs: docx_edit writes out_dir/clean.docx, redline.docx, patch.diff, report.json and optional redline.pdf/redline-page-NN.png; docx_render writes out_dir/page-NN.png and optional render.pdf. Publisher stages all members first but commits per file, so later commit failures can leave earlier committed members. Evidence: jubarte-python/python/jubarte_redlines/mcp_server.py:185-218; jubarte-python/python/jubarte_redlines/mcp_server.py:234-255; src/publication.rs:115-130; src/publication.rs:168-173.
- Native CLI -> ambient output paths: explicitly requested paths use publication::publish_paths, holding parent capabilities and staging bytes before commit. This intentionally does not impose MCP root confinement. Python and Node CLI wrappers own their I/O and use direct host writes; sharing the Rust parser does not share the native publisher. Evidence: src/bin/jubarte.rs:261-273; src/publication.rs:203-225; jubarte-python/python/jubarte_redlines/__main__.py:126-133; jubarte-python/python/jubarte_redlines/__main__.py:1002-1026; jubarte-wasm/cli/bin/jubarte-redlines.mjs:76-79; jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111.
- Native Markdown image targets -> local resource files: explicit resource_path overrides the Markdown parent directory, with '.' for a bare filename. image_loader canonicalizes that root, rejects inappropriate decoded targets and reads through a held OutputRoot capability. Hosted callers must separately decide what input authority to grant. Evidence: src/bin/jubarte.rs:2840-2876; src/bin/jubarte.rs:2936-2943; docs/FILESYSTEM_PUBLICATION.md:78-81.
- Native rendering -> host fonts: JUBARTE_FONT_DIR overrides platform defaults; otherwise macOS uses HOME/Library/Application Support/jubarte/fonts, Windows APPDATA/jubarte/fonts, and other platforms XDG_DATA_HOME/jubarte/fonts or HOME/.local/share/jubarte/fonts. macOS discovery also searches system/Word font paths and HOME/Library/Group Containers/UBF8T346G9.Office/FontCache/4/CloudFonts/<family>; family must be one normal path component. These reads use renderer/OS authority, not MCP document-root authority. Evidence: src/convert/font.rs:2194-2216; src/convert/font.rs:2225-2236; src/convert/font.rs:2633-2652.
- Operator self-update -> GitHub release -> executable replacement: explicit command, platform selection, version decision and optional confirmation precede delegated installation; SHA256SUMS.txt is configured and the extracted binary must be a regular file. Current compiled keys require no signature. Windows selects a ZIP archive, other published targets use tar.gz; extraction/swap internals belong to self_update and were not independently inspected in this pass. Evidence: src/update.rs:44-48; src/update.rs:186-257; src/update.rs:299-321; docs/SELF_UPDATE.md:22-41.
- Tag/release infrastructure -> public executable assets: v* tag push triggers the release workflow, which checks tag/manifests, builds with read permissions, and grants contents:write only to the release job. ZIPSIGN_PRIVATE_KEY is scoped to the signing step, decoded into RUNNER_TEMP/zipsign.XXXXXX/keyN and cleaned on exit; missing secret fails only when committed public keys exist. The GitHub token separately authorizes gh release create for github.repository with dist/* and notes.md. Evidence: .github/workflows/release.yml:15-55; .github/workflows/release.yml:230-309; .github/workflows/release.yml:356-369.
- Local release operator -> registry publication: release.sh obtains typed tag confirmation unless YES is set, pushes the release tag, separately publishes crates.io and two npm packages, and sends dist/pypi/* to PyPI using UV_PUBLISH_TOKEN. These registry/account capabilities are distinct from GitHub release signing and publication. Evidence: scripts/release.sh:875-901; scripts/release.sh:918-919; scripts/release.sh:935-956; scripts/release.sh:1042-1069.
- PR/repository content -> CI runner and external review: CI/docs execute repository-controlled build/generation code on self-hosted runners with contents:read and nonpersisted checkout credentials; runner filesystem/network isolation is not established by token permissions. Jules review separately receives JULES_API_KEY and a token with PR/check write capability; same-repository/non-Dependabot guards apply. Companion remediation additionally gates session startup to TRUSTED_USERS and configured events, but delegates AUTO_CREATE_PR with require_plan_approval:false to a pinned external action whose implementation is absent here. Evidence: .github/workflows/ci.yml:13-48; .github/workflows/docs.yml:76-99; .github/workflows/jules-review.yml:19-50; .github/workflows/jules-el-conejo-review.yml:35-52; .github/workflows/jules-el-conejo-review.yml:254-324.
- CLI plan staging has separate implementations: native write_plan uses exclusive publication; Python and Node wrappers construct PID-based partial paths and open them with ordinary truncating writes before rename. A lower-trust local actor requires shared-directory entry rights and permissive OS symlink handling to influence this boundary. Evidence: src/edit/record.rs:142-165; jubarte-python/python/jubarte_redlines/__main__.py:403-414; jubarte-wasm/cli/bin/jubarte-redlines.mjs:409-427.

## Attacker Capabilities

- A document supplier can control ZIP/XML/OPC, legacy OLE, embedded image/font and Markdown data processed by a caller. This alone does not grant process execution, ambient filesystem paths, trusted environment variables or publication credentials.
- An MCP caller can supply tool arguments and edit plans and request reads/writes within the configured root, including overwrite=true. Additional host approval is a host policy; MCP annotations are not enforcement. Authority outside the granted document root must be assessed separately from root-confined document operations.
- A local CLI caller already has the invoking account's ambient file authority. Demonstrating arbitrary paths supplied by that caller is not itself a privilege gain; a meaningful violation needs an untrusted document-driven path or another actor with less authority.
- A PR author controls proposed source/build inputs. Same-repository PRs and trusted-author remediation have materially different gates from fork PRs. Access to self-hosted runner resources depends on runner configuration and workflow admission that are not present in this source.
- An attacker controlling only unsigned release assets and their accompanying checksums is outside checksum-corruption protection; changing those assets is not assumed without a separate GitHub/release compromise prerequisite. Current shipped updater signing is disabled by explicit empty compiled keys.
- External-action internals, remote Jules/GitHub authorization, registry account protection, host filesystem ACLs, process resource limits and browser embedding policy are not established by this architecture review.

## Security Objectives

- Reject malformed or over-budget untrusted packages before expensive engine processing, while retaining checked XML policy at raw-input boundaries. Comparison's larger limits and any caller overrides must remain explicit. Evidence: src/admission.rs:63-108; src/admission.rs:439-574.
- Preserve source/edit correspondence when a source digest is supplied and refuse invalid plans before producing publishable edits. Keep author attribution separate from authentication. Evidence: src/edit.rs:1740-1761; src/edit.rs:2074-2100.
- Confine MCP document reads, parent creation and publication to the held root capability; reject unsafe export names and output symlinks; preserve no-overwrite behavior under publication races. Evidence: src/publication.rs:146-199; src/publication.rs:228-273; docs/FILESYSTEM_PUBLICATION.md:60-69.
- Keep output durability and atomicity claims aligned with implementation: native per-file staging/commit differs from multi-file transactions, directory bundles and direct-write wrapper paths; Windows directory synchronization has a documented limitation. Evidence: src/publication.rs:115-130; src/publication.rs:168-173; docs/FILESYSTEM_PUBLICATION.md:28-58; jubarte-python/python/jubarte_redlines/__main__.py:126-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111.
- Do not turn document relationships or Markdown resource targets into unrestricted host/network access. Explicit resource roots and caller-provided loaders are capabilities, not document authority. Evidence: src/bin/jubarte.rs:2851-2876; src/bin/jubarte.rs:2936-2943; src/document_comparer.rs:100-107.
- Protect executable/package publication credentials, bind released artifacts to selected versions and targets, and describe current checksum-only updater trust accurately. Evidence: src/update.rs:44-48; src/update.rs:198-257; .github/workflows/release.yml:41-49; .github/workflows/release.yml:261-309; scripts/release.sh:870-899.
- Keep review/report permissions, remediation session authority and public package publication distinct; do not infer enforcement from review prompts or MCP tool hints. Evidence: .github/workflows/jules-review.yml:28-50; .github/workflows/jules-el-conejo-review.yml:254-324.
