# Threat Model

Jubarte is an in-process Rust document engine for comparison, tracked edits, inspection, validation, sanitization, legacy DOC import, Markdown conversion, and PDF/PNG rendering. It accepts complete document bytes and returns generated bytes or reports (src/lib.rs:7-35). Hosts include the native CLI, Python/PyO3 library and CLI, browser/Node WASM bindings, Node CLI, and optional Python stdio MCP server (jubarte-python/src/lib.rs:5-15; jubarte-python/pyproject.toml:42-49; jubarte-wasm/src/lib.rs:7-28). Normal processing is local; native rendering additionally reads installed fonts and persists a font index. CLI self-update and privileged installation/publication workflows have separate network and filesystem authority. MCP supplies capability-confined document I/O, whereas CLI paths use the invoking account's ambient authority.

## Assets

- Confidential input document text, revisions, comments, embedded media, metadata, and generated document/PDF/PNG/report contents; MCP explicitly returns document text through designated tools (docs/adoption/mcp.md:69-75).
- Integrity and availability of the hosting process and document transformations: untrusted ZIP/XML, legacy DOC, fonts, and images reach native parsing/rendering code; unsafe Rust is forbidden in the engine itself (src/lib.rs; SECURITY.md:35-74).
- Filesystem contents reachable through MCP's granted root versus ambient CLI paths; OutputRoot holds an open cap_std directory capability, while publish_paths explicitly grants ambient local access (src/publication.rs:146-165,203-225).
- Native font files and persistent font-resolution metadata. Supplemental fonts resolve from JUBARTE_FONT_DIR or platform user-data directories; the index defaults to font-index.tsv beside, rather than inside, the fonts directory (src/convert/font.rs:2637-2652,3098-3107).
- Installed executable integrity during self-update. Current compiled release verification keys are empty and the first signed release is unset; updates therefore rely on release SHA-256 checksums and transport/release authority (src/update.rs:25-48,198-210,245-257).
- Release signing authority, GitHub release write authority, and separate crates.io/npm/PyPI publication credentials (.github/workflows/release.yml:230-235,261-307,356-369; scripts/release.sh:370-380,875-899).

## Trust Boundaries

- Document supplier to engine: attacker-controlled DOCX bytes cross archive admission, OPC loading, XML validation, comparison/editing, and rendering. Default admission allows 64 MiB compressed, 10,000 entries, 64 MiB per part, 256 MiB inflated, and XML depth 256; comparison permits 512 MiB compressed/per part and 2 GiB inflated (src/admission.rs:63-100). Structural ZIP checks compare central/local records and reject recorded defects; actual decompression is bounded independently of declared sizes (src/admission.rs:439-470; src/opc/archive.rs:34-51; src/opc/mod.rs:275-324).
- Caller-controlled input limits to binding configuration: Python and WASM parse overrides through InputLimitOverrides and apply them over comparison settings. Unknown keys are rejected; applications own any decision to raise or lower these limits (src/admission.rs:103-138; jubarte-python/src/lib.rs:65-79; jubarte-wasm/src/lib.rs:63-85).
- Raw XML library caller to DOM: parse_xdocument is intentionally permissive and does not enforce input policy; try_parse_xdocument_with_limits validates before constructing a DOM (src/xmllinq/parse.rs:90-135). Package admission must not be inferred for arbitrary direct XML API use.
- MCP client/model to filesystem tools: --root defaults to startup cwd and is resolved once; path arguments receive Python containment diagnostics, but actual document reads/publication use native OutputRoot (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381). OutputRoot is the enforcement owner, not MCP annotations. Read-only/destructive hints are tool metadata, and client approval remains host-owned (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55; docs/adoption/mcp.md:39-41).
- MCP publication: edits derive clean.docx, redline.docx, patch.diff and report.json below caller-selected out_dir; optional render products share that directory. Native publication validates names and stages every output before committing, rejects unsafe paths, and uses overwrite=false unless granted. Commit atomicity is per file, not across the set; errors identify already committed files (jubarte-python/python/jubarte_redlines/mcp_server.py:152-217; src/publication.rs:83-143,168-199).
- Native CLI to filesystem: document input paths are read with std::fs::read; authorized output paths are handed to ambient publication. There is no MCP-style root capability for the entire CLI (src/bin/jubarte.rs:261-273,2740-2756; src/publication.rs:203-225). Python Document.read and Node CLI similarly read explicitly supplied paths; Node writes use fs.writeFileSync (jubarte-python/python/jubarte_redlines/document.py:142-145; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-73,106-111).
- Markdown-controlled image references to local resources: the native CLI resolves --resource-path or the Markdown input's resource directory, percent-decodes targets, refuses URL schemes and escapes, then reads through a held OutputRoot capability (src/bin/jubarte.rs:2811-2870,3365-3375). Library DocxOptions instead accepts a caller-provided ImageLoader callback and defaults to no loader; callback authority belongs to the embedding application (src/markdown/mod.rs:159-170).
- Native render request to ambient font state: requested families select installed/supplemental font searches and FONT_INDEX lookups. These reads and index writes use ambient fs operations, independent of MCP document-root confinement (src/convert/font.rs:2258-2315,2637-2652,3154-3188,3213-3227). Windows system font locations derive from WINDIR, then SystemRoot, then C:\Windows, plus LOCALAPPDATA\Microsoft\Windows\Fonts (src/convert/font.rs:2855-2862).
- Edit requester to document mutation: optional source_sha256 binds a schema-1 plan to the exact source snapshot and mismatches produce STALE_SOURCE. This is a consistency guard, not authentication or approval (src/edit.rs:2074-2089; SECURITY.md:76-85).
- Maintainer debug mode to malformed packages: debug intentionally uses open_archive_unchecked so rejected archives can be inspected, unlike ordinary package loading; this materially different parser path must retain its own resource assessment (src/debug.rs:213; src/opc/archive.rs:15-20,34-51).
- Operator to self-update: only the explicit self-update command invokes update::run. It selects jandira-tech/jubarte-redlines releases, platform asset and archive binary path, SHA256SUMS.txt, optional signature verification, and an extracted-regular-file hook before delegated replacement (src/bin/jubarte.rs:4062-4073; src/update.rs:25-48,186-210,234-257,299-321).
- Maintainer/tag authority to distribution: v* tags trigger read-only build jobs and a separate contents:write release job. Optional signing receives ZIPSIGN_PRIVATE_KEY only in its step, decodes it beneath RUNNER_TEMP, and removes temporary keys on exit; GitHub publication receives GITHUB_TOKEN separately (.github/workflows/release.yml:15-21,230-307,356-369). Local release.sh independently confirms the target version unless --yes, pushes release state, and publishes using operator registry identities (scripts/release.sh:875-899).
- Effective font resources by deployment: JUBARTE_FONT_DIR overrides supplemental fonts. Otherwise macOS uses $HOME/Library/Application Support/jubarte/fonts; Linux requires HOME and uses nonempty XDG_DATA_HOME or $HOME/.local/share, then jubarte/fonts; Windows uses %APPDATA%\jubarte\fonts. All reads retain process OS authority, including during MCP rendering (src/convert/font.rs:2637-2652).
- Effective font index: nonempty JUBARTE_FONT_INDEX selects the exact caller-configured path; empty or off disables it. Otherwise the index is parent(user_font_dir)/font-index.tsv: macOS $HOME/Library/Application Support/jubarte/font-index.tsv, Linux ${XDG_DATA_HOME:-$HOME/.local/share}/jubarte/font-index.tsv, Windows %APPDATA%\jubarte\font-index.tsv. JUBARTE_FONT_DIR therefore changes the default index to its parent, not its child. A temporary sibling uses extension tsv.<pid>.tmp before rename; readers/writers are native renderer processes and index-path principals, protected by ambient OS permissions and freshness checks (src/convert/font.rs:3098-3107,3154-3188,3213-3227).
- Effective MCP products: operator grants canonical startup --root (default cwd); client-selected out_dir yields clean.docx, redline.docx, patch.diff and report.json, optionally redline.pdf and redline-page-NN.png under that capability. The client receives designated text/reports and paths; document-output writes use overwrite=false unless explicitly selected. Publication stages all bytes, then commits per file and reports partial commits (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,152-217; src/publication.rs:83-143,168-199).
- Effective release signing: ZIPSIGN_PRIVATE_KEY is a step-scoped secret reference, decoded to $RUNNER_TEMP/zipsign.XXXXXX/keyN and consumed by zipsign for dist/jubarte archives; cleanup trap removes the private files. Missing secret is tolerated only before keys/*.pub exists. GitHub publication separately consumes GITHUB_TOKEN as GH_TOKEN in the contents:write release job, targeting github.repository/GITHUB_REF_NAME. Local registry publication uses operator cargo/npm credentials and UV_PUBLISH_TOKEN, after version confirmation unless --yes (.github/workflows/release.yml:230-307,356-369; scripts/release.sh:370-380,875-899).

## Attacker Capabilities

- A document author can supply malformed DOCX/ZIP/XML, legacy DOC, embedded fonts/images, document metadata, and Markdown image destinations to an application that processes such input. The author does not thereby control environment variables, MCP root, process identity, registry credentials, or release keys.
- An MCP client can invoke exposed read and write tools using paths under the granted root, select output directories and overwrite=true, and receive intentionally exposed document contents. No per-user or per-tenant separation is established inside that root; host process launch and tool approval define caller authority.
- A malicious document can cause parsing/rendering work and family lookups, but filesystem image reads in the native Markdown loader remain separately confined to its resource root. Embedding applications may grant more authority through their own ImageLoader.
- A party controlling a release asset or privileged publication account would affect a different supply-chain boundary from an ordinary document supplier. Current checksum-only updating does not provide an independent compiled signing-key identity.
- An attacker who already controls the invoking account's CLI paths or environment has that account's authority; ordinary authorized local I/O is not itself a privilege escalation.
- A distinct local principal with write access to a shared output/plan directory may substitute directory entries while the victim CLI runs, without already being able to modify victim-owned referents elsewhere. Shared-directory use is conditional, not a default deployment assumption.

## Security Objectives

- Reject unsafe or ambiguous package identities and structurally inconsistent ZIP content before ordinary processing, and bound actual inflated bytes rather than trusting archive metadata (src/admission.rs:439-470; src/opc/mod.rs:275-324).
- Enforce active XML tag, attribute, namespace, and depth policies before checked DOM construction. Default XML caps include 1,024 attributes, 1,024-byte qualified attribute names, 64 MiB attribute values, and 128 MiB start tags (src/xmllinq/parse.rs:49-57,119-135).
- Keep MCP document reads and output publication inside its granted directory capability even when symlinks change, and preserve existing destinations unless overwrite is authorized (src/publication.rs:146-199; jubarte-python/python/jubarte_redlines/mcp_server.py:91-108).
- Keep native Markdown image loading inside the explicitly selected resource root and never fetch URL destinations through that loader (src/bin/jubarte.rs:2811-2870).
- Preserve edit snapshot consistency where hashes are supplied and report refusals before publication; distinguish transformation refusal from later filesystem commit failures (src/edit.rs:2074-2089; src/publication.rs:83-143).
- Limit self-update to an explicit operator action and platform-selected executable; verify configured checksums/signatures and reject extracted nonregular binaries before replacement (src/update.rs:186-257,299-321).
- Keep release signing, GitHub publication, and registry publication authority separate from untrusted document processing.
- Bound decoded/generated graph traversal, field depth, numeric geometry, numbering labels and correspondence work, not only compressed/input bytes. Enforce privacy postconditions for every supported encoding and relationship-selected part location; validated findings show gaps (src/markdown/from_docx/drawing.rs:1956-2007; src/markdown/view_stories.rs:773-782; src/convert/altchunk.rs:470-493; src/convert/mod.rs:13600-13615; src/scrub.rs:357-384,467-475).

## Assumptions

- No user deployment context, knowledge base, supplied threat model, or scoped inventory was provided. Source mapping does not establish a public service, network exposure, tenancy, actual installed versions, host mounts, live credentials, registry permissions, or external branch-protection settings.
- Applicable root SECURITY.md covers the engine, CLI and Python/WASM bindings. Its requirement for host process memory/CPU limits remains a caller obligation; input limits do not establish complete denial-of-service protection (SECURITY.md:9-11,71-74).
- The model distinguishes default and comparison budgets. WASM source explicitly warns that its default comparison budget can exceed a 32-bit WASM heap and instructs browser hosts to lower it (jubarte-wasm/src/lib.rs:80-85).
- Documentation says the byte-oriented toolkit uses no temporary files (src/lib.rs:7-11), while native rendering's font index writes a sibling temporary file before rename (src/convert/font.rs:3213-3227). This is a documentation qualification/disagreement about rendering side effects, not a demonstrated vulnerability. README.md:907-920 separately documents persistent font-index configuration and disabling it.
- MCP documentation promises confinement of path arguments and output products (docs/adoption/mcp.md:61-70). That capability does not sandbox the entire native renderer: installed-font reads and font-index writes retain ambient process access (src/convert/font.rs:2637-2652,3154-3188,3213-3227). Actual fonts/index environment and host permissions are unknown.
- Current compiled signing configuration is checksum-only (src/update.rs:44-48), consistent with the staged-signing description in docs/SELF_UPDATE.md:67-79. Whether CI has an optional signing secret is unknown; a configured CI secret alone would not add trusted keys to existing binaries.
- Direct permissive XML parsing and maintainer debug archive opening are deliberate exceptions; generic claims that every exposed API enforces full admission must retain these exceptions (src/xmllinq/parse.rs:90-135; src/opc/archive.rs:15-20).
- External dependency extraction/replacement internals, generated WASM equivalence, all publication call sites, browser embedding policy, and exhaustive parser/callback reachability were not fully reviewed. Architecture mapping is not completed security-audit coverage.
- Repository security policy names rdocx-opc 0.2 (SECURITY.md:89-98), while the effective dependency is oxml-opc 0.14.2 with default features disabled (Cargo.toml:102-117; src/opc/mod.rs:29-51,222-251). This stale policy statement is a documentation/configuration discrepancy, not by itself a vulnerability.
- Current bindings do not expose the ImageLoader callback claimed by the comment at src/markdown/mod.rs:159-162. Actual Python/WASM conversion wrappers use docx_options_from_json with images=None; CLI adapters reject --resource-path. The native CLI alone supplies the reviewed confined resource loader (jubarte-python/src/lib.rs:1204-1226; jubarte-wasm/src/lib.rs:1438-1449; src/markdown/mod.rs:216-283).
