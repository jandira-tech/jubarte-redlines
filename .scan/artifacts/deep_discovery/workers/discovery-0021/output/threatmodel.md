# Threat Model

Jubarte is an in-process Rust DOCX comparison, editing, inspection, repair, scrubbing and PDF/PNG rendering engine, exposed through the native CLI, PyO3/Python facade and CLI, optional Python MCP stdio server, and wasm-bindgen browser/Node byte APIs. Documents enter package admission, OPC/XML parsing and comparison/edit/render components; outputs return as bytes or are published by the host adapter. Legacy DOC conversion is a separate OLE parser (src/lib.rs:7-29; src/legacy_doc.rs:13-50; jubarte-python/src/lib.rs:5-15; jubarte-wasm/src/lib.rs:77-98). Native rendering additionally reads host fonts and maintains a persistent font index; it is not entirely filesystem-free (src/convert/font.rs:2258-2276,2637-2652,3090-3106,3213-3229). Conditional privileged paths are explicitly requested CLI self-update and maintainer release publication (src/update.rs:186-258; .github/workflows/release.yml:230-369; scripts/release.sh:886-899).

## Assets

- Confidential document text, comments, authors, embedded media and generated reports; MCP returns document-derived text and inspection data to its connected client (jubarte-python/python/jubarte_redlines/mcp_server.py:131-150,185-217).
- Integrity of source snapshots, exact edit targets, resulting tracked changes and published files. PlanV2 validates source.sha256 before resolving decisions, scope and operations (src/edit/v2_apply.rs:80-106).
- Host filesystem authority: native CLI ambient output paths; MCP's independently held directory capability; Markdown's separately granted image-resource capability (src/publication.rs:146-225; src/bin/jubarte.rs:2858-2870).
- Process memory/CPU availability across Rust, Python and WASM consumers; package admission budgets are not complete process-resource isolation (src/admission.rs:39-99; SECURITY.md:71-74).
- Host font files and persistent font-index integrity. The index records looked-up families, source-file paths and filesystem stamps, and subsequently reads those paths (src/convert/font.rs:3090-3096,3154-3171,3192-3227).
- Installed native executable, release assets, GitHub publication authority, optional signing-key material and registry publication credentials (src/update.rs:198-257; .github/workflows/release.yml:261-308,356-369; scripts/release.sh:919,935-954,1069).

## Trust Boundaries

- Document supplier to engine: supplied DOCX ZIP/XML, legacy DOC, embedded fonts/images and Markdown are data, not operator configuration. Representative comparison and rendering paths admit packages before processing; admission checks ZIP structural disagreement and package identity (src/document_comparer.rs:4907-4927; src/convert/mod.rs:773-778; src/admission.rs:439-490). Defaults are 64 MiB compressed/per-part, 256 MiB inflated, 10,000 entries and depth 256; comparison permits 512 MiB compressed/per-part and 2 GiB inflated (src/admission.rs:63-99).
- Raw XML caller to DOM: parse_xdocument is deliberately permissive and does not enforce input policy; checked try_parse_xdocument_with_limits validates before DOM construction. Do not collapse these independently exposed APIs into universal automatic admission (src/xmllinq/parse.rs:90-108,119-135). Debug is a deliberate unchecked ZIP-inspection path, distinct from production package refusal (src/opc/archive.rs:16-45; src/debug.rs:213).
- MCP client to document filesystem: --root defaults to server cwd and is expanded/resolved once. _OutputRoot holds cap-std directory authority; actual reads and publication use that authority, rather than trusting Python's earlier resolve checks. All connected callers receive the registered read/write tools; annotations are hints, not user/tenant authorization (jubarte-python/python/jubarte_redlines/mcp_server.py:54-108,373-381; jubarte-python/src/lib.rs:1244-1276; src/publication.rs:146-199).
- MCP write capability: tool-selected out_dir derives clean.docx, redline.docx, patch.diff, report.json and optional redline.pdf/redline-page-NN.png beneath the root. Native publication rejects unsafe relative names, escaping resolution and output symlinks; overwrite must be requested. Staging is validated before commits, but atomicity is per file and failures can report prior committed files (jubarte-python/python/jubarte_redlines/mcp_server.py:185-217; src/publication.rs:123-130,168-199,228-250,431-469,558-569).
- CLI operator to ambient filesystem: native publication holds each explicitly selected parent directory, stages bytes in parent/.jubarte-<uuid>.partial/bytes and installs by rename or no-clobber hard link. This grants ambient local access, unlike OutputRoot. Python and npm CLIs instead perform their own ambient direct writes after overwrite checks; shared command grammar does not establish equal filesystem guarantees (src/bin/jubarte.rs:261-273; src/publication.rs:203-225,480-505,558-569; jubarte-python/python/jubarte_redlines/__main__.py:101-103,126-133,510-517; jubarte-wasm/cli/bin/jubarte-redlines.mjs:76-79,106-111).
- Markdown image reference to host file: native CLI --resource-path overrides the Markdown source's parent directory, defaulting to '.'. URL-like targets are refused; decoded/canonicalized paths must resolve inside that root and actual reads use its held OutputRoot capability. This is separate from document output publication (src/bin/jubarte.rs:2669-2677,2811-2848,2858-2870,2937-2943).
- Native renderer to ambient font resources: JUBARTE_FONT_DIR overrides platform user-font locations; system/Word/Office cloud-font directories are also searched. JUBARTE_FONT_INDEX overrides the index path; empty/off disables it; otherwise the default is user_font_dir().parent()/font-index.tsv. Index writes use sibling font-index.tsv.<pid>.tmp followed by rename, outside the MCP document-root capability when the configured font location is outside it (src/convert/font.rs:2228-2235,2281-2315,2637-2652,2855-2862,3100-3106,3213-3229). Effective default font directories are macOS $HOME/Library/Application Support/jubarte/fonts, Linux $XDG_DATA_HOME/jubarte/fonts else $HOME/.local/share/jubarte/fonts, Windows $APPDATA/jubarte/fonts. The default index is one directory above, font-index.tsv. Windows system font roots use WINDIR else SystemRoot else C:\Windows, plus LOCALAPPDATA/Microsoft/Windows/Fonts; Office cloud cache is $HOME/Library/Group Containers/UBF8T346G9.Office/FontCache/4/CloudFonts.
- JS host to WASM: compare accepts borrowed document bytes plus JSON limit overrides and returns bytes/errors. Browser/Node package entrypoints are separate generated loaders; native publication is cfg-excluded on wasm32. Node CLI filesystem authority belongs to its JS adapter, not to the WASM byte API (jubarte-wasm/src/lib.rs:65-98; jubarte-wasm/npm/package.json:34-75; src/lib.rs:163-165; jubarte-wasm/cli/bin/jubarte-redlines.mjs:16-21,52-55,106-111).
- Operator to updater to release infrastructure: only explicit self-update enters this flow. Fixed repository jandira-tech/jubarte-redlines, target-specific asset and SHA256SUMS.txt feed self_update; --check does not install; confirmation or --yes precedes installation. RELEASE_KEYS is empty and FIRST_SIGNED_RELEASE is None, so this checkout enforces checksum-only updates. A regular-file verification hook rejects extracted symlink/nonregular binaries before swap (src/update.rs:25-48,186-210,223-257,307-321). Windows enables ZIP extraction while other shipped targets use tar.gz (Cargo.toml:144-155; docs/SELF_UPDATE.md:25-36). Archive assets are jubarte-<version>-<target>.tar.gz or .zip, containing jubarte-<version>-<target>/jubarte[.exe]; the independent architecture reviewer inspected self_update 1.3.1 common builder lines1106-1108 and found the install destination defaults to std::env::current_exe(). No actual deployed executable path was queried.
- Maintainer/tag authority to public distribution: v* tags trigger release builds; build jobs have contents:read and release job contents:write. Optional ZIPSIGN_PRIVATE_KEY is provided to the signing step, decoded under RUNNER_TEMP/zipsign.<random>/keyN and removed by trap; signed archives precede checksum generation. GH_TOKEN references GITHUB_TOKEN for gh release create, publishing dist/* to the tagged repository release. The maintainer script separately publishes crates.io jubarte-redlines, npm jubarte-wasm and jubarte-redlines, and PyPI jubarte-redlines using operator-held credentials (.github/workflows/release.yml:15-21,230-308,317-321,356-369; scripts/release.sh:886-899,919,935-954,1069).
- Legacy DOC logical mapping and field-state boundaries are distinct from ZIP/XML policy: the convert branch materializes DOCX only after legacy decoding, and public legacy read directly expands pieces and parses field state (src/bin/jubarte.rs:3125-3144; src/legacy_doc.rs:180-215,1084-1109,1181-1221,1591-1620). Public scrub::leaks performs bounded ZIP reads but invokes raw XML DOM construction separately (src/scrub.rs:403-469,527-530). These are source-backed availability scenarios retained as findings, without assuming remote deployment.

## Attacker Capabilities

- A document supplier may control document package bytes, XML, embedded fonts/images, Markdown and edit-plan content passed by a host. The supplier does not thereby control environment variables, the MCP root, arbitrary CLI flags, release assets, signing keys or operator credentials (SECURITY.md:38-74; jubarte-python/python/jubarte_redlines/mcp_server.py:67-87; src/update.rs:25-48).
- An authorized MCP client can request registered document reads and writes anywhere allowed by the granted root and tool parameters, including overwrite=true. This already-authorized root access is not a new privilege; a meaningful failure would cross the root or other independently enforced capability (jubarte-python/python/jubarte_redlines/mcp_server.py:75-108,152-160).
- A caller embedding the Rust/Python library already has its host process's authority. Parser-input compromise could add unauthorized access or computation, but no repository evidence establishes an internet-facing or multitenant deployment (src/lib.rs:7-11; jubarte-python/src/lib.rs:5-15).
- Release-asset replacement becomes relevant only when an operator requests an update; checksum-only authenticity depends on the trusted release channel because an asset replacer can also replace its adjacent checksum. Signing-key or release-workflow compromise is a distinct privileged prerequisite (docs/SELF_UPDATE.md:59-80; src/update.rs:44-48,245-257).
- A separate local filesystem adversary may control entries in an operator-selected shared output/plan directory without permission to write victim-owned files elsewhere. Direct writes and predictable staging add capability if they follow those entries; private directories prevent this scenario (jubarte-python/python/jubarte_redlines/__main__.py:126-133,407-411; jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-112,420-423).

## Security Objectives

- Treat the inputs named by repository policy as untrusted; preserve admission, ZIP/XML constraints and checked parsing boundaries, and require host memory/CPU limits rather than treating input budgets as isolation (SECURITY.md:38-74; src/admission.rs:63-99; src/xmllinq/parse.rs:129-135).
- Keep untrusted document processing from fetching external relationships or executing document macros; retain the policy's distinction between permitted ambient host resources and external document references (SECURITY.md:71-85; src/admission.rs:22; src/opc/mod.rs:778). The engine crate forbids unsafe Rust; this does not claim dependency-wide absence of unsafe code (src/lib.rs:86).
- Preserve edit-source identity and exact scope before mutation, then preserve publication target and payload integrity with the guarantees owned by the particular adapter (src/edit/v2_apply.rs:84-106; src/publication.rs:168-173,538-569).
- Confine MCP document reads/writes and native Markdown image reads to their independently granted capabilities; do not advertise these as whole-process confinement of native rendering (src/publication.rs:146-199; src/bin/jubarte.rs:2858-2870; src/convert/font.rs:3100-3106,3213-3229).
- Permit executable replacement and public package publication only through the separately authorized operator/maintainer workflows; preserve platform/asset selection, checksum verification and the actual configured signature policy (src/update.rs:186-257; .github/workflows/release.yml:261-308,356-369; scripts/release.sh:886-899).

## Assumptions

- No supplied threat model, deployment context or knowledge base. Root SECURITY.md was resolved as applicable; no nested SECURITY.md was found. Architecture review was independent, offline/read-only, without application execution, network, triggering inputs or a vulnerability audit.
- No observed server deployment, HTTP listener, authentication layer, tenant isolation, process sandbox or host CPU/memory quotas is established. The supported MCP entrypoint uses stdio; its host must choose an appropriate root and trust connected clients accordingly (jubarte-python/python/jubarte_redlines/mcp_server.py:373-381; SECURITY.md:72-85).
- Documentation qualification: src/lib.rs:9-11 describes every function as package-byte processing with no temporary files, and MCP prose says every path/output is under root (jubarte-python/python/jubarte_redlines/mcp_server.py:7-9). Native rendering actually reads ambient fonts and writes the persistent font index and sibling temporary file (src/convert/font.rs:2637-2652,3100-3106,3213-3229). Document capability confinement remains distinct from those renderer side effects.
- Documentation qualification: Python/npm CLI descriptions advertise the same output files and behavior as the native binary, but their direct path writes do not inherit native cap-std staging and no-clobber installation. Parent review established shared-directory attacker prerequisites for separate retained findings (jubarte-python/python/jubarte_redlines/__main__.py:5-7,126-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:6-8,106-111; src/publication.rs:558-569).
- Documentation qualification: signing support is implemented but currently inactive; do not describe releases from this checkout as signature-required. docs/SELF_UPDATE.md:69-80 agrees with empty RELEASE_KEYS and FIRST_SIGNED_RELEASE=None in src/update.rs:44-48.
- Documentation disagreement: docs/SELF_UPDATE.md:22-24 says GH_TOKEN/GITHUB_TOKEN lift updater request limits; src/update.rs:198-211 configures neither auth_token nor auth_token_from_env. Independent reviewer inspected cached self_update 1.3.1 defaults None/false, so ambient updater token transmission is not established. Supporting dependency evidence from reviewer: GitHub backend lines358-359 and common builder defaults lines1027-1053; parent has not fully audited the dependency.
- jubarte-rust-inproc is a developer benchmark worker, not a separate production service: stdin COMPARE paths cause ambient file reads and output writes under harness authority (jubarte-rust-inproc/src/main.rs:5-20,91-99).
- Registry/package-manager authentication, actual signing-secret availability, branch/tag protection and deployments outside this repository remain external prerequisites; the model does not establish their live settings.
- Input resource constraints are byte/depth/count based; semantic renderer amplification and relationship normalization are investigated separately. One focused investigator failed to return; parent continued source validation directly.
