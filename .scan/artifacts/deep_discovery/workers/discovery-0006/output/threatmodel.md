# Threat Model

Jubarte is an in-process Rust DOCX comparison, revision, inspection, editing and rendering engine, exposed through a native CLI, PyO3 Python library/CLI, wasm-bindgen browser/Node APIs, a Node CLI and an optional Python MCP stdio server (README.md:12-16; src/lib.rs:15-35; jubarte-python/python/jubarte_redlines/mcp_server.py:373-381). Normal processing consumes document bytes and produces document bytes or views; it does not automate Word or LibreOffice (src/lib.rs:7-11). Filesystem authority differs materially: the native CLI publishes caller-selected ambient paths through staged publication; Python and Node CLI helpers use ordinary ambient file writes; the MCP adapter holds a root directory capability for input reads and output publication; WASM byte APIs do not expose native publication (src/bin/jubarte.rs:261-273; src/publication.rs:153-225; jubarte-python/python/jubarte_redlines/__main__.py:126-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:106-111; src/lib.rs:163-165). Explicit self-update and release workflows independently exercise network, executable-replacement, signing and publication authority.

## Assets

- Confidential source DOCX, legacy DOC and Markdown content; revision authors, comments, metadata, media, generated agent views, reports, patches, clean documents and redlines (src/lib.rs:15-30; jubarte-python/python/jubarte_redlines/mcp_server.py:185-217). MCP edit exports have distinct derived destinations under the selected root and out_dir: clean.docx, redline.docx, patch.diff, report.json, optionally redline.pdf and redline-page-NN.png.
- Integrity of edit targets and their source revision. EditPlan.source_sha256 is optional, and when supplied the actual source hash must match or STALE_SOURCE is returned; author labels are document data rather than authenticated identities (src/edit.rs:97-108,2081-2092).
- Host filesystem content reachable with the invoking OS account; MCP's selected root directory capability; CLI Markdown resource roots; ambient native renderer font directories; output staging and existing output bytes (src/publication.rs:153-199,203-225,421-505; src/bin/jubarte.rs:2858-2871,2937-2943; src/convert/font.rs:2633-2652).
- Availability of the embedding Python process, native process or browser/Node WASM instance. Ordinary admission defaults allow 64 MiB compressed/per-part, 256 MiB inflated total, 10,000 entries and XML depth 256; comparison defaults instead allow 512 MiB compressed/per-part and 2 GiB inflated total (src/admission.rs:63-100).
- Installed jubarte executable integrity and the authority to replace it. Current trusted release-key configuration is empty, so the updater uses release checksums rather than mandatory signatures (src/update.rs:44-48,198-210,245-257).
- Release signing secret reference ZIPSIGN_PRIVATE_KEY, GitHub release publication token reference GITHUB_TOKEN, local PyPI token reference UV_PUBLISH_TOKEN and local npm/Cargo publishing credentials. These are separate capabilities and are not document-processing credentials (.github/workflows/release.yml:230-275,278-307,356-369; scripts/release.sh:919,934-954,1069).
- GitHub review comments/checks and external Jules session capability. Ordinary reviewer and companion-remediation workflows receive different permissions and apply different caller gates (.github/workflows/jules-review.yml:19-50; .github/workflows/jules-el-conejo-review.yml:35-52,259-272,320-324).

## Trust Boundaries

- Untrusted package bytes cross into ZIP/OPC/XML parsing and rendering. Admission prechecks budgets, checks duplicate entries and shared ZIP structural defects, and bounds actual inflated reads rather than trusting declared sizes (src/admission.rs:439-470,531-535). The shared checked ZIP opener rejects defects; debug is an intentional unchecked diagnostic exception (src/opc/archive.rs:15-19,34-51). Checked XML APIs and raw permissive DOM APIs are separate caller contracts, explicitly distinguished by SECURITY.md:51-65.
- Untrusted legacy DOC is a separate OLE/FIB/piece-table parsing path, subsequently converted into Markdown/DOCX; it is not covered merely by identifying DOCX ZIP admission (src/legacy_doc.rs:13-50). Embedded fonts, image decoders and layout are additional native parser surfaces identified by Cargo.toml:107-110.
- Native CLI operators select ambient input/output paths. src/bin/jubarte.rs:261-273 invokes publication::publish_paths, whose root=None backend opens output parents with ambient authority (src/publication.rs:203-225,431-446). Outputs stage beside their destination in .jubarte-<UUID>.partial/bytes, with Unix staging directory mode 0700 and exclusive creation (src/publication.rs:472-505). Publication stages all files first but commits per file; failures can leave named committed outputs, and Windows directory synchronization is intentionally a no-op (src/publication.rs:100-130,168-174,387-405). This is not an all-files transaction.
- Python and Node CLI callers retain ambient local filesystem authority. Python's _read_side consumes caller paths and _write calls Path.write_bytes; Node's read and write helpers call fs.readFileSync/writeFileSync (jubarte-python/python/jubarte_redlines/__main__.py:73-83,126-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:52-56,106-111). Native staged-publication properties cannot be assumed for these helpers.
- The MCP operator grants a directory root once; a connected stdio client can invoke all registered read/write tools within that grant. --root defaults to current working directory, is expanded/resolved, and must be a directory; no HTTP listener or application authentication is configured in this entrypoint (jubarte-python/python/jubarte_redlines/mcp_server.py:373-381). Python containment checks are early diagnostics; actual reads and publications use _native._OutputRoot, backed by cap_std directory authority and portable relative-write validation (jubarte-python/python/jubarte_redlines/mcp_server.py:69-108; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:153-199,228-273,431-463). overwrite is a per-call replacement capability, defaulting false. ToolAnnotations are metadata, not a separate authorization layer (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,153-160).
- CLI Markdown image targets cross into local filesystem reads only through a selected resource root: explicit --resource-path wins, otherwise the Markdown file's parent, otherwise '.' (src/bin/jubarte.rs:2937-2943). The loader canonicalizes and holds that directory capability, applies image policy and reads relative to the capability; URLs are not fetched by this loader (src/bin/jubarte.rs:2851-2877). This capability is separate from output publication authority.
- Native renderer font discovery is ambient OS-account access, independent of MCP's document/output root. JUBARTE_FONT_DIR overrides per-user locations; absent it, Windows uses APPDATA/jubarte/fonts, macOS HOME/Library/Application Support/jubarte/fonts, and other native platforms XDG_DATA_HOME/jubarte/fonts or HOME/.local/share/jubarte/fonts (src/convert/font.rs:2633-2652). Native discovery also examines named system/Word font directories and HOME/Library/Group Containers/UBF8T346G9.Office/FontCache/4/CloudFonts/<family>; the document-supplied family must be a single normal path component for that derived cloud directory (src/convert/font.rs:2225-2236,2281-2309).
- Browser/Node WASM callers pass byte arrays and JSON options into the engine. The bindings disable default engine features, omit native publication on wasm32 and support comparison-budget overrides; the binding explicitly warns that its 2 GiB inflated default can exceed practical WASM heap capacity (jubarte-wasm/Cargo.toml:18-23; src/lib.rs:163-165; jubarte-wasm/src/lib.rs:63-97). Hosting applications own admission tuning, upload authorization, origin policy, worker isolation and persistence.
- Explicit jubarte self-update crosses from GitHub release metadata/assets into executable replacement. Repo is jandira-tech/jubarte-redlines; the chosen archive member is jubarte-<version>-<platform>/jubarte[.exe]; SHA256SUMS.txt is configured; extracted binary must lstat as a regular file (src/update.rs:25-27,91-109,198-210,299-321). Without --check/--yes, noninteractive runs stop before lookup; installation requires confirmation unless --yes; explicitly selected versions may downgrade (src/update.rs:120-125,144-160,234-247). Current RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None mean signature enforcement is inactive (src/update.rs:44-48,274-285).
- Tag-driven GitHub release automation builds platform archives/wheels with read-only job permissions, then a separate contents:write job signs when configured, computes checksums and publishes dist/* to the triggering tag's release (.github/workflows/release.yml:15-21,51-89,230-275,295-321,356-369). The signing secret is scoped to the signing step, decoded into RUNNER_TEMP/zipsign.<random>/keyN and removed by an EXIT trap; the signing tool and runner are recipients of this authority (.github/workflows/release.yml:261-307).
- The local release script separately publishes the Rust package, both npm packages and PyPI artifacts. Typed version confirmation precedes pushing unless YES is set, then each registry operation uses its own tool/account authority (scripts/release.sh:877-919,929-959,1063-1069). The script calls a downstream app checkout, but that application's implementation is absent from this repository and is not included as inspected architecture (scripts/release.sh:141-175).
- PR automation crosses repository-controlled PR source, descriptions and tool output into external actions and agent sessions. The normal review workflow excludes fork/Dependabot PRs and grants contents:read, pull-requests:write and checks:write; companion remediation additionally gates session creation on TRUSTED_USERS=['arthrod'] and selected events, uses AUTO_CREATE_PR and require_plan_approval=false (.github/workflows/jules-review.yml:19-50; .github/workflows/jules-el-conejo-review.yml:35-52,259-272,320-324). External action internals, Jules integration permissions and runtime restrictions are not present here.
- CI/docs workflows execute checked-out repository code on self-hosted runners for pull_request events. Workflow token permissions are contents:read and checkout disables persisted credentials, but host filesystem, network, persistent-state isolation and runner admission controls are external deployment controls (.github/workflows/ci.yml:13-40,72-99; .github/workflows/docs.yml:42-86,98-99).
- Validated audit refinements: package admission's extension-based selection does not cover relationship-resolved notes with non-XML suffixes (src/admission.rs:533-570; src/document_comparer.rs:6318-6328,6461-6479). Admission also ignores DTD while the raw DOM disagrees on declaration boundaries (src/admission.rs:798-820; src/xmllinq/parse.rs:539-547,660-662). These are findings, not assertions that the intended policy is fully enforced.

## Attacker Capabilities

- A document supplier can control document bytes, ZIP/XML structure, relationships, embedded media/fonts, Markdown content and document metadata that callers choose to process. This does not grant control of trusted environment variables, arbitrary operator-selected paths, release credentials or executable installation decisions.
- A connected MCP client can choose tool arguments, source files and output destinations inside the operator-granted root and request overwrite=true. These are existing tool capabilities; new security impact would require exceeding the root grant, unintended disclosure to another actor, bypassing promised replacement restrictions or attacking the host process.
- A library/WASM caller can choose API input bytes and exposed options, including input-limit overrides. A hosted service may expose a narrower subset, but no such service deployment or tenant model is established by this repository.
- A PR contributor can control PR source/text subject to repository contribution permissions and workflow event gates. Same-repository authorship, trusted-user session gates, self-hosted runner admission and external agent authority must be evaluated separately; fork authors are not automatically authorized for secret-bearing Jules workflows.
- Release-asset modification or privileged tag/release control is a distinct prerequisite for updater supply-chain impact. Ordinary document control does not confer it; checksums fetched with release assets do not independently authenticate the publisher (docs/SELF_UPDATE.md:59-80).

## Security Objectives

- Reject malformed/unsupported packages and enforce active resource limits before expensive parsing; do not interpret archive member names as arbitrary extraction paths or execute document macros. Checked ZIP admission and XML policy are component controls, while process CPU/memory isolation remains a host obligation (src/admission.rs:13-28,439-470,531-535; SECURITY.md:69-74).
- Preserve MCP document read/output confinement through held directory capabilities despite path changes, and reject unsafe output paths and output symlinks rather than relying solely on Python resolve checks (jubarte-python/python/jubarte_redlines/mcp_server.py:75-108; src/publication.rs:153-199,228-273,431-463).
- Preserve existing output bytes through staging failures; report partial commits and durability uncertainty accurately. Do not claim atomic publication across multiple files or native publication parity for Python/Node write helpers (src/publication.rs:100-130,168-174,387-405).
- Keep Markdown image reads inside the selected resource root and avoid automatic network fetches from image targets (src/bin/jubarte.rs:2851-2877,2937-2943). Keep this control distinct from native font discovery and output confinement.
- Reject stale edit snapshots when source_sha256 is supplied, and preserve the documented caller obligation when it is omitted (src/edit.rs:103-106,2081-2089). Revision author fields and SHA-1/FNV comparison keys must not become authentication claims (SECURITY.md:76-85).
- Install only the explicitly selected supported-platform release artifact after applicable checksum, signature-policy and regular-file checks, with the documented interaction/downgrade policy (src/update.rs:91-125,144-160,198-257,307-321).
- Keep release signing, GitHub release writes, registry publishing, PR comments/checks and external remediation sessions as independent capabilities with their own event/account gates and external permission prerequisites.
- When docprops scrubbing is requested, remove identifying properties by authoritative OPC metadata target before returning outgoing package bytes; conventional-path-only sanitation misses relocated parts (src/scrub.rs:357-384; src/opc/mod.rs:655-667).

- SECURITY.md is repository policy data, not evidence that every implementation guarantee has been exhaustively verified. Its latest-release support, untrusted-input policy and process-limit requirement apply as stated; this pass did not run tests or application code.
- Signing documentation describes both signature-capable future releases and the checksum-only current phase. Actual constants remain RELEASE_KEYS=[] and FIRST_SIGNED_RELEASE=None; therefore signature support must not be described as current mandatory verification (docs/SELF_UPDATE.md:59-80; src/update.rs:44-48,245-249,274-285). This is an explicit staged configuration rather than a newly established vulnerability.
- Documentation/configuration disagreement: docs/SELF_UPDATE.md:22-24 says GH_TOKEN/GITHUB_TOKEN are used when set. src/update.rs:198-211 configures neither auth_token nor auth_token_from_env. Offline architecture review of the locked cached self_update 1.3.1 dependency showed CommonBuilderConfig defaults auth_token=None and auth_token_from_env=false, with environment lookup opt-in. Preserve both the documentation claim and effective anonymous configuration; impact here is authentication/rate-budget behavior, not evidence of token disclosure. Dependency evidence: cached self_update-1.3.1/src/backends/common.rs:1027-1053 and backends/github.rs:391-406; repository version anchor Cargo.lock:2552-2553.
- The broad library statement that entry points admit input (src/lib.rs:30) has documented exceptions: debug intentionally opens unchecked ZIPs and raw parse_xdocument is not an input-policy API (src/opc/archive.rs:15-19; SECURITY.md:54-65). Treat these as distinct interfaces rather than projecting ordinary admission guarantees onto all public helpers.
- MCP root, explicit Markdown resource root, environment-selected font root, output paths and installed binary path are runtime/operator choices absent from supplied deployment context. The configuration chains and derived child names are established; exact machine-specific absolute values are not.
- Native font lookup uses ambient directories even when the hosting MCP adapter confines document and output paths. MCP root confinement is not a whole-process filesystem sandbox (src/convert/font.rs:2228-2234,2281-2309,2637-2652).
- WASM/native bindings reuse the engine but have materially different host capabilities and budgets. Browser resource isolation and remote-service limits are external caller obligations; the WASM binding explicitly warns about default comparison memory limits (jubarte-wasm/src/lib.rs:80-85).
- The external Jules actions, hosted service permissions, self-hosted runner lifecycle/network/filesystem controls and downstream jubarte-app implementation were not available as inspected repository source. Workflow configuration establishes grants and gates but does not prove external enforcement.
- This independent architecture review is not completed security-audit coverage and contains no validated vulnerability findings.
