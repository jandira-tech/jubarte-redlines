# Threat Model

Jubarte is an in-process Rust DOCX comparison, inspection, editing, revision-resolution and rendering engine, exposed through a native CLI, PyO3 Python bindings, wasm-bindgen Node/browser bindings, and an optional Python MCP server over stdio. Documents flow from caller-owned bytes or local files through ZIP/OPC admission, XML/DOM processing, comparison/edit/layout components, then back to bytes, stdout or explicitly selected output paths. Python and WASM reuse the root engine with default features disabled, excluding its self-updater (README.md:14-18; src/lib.rs:96-165; jubarte-python/Cargo.toml:35-39; jubarte-wasm/Cargo.toml:18-32). MCP grants a persistent filesystem capability rooted at --root, defaulting to startup cwd (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381). Native rendering independently discovers host fonts and maintains a font index outside that document-root capability (src/convert/mod.rs:806-857; src/convert/font.rs:2637-2652,3100-3106,3213-3227). Native self-update and maintainer release/publication are conditional privileged workflows (src/update.rs:186-257; scripts/release.sh:875-919; .github/workflows/release.yml:230-269).

## Assets

- Confidential document text, comments, revisions, embedded media/fonts and metadata; emitted Markdown, snapshots, patches, reports, PDFs and PNGs can contain that content. MCP reads return document content; edit/render writes named artifacts (jubarte-python/python/jubarte_redlines/mcp_server.py:131-150,185-217,234-255).
- Integrity of source snapshots and authorized clean/tracked output. V1 plans optionally bind source_sha256; V2 requires matching source.sha256. Native CLI rechecks named source against preparation bytes (src/edit.rs:99-106,2073-2105; src/edit/v2_apply.rs:84-99; src/bin/jubarte.rs:1642-1655).
- Host CPU, memory and filesystem authority exercised by parsers, image/font decoders and publication. Default admission permits 64 MiB compressed/per part, 256 MiB total inflated, 10,000 entries and depth 256; comparison permits 512 MiB compressed/per part and 2 GiB total (src/admission.rs:63-99).
- MCP root document/output files; native host fonts, user font folders and font-index.tsv are separately authorized resources (src/publication.rs:146-199; src/convert/font.rs:2281-2315,2637-2652,3100-3106).
- Installed native executable and package integrity. Updater currently trusts release-adjacent SHA256SUMS.txt; compiled signing keys are empty and first-signed-release is None (src/update.rs:25-48,198-210,245-257).
- Distinct publication credentials: CI ZIPSIGN_PRIVATE_KEY, release-job GITHUB_TOKEN, operator Cargo credentials, npm login/NPM_OTP and UV_PUBLISH_TOKEN (.github/workflows/release.yml:234-235,261-290,356-369; scripts/release.sh:374-380,919,934-956,1069).

## Trust Boundaries

- Untrusted DOCX crosses ZIP/OPC admission: pre-index budgets, ZIP structural/canonical-name checks, encryption/compression refusal, bounded inflation and XML policy (src/admission.rs:439-569). OPC independently checks archive defects, bounded reads and case-insensitive duplicates (src/opc/archive.rs:34-51; src/opc/mod.rs:282-350,497-524). Rendering admits before normalization/layout (src/convert/mod.rs:769-798).
- Raw XML parse_xdocument intentionally skips input policy; try_parse_xdocument_with_limits validates first. Callers of raw API own prior admission (src/xmllinq/parse.rs:88-135). Tag defaults are 1,024 attributes, 1,024-byte names, 64 MiB values and 128 MiB tags (src/xmllinq/parse.rs:48-65).
- Edit plans cross into mutation using schema/source checks, exact anchors and preparation gates; author labels are not authenticated identities. V1 rejects macro-bearing/signed packages and checks optional source hash; V2 rejects mismatching source hash before operation resolution (src/edit.rs:97-108,2073-2105; src/edit/v2_apply.rs:84-111).
- Native CLI uses ambient operator filesystem authority. publish_paths holds parents, stages/verifies bytes and installs via overwrite rename or no-clobber hard link, atomic per file rather than per set (src/publication.rs:168-174,203-225,419-505,534-570). Python/Node ordinary CLI path writes have different controls (jubarte-python/python/jubarte_redlines/__main__.py:101-133; jubarte-wasm/cli/bin/jubarte-redlines.mjs:76-80,106-111).
- MCP client arguments cross a server-granted directory capability. Startup resolves --root once; diagnostics precede capability-relative actual reads/writes. Portable relative-name checks, overwrite opt-in and output-symlink refusal apply (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381; jubarte-python/src/lib.rs:1244-1278; src/publication.rs:146-199,228-273,431-463). All connected stdio clients receive registered tools; annotations are hints rather than per-user authorization (mcp_server.py:54-55,126-159,258-277, relative to jubarte-python/python/jubarte_redlines).
- Native Markdown image loading separately grants --resource-path, otherwise Markdown parent or '.'. Percent decoding precedes scheme/containment checks and capability reads; operator chooses trusted root (src/bin/jubarte.rs:2811-2877,2936-2943). Python/Node reject resource_path; byte conversion defaults to no image callback (jubarte-python/python/jubarte_redlines/__main__.py:1057-1064; jubarte-wasm/cli/bin/jubarte-redlines.mjs:724-727; src/markdown/mod.rs:159-198,226).
- Native font discovery reads system/Word, macOS Office CloudFonts/<family>, and configured/per-user fonts. Cloud family must be a single normal component. Index-named files are read after length/mtime checks; ambient cache persistence is independent of MCP root (src/convert/mod.rs:806-857; src/convert/font.rs:2225-2236,2258-2315,2637-2652,2855-2862,3154-3188,3213-3227).
- Maintainer debug intentionally uses open_archive_unchecked after budget preflight, reports defects and continues, unlike ordinary refusal paths (src/debug.rs:206-222; src/opc/archive.rs:15-19).
- Native updater downloads fixed repository/platform release assets, checks adjacent checksum and extracted regular-file type, and requires terminal confirmation or --yes; --check does not install. Empty signing keys disable required signatures (src/update.rs:25-48,91-108,120-125,198-257,299-320).
- Tag CI separates read-only build from contents:write release. Signing-step secret is decoded below RUNNER_TEMP/zipsign.<random>/keyN and cleaned on exit. Separate GitHub token publishes dist/*; operator script independently publishes Cargo, npm engine/CLI and PyPI (.github/workflows/release.yml:15-21,54-55,230-290,303-321,356-369; scripts/release.sh:875-919,934-956,1039-1069).
- Contributor pull_request jobs check out contributor code onto self-hosted runners also selected by main pushes; their local action configures a private mbx cache endpoint and documents persistent checkout/store use (.github/workflows/ci.yml:13-16,34-48,72-99; .github/actions/mbx/action.yml:8-12,20-38). External approval and runner isolation controls remain unknown.
- Legacy DOC crosses OLE/FIB/piece decoding then field-block processing before Markdown/DOCX generation; physical chain bounds do not establish logical story or field-work limits (src/legacy_doc.rs:180-215,1090-1225,1596-1619). Embedded WMF crosses binary record decoding to owned text and raster output; MAX_SIDE bounds only pixels (src/convert/metafile.rs:25-31,477-489,603-620,692-700).

## Attacker Capabilities

- Input suppliers control DOCX ZIP/XML, embedded fonts/images, legacy DOC, Markdown and caller-accepted edit plans, without automatically controlling trusted environment, arbitrary local paths, credentials or releases (SECURITY.md:38-74; src/admission.rs:439-569; src/legacy_doc.rs:13-50).
- MCP clients select in-root documents/operations, receive derived content and request overwrite=true in-root writes; those intended grants are not additional compromise (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,131-217,258-277).
- CLI/library callers already control invocation and explicitly supplied paths under their OS account; escalation requires authority beyond these grants (src/publication.rs:203-225; src/bin/jubarte.rs:2851-2866). A separate local principal may control entries in a shared output/plan directory.
- Release/registry/signing compromise is separate authority; checksum-only updates do not authenticate against a compiled key, but document control does not imply release control (src/update.rs:44-48,245-257; docs/SELF_UPDATE.md:59-80).
- Public-service/tenant effects require deployment separation not established by inspected source; no public HTTP service was established (jubarte-python/python/jubarte_redlines/mcp_server.py:373-381; SECURITY.md:84-85).
- PR authors control checked-out build scripts/tests/local actions for permitted CI jobs; GitHub workflow approval policy and actual runner lifecycle are external prerequisites (.github/workflows/ci.yml:13-48).

## Security Objectives

- Bound untrusted package processing and reject ambiguous archive names/interpretations before higher-level processing (src/admission.rs:439-569; src/opc/archive.rs:34-51).
- Keep external relationships from fetching network resources and Markdown image reads within explicitly granted resource roots (SECURITY.md:70-74; src/convert/mod.rs:789-793,21285-21298; src/bin/jubarte.rs:2811-2877).
- Bind prepared edits to intended immutable source and refuse before publication; caller author labels are not authentication (src/edit.rs:99-108,2073-2105; src/edit/v2_apply.rs:84-111; src/bin/jubarte.rs:1642-1655).
- Maintain MCP I/O confinement through actual directory handles and no-clobber unless replacement is requested (src/publication.rs:146-199,431-463,558-570).
- Preserve output integrity and honestly report partial commits/durability uncertainty; publication is per-file (src/publication.rs:110-143,168-174).
- Restrict executable replacement and registry publication to explicit operator workflows, matching platforms and verification controls; protect each signing/publication credential independently (src/update.rs:91-125,198-257,299-320; .github/workflows/release.yml:261-290,356-369; scripts/release.sh:875-919,934-956,1069).
- Keep untrusted PR execution separate from persistent trusted runner state/private services (.github/actions/mbx/action.yml:8-12,27-38).

## Assumptions

- Read-only architecture/static inspection; no application execution, external-service checks or runtime reproduction. Input budgets are not a proof against all DoS; hosts remain responsible for process limits (SECURITY.md:70-74).
- MCP says tools only touch files under root (jubarte-python/python/jubarte_redlines/mcp_server.py:7-9,67-68), but render calls native installed-font discovery and index persistence outside that root (same file:234-236; src/convert/mod.rs:857; src/convert/font.rs:2637-2652,3100-3106,3183-3188,3213-3227). Tool document/output I/O is confined; broad documentation guarantee is narrower in implementation. No exploit established merely from font use.
- Default font index is parent(JUBARTE_FONT_DIR)/font-index.tsv when overridden; otherwise macOS $HOME/Library/Application Support/jubarte/font-index.tsv, Linux ${XDG_DATA_HOME:-$HOME/.local/share}/jubarte/font-index.tsv, Windows %APPDATA%/jubarte/font-index.tsv. JUBARTE_FONT_INDEX overrides full path; empty/off disables. It is not inside fonts nor necessarily MCP root; temporary sibling is font-index.tsv.<PID>.tmp (src/convert/font.rs:2637-2652,3100-3106,3213-3227).
- Font discovery: macOS System/Library/Fonts[/Supplemental], /Library/Fonts[/Microsoft], Word.app/Contents/Resources/DFonts, $HOME/Library/Group Containers/UBF8T346G9.Office/FontCache/4/CloudFonts/<family>, plus configured/per-user Jubarte fonts (src/convert/font.rs:2225-2236,2281-2315,2637-2652). Windows uses WINDIR then SystemRoot then C:\Windows, /Fonts, optional LOCALAPPDATA/Microsoft/Windows/Fonts, and JUBARTE_FONT_DIR or APPDATA/jubarte/fonts (src/convert/font.rs:2637-2652,2831-2862). Linux uses JUBARTE_FONT_DIR or ${XDG_DATA_HOME:-$HOME/.local/share}/jubarte/fonts; absent required HOME removes default (2637-2652). Host permissions enforce these reads; not MCP root.
- Native publication effective staging is <destination-parent>/.jubarte-<UUID>.partial/bytes with held parent, exclusive creation/readback and atomic rename/hard-link. MCP edit outputs are <root>/<out_dir>/{clean.docx,redline.docx,patch.diff,report.json,optional redline.pdf/redline-page-NN.png}; MCP render outputs page-NN.png and optional render.pdf, with client receiving reports/text (src/publication.rs:419-570; jubarte-python/python/jubarte_redlines/mcp_server.py:185-255).
- Updater effective assets are jubarte-<version>-{macos,linux}-{aarch64,x86_64}.tar.gz or windows-x86_64.zip; internal jubarte-<version>-<target>/jubarte[.exe] replaces installed executable. Fixed repository is jandira-tech/jubarte-redlines, current control TLS/checksum/regular-file check/confirmation. RELEASE_KEYS empty and FIRST_SIGNED_RELEASE None intentionally mean checksum-only; actual CI key-secret availability unknown (src/update.rs:25-48,91-108,198-285; docs/SELF_UPDATE.md:59-80; .github/workflows/release.yml:268-275).
- SELF_UPDATE says GH_TOKEN/GITHUB_TOKEN lift rate limits (docs/SELF_UPDATE.md:22-24), but updater never opts into environment-token loading (src/update.rs:198-211). Architecture reviewer inspected locked self_update 1.3.1 default auth_token=None/auth_token_from_env=false and token copying; supporting cached dependency src/backends/common.rs:1027-1053,1077-1085 and src/macros.rs:580; repository Cargo.lock:2552-2553. Documentation/availability discrepancy, not evidence of leakage.
- Frontend common flags do not establish identical filesystem controls: Python/Node ordinary output uses host path APIs and rejects unsupported capabilities; WASM has no native OutputRoot module/dependency, Node filesystem belongs to JS host (jubarte-python/python/jubarte_redlines/__main__.py:101-133,1048-1073; jubarte-wasm/cli/bin/jubarte-redlines.mjs:6-14,76-80,106-111,724-740; Cargo.toml:173-177; src/lib.rs:160-165).
- CI signing receives only ZIPSIGN_PRIVATE_KEY in the signing shell/zipsign process, stores decoded keys under RUNNER_TEMP/zipsign.<random>/keyN, validates 64-byte keys, cleans on exit and signs dist/jubarte-*.tar.gz/zip; verification uses committed keys when present. Release publisher independently uses secrets.GITHUB_TOKEN as GH_TOKEN with contents:write, github.repository and GITHUB_REF_NAME to publish notes.md/dist/* (.github/workflows/release.yml:230-321,356-369).
- Operator Cargo publication uses Cargo-owned credentials/CARGO_REGISTRY_TOKEN and confirmation/release gates; npm engine jubarte-wasm and CLI jubarte-redlines publish independently under npm login and optional NPM_OTP; PyPI uses UV_PUBLISH_TOKEN and validated complete CI wheels/sdist, with explicit --no-wait for local partial fallback (scripts/release.sh:363-380,875-959,1039-1069). Secret scopes and actual provider accounts are external.
- Release script selects an external application checkout via JUBARTE_APP_DIR or jubarte-app; its implementation is outside scope and uninspected (scripts/release.sh:382-387).
- Actual GitHub protections/approvals, registry scopes, host ACLs, MCP client trust and process/container isolation are unknown; repository declarations alone do not establish them. Generated WASM implementation was not executed/disassembled and source parity remains unverified.
