# Threat Model

Jubarte is an in-process Rust Word-document engine for comparison, inspection, edit plans, tracked-change resolution, Markdown conversion, legacy DOC import, validation, scrubbing and PDF/PNG rendering. Native CLI, PyO3/Python and wasm-bindgen/Node/browser surfaces call the shared engine (src/lib.rs:7-35; jubarte-python/Cargo.toml:35-39; jubarte-wasm/Cargo.toml:18-32). A separately installed Python MCP server brokers document tools over stdio under one directory capability; the Gemini extension starts this server with workspacePath as its root (jubarte-python/python/jubarte_redlines/mcp_server.py:67-108,373-381; gemini-extension.json:5-9). Native CLI self-update is a distinct optional network-and-executable-replacement workflow. Tag releases, local registry publication, CI and external Jules review/remediation are conditional maintainer workflows, not document-runtime capabilities.
Jubarte is a local Rust Word-document toolkit exposed through Rust byte APIs, PyO3 Python, WASM/Node, native and language CLIs, and an optional Python MCP server over stdio. Untrusted DOCX/DOC/Markdown and JSON edit plans feed package admission, XML/legacy parsers, comparisons, edits and PDF/PNG rendering. Native publication and explicit self-update are separate host-authority boundaries (src/lib.rs:7-30,106-174; src/convert/mod.rs:769-798; jubarte-python/python/jubarte_redlines/mcp_server.py:67-112,373-381). ## Trust Boundaries

- Document author -> Rust parsing/rendering -> caller process. admission bounds compressed bytes, entry counts, per-part/total inflation and selected XML depth/tag policy; downstream XML, numeric layout, images/fonts and legacy fields require their own effective controls (src/admission.rs:442-580,788-827; src/convert/mod.rs:769-798).
- Python/Node/native CLI callers choose ambient local input/output paths; these callers already possess operator file authority. MCP clients instead provide relative document/output names beneath --root, default current working directory; build_server resolves that root once and _OutputRoot retains native cap_std::Dir authority for actual I/O (jubarte-python/python/jubarte_redlines/mcp_server.py:67-112,373-381; jubarte-python/src/lib.rs:1244-1279; src/publication.rs:146-200).
- MCP/native rendering -> ambient font resources: JUBARTE_FONT_DIR overrides the platform user font directory; macOS ~/Library/Application Support/jubarte/fonts, Unix $XDG_DATA_HOME/jubarte/fonts or ~/.local/share/jubarte/fonts, Windows %APPDATA%/jubarte/fonts. Fonts are read by conversion outside the document root (src/convert/font.rs:2637-2652).
- Rendering -> persistent font index: JUBARTE_FONT_INDEX selects a path; empty/off disables it; default parent(user_font_dir)/font-index.tsv. FONT_INDEX loads that path and save merges and writes path.with_extension(tsv.<pid>.tmp), then renames it to the index (src/convert/font.rs:3100-3107,3213-3229). This is component ambient authority, distinct from tool document/output confinement.
- Explicit self-update -> fixed jandira-tech/jubarte-redlines GitHub release and SHA256SUMS.txt -> extracted platform executable -> installed binary. TLS/checksum verification, optional compiled version-gated signing policy, and lstat regular-file hook enforce distinct steps (src/update.rs:25-48,198-257,274-285,299-321; Cargo.toml:137-148).
- Privileged release workflows: release.yml optionally signs with secret-store ZIPSIGN_PRIVATE_KEY, computes SHA256SUMS.txt and publishes GitHub assets. Operator scripts/release.sh:976-1012 can recover workflow artifacts into dist/release, compute checksums and create a release without that signing step.
- Caller-supplied DOCX/ZIP/XML/media/fonts cross into the host engine. Admission counts actual inflation, checks package identity, names and XML limits; production archive opening rejects header/extent/special-entry defects. Low-level permissive parse_xdocument does not apply input policy: callers of raw XML APIs must select checked parsing or prevalidate. The deliberate debug archive reader is an inspection exception (src/admission.rs:13-28,439-566; src/opc/archive.rs:20-51; src/xmllinq/parse.rs:21-36,98-135; SECURITY.md:132-139).
- Legacy DOC is a separate OLE/FIB/piece-table parser, not a ZIP-admission path. It converts the supported main story to Markdown/DOCX and explicitly excludes encrypted/obfuscated and older Word formats (src/legacy_doc.rs:13-50).
- Edit-plan author transfers requested mutations and optionally source identity to the engine. Schema version and a supplied source_sha256 are checked; the v1 source guard is optional, not an authorization or mandatory freshness credential (src/edit.rs:97-106,2072-2094). Filesystem publication is a separate boundary from in-memory edit acceptance.
- Native CLI uses ambient caller-selected output paths. publish_paths holds each parent directory, stages into parent/.jubarte-<uuid>.partial/bytes, uses Unix staging mode 0700, and commits per file; OutputRoot additionally validates portable relative names and confines capability-relative I/O. Multi-file publication is explicitly not atomic across the set, and errors record already committed files (src/publication.rs:83-143,146-225,228-273,420-505). Python and npm general-output helpers instead directly call Path.write_bytes/fs.writeFileSync; native publication controls cannot be assumed for those helpers (jubarte-python/python/jubarte_redlines/__main__.py:101-113,126-132; jubarte-wasm/cli/bin/jubarte-redlines.mjs:76-79,106-110).
- MCP caller gains document read/write operations only within the operator-selected root. Python resolve-based checks are early diagnostics; native cap-std OutputRoot owns the actual read/write confinement. overwrite is caller-controlled, false by default; annotations are hints, not per-tool authorization. stdio possession is the transport access boundary; no distinct users/tenants are established by this adapter (jubarte-python/python/jubarte_redlines/mcp_server.py:54-55,67-108,152-160,373-381; src/publication.rs:146-199).
- Native Markdown image references cross from document content into local reads. Effective resource root is --resource-path or the Markdown file's parent, falling back to current directory. Percent-decoded targets must canonically remain under that root and actual reads use its held OutputRoot capability; URL schemes are refused. - Native/Python rendering may read installed fonts and update the ambient per-user/configured index even when invoked through MCP. MCP's document-path capability is not a whole-process filesystem sandbox. Browser/WASM uses embedded/bundled faces rather than installed fonts; its byte APIs do not expose native OutputRoot publication (src/convert/font.rs:2258-2285,2633-2652,3095-3107,3182-3229; README.md:901-920; Cargo.toml:149-152).
