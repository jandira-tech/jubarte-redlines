# C#-oracle goldens

Generated by `tools/gen-goldens-cs.sh` from the in-repo (local-only, git-ignored)
`Docxodus/tools/redline` CLI — dotnet, SDK pinned by `Docxodus/global.json` (the
script cd's into `Docxodus/` so the pin applies; building with SDK 10 breaks on
the C# 14 first-class-span `Reverse()` shadowing). Settings pinned to author
`Test Author`, date `2020-01-01T00:00:00Z`, `--detail-threshold=0.15` (the CLI
default is 0, the library default is 0.15 — never omit the flag).

`<name>.revcount.txt` is the `WmlComparer.GetRevisions` count the CLI reported
for its own output (used by GetRevisions API tests).

## Known TS↔C# oracle divergence (logged 2026-07-02)

Same-settings text comparison (m4i-style extraction: `w:delText` + `w:t` under
`w:ins`, `word/document.xml` only) of these goldens vs the TS goldens in
`tests/goldens/`:

- `inpi`, `inpi2`: **exact match** on deleted AND inserted text.
- `redline`: deleted text matches exactly; inserted text differs wildly
  (TS 13,607 chars vs C# 1,943). The fixture is pathologically repetitive
  ("mamaum" × hundreds), where distinct-but-valid LCS alignments yield the same
  concatenated deleted string but different inserted/equal splits. The C#
  alignment is much tighter. This is a pre-existing correlation-algorithm
  divergence between the oracles, NOT caused by (and out of scope of) the
  2026-07-02 gap-closure work; the TS-based `m4i_parity` gate remains the
  regression gate for the Rust port's TS-faithful correlation. Consequence for
  GetRevisions tests: C# revision-count parity is only asserted on pairs whose
  alignments agree (`inpi`, `inpi2`), not on `redline`.

## `cs/redline.redline.docx` is Word-INVALID (verified in real Word 2026-07-02)

Opening it in real Microsoft Word raises "Word found unreadable content …
recover?" (word-open-probe FAILED). I.e. the C# oracle's own Compare output for
this pathological pair fails the real-Word oracle. Therefore these C# goldens
are **text/revision-count expectation sources ONLY** — never Word-validity or
structural baselines. Word-validity oracles remain: real Word
(`parity/scripts/word-open-probe.sh`) and the ooxmlsdk typed load.
